# 必装 · 1688 本地 MCP（星空 V2）

**这是 S1 抓 1688 详情的主路径，不是选配。**  
注册名 `1688_scraper`。能力强于、也优先于 Skill `1688-product-detail-scraper` 自己开网页。  
Skill 只负责把 MCP 抓到的事实写成 `03_1688产品资料_*.md`。生产模式 `ping` 不通就停，去装这一包。

仅当用户明确说「演示、没有 1688 MCP」时，才允许网页半辅助回落。

2026-08-13 本机实测：offer `828851649557` 抓到 `window.context`、主图、详情长图（`detailUrl`）、视频。

`download_media` 会再请求 `description.fields.detailUrl`，把详情长图放进 `详情图/`；视频封面进 `视频封面/`，不冒充详情图。

## 这一包有什么

| 文件 | 作用 |
|---|---|
| `server.py` | MCP 服务 |
| `requirements.txt` | Python 依赖 |
| `install.sh` | Mac 安装 |
| `install.bat` | Windows 安装 |
| `config.snippet.toml` | 贴进 Codex 的配置模板 |
| `测试口令.md` | 装好后用来验通 |

**不会**带：`.venv`、`pw_user_data`（登录态）、你的 Cookie。  
每人自己装、自己扫码登录。

## 前置

- Python **3.10+**（终端里 `python3 --version`）
- 已装好 `星空亚马逊 Agent` 插件（本包就在插件 `mcp/1688/`）
- 官方 Codex（改完配置要**完全退出再开**）

## 两步装（Windows）

### 1. 跑安装

双击 `install.bat`（通过星空插件市场安装的用户：双击 `星空亚马逊Agent` 文件夹里的 `安装1688本地MCP.bat`，效果相同）。

它会把 `server.py` 等文件复制到**插件外的固定目录** `%USERPROFILE%\.codex\mcp\starsky-1688\`，在那里建虚拟环境、装依赖、装 Chromium。⚠️ 不要在插件目录里装：插件每次升级都会换目录，装在里面的虚拟环境和登录态会丢。已有环境时重跑只更新依赖和 `server.py`，登录态保留。

### 2. 写入 Codex 配置

`install.bat` 装完会问「现在自动写入吗」，按 `Y` 即可；也可以随时双击 `写入Codex配置.bat`。它把 `[mcp_servers.1688_scraper]` 写进 `%USERPROFILE%\.codex\config.toml`：已有这一段就整段替换成新路径，没有就追加，写之前自动备份 `config.toml`。

手动贴的话，打开 `~/.codex/config.toml`，在末尾追加 `config.snippet.toml` 里那一段。⚠️ Windows 路径必须用**单引号**包（TOML 里双引号 + 反斜杠是非法转义，Codex 会读不了配置）。

完全退出 Codex，再打开。工具面板应能看到 `1688_scraper`：`ping` / `login_1688` / `get_offer` / `download_media`（另有 `search_offers` 关键词搜 offer）。
不放心可跑冒烟测试：在 `%USERPROFILE%\.codex\mcp\starsky-1688\` 执行 `.venv\Scripts\python.exe smoke_test.py`，看到 `PASS` 即服务可启动；或双击 `一键体检.bat` 看全套红绿灯。

## 第一次用

1. 模型用 **5.6 Terra · 高**（卡登录再另开 Sol）。
2. 粘 `测试口令.md`。
3. 会弹出 **MCP 自己的 Chromium**（不是 Safari，也不是 Codex 内置浏览器）。
4. 在那个窗口登录 1688 / 过滑块。
5. 回到 Codex 只回 **已完成**。

登录态留在 `%USERPROFILE%\.codex\mcp\starsky-1688\pw_user_data\`，下次一般不用再登。这个目录不要发给别人。
