# 星空产品推广知识库 MCP · 使用说明

版本：1.0.0（随星空 Codex 业务包分发）· 注册名 `promotion_knowledge_base`
适用：任何支持 MCP（stdio）的宿主（ZCode / Codex / Claude Desktop / Cursor / 其他），任何对话/推理基座。本说明不绑定模型，换基座不用改调用方式。

## 一、它是什么、不是什么

- 是什么：产品推广打法知识卡（54 张 PK 卡 + 3 本场景手册），回答“这个产品、这个阶段、这个症状 → 该怎么推、节奏怎么定、数据回来怎么调”。
- 不是什么：不是广告 API，不读你后台账户，不改价、不改预算、不改库存、不下单。账户花费、订单、库存只认你自己的报表或 ERP，知识库只给原因树、节奏与出处。
- 阈值性质：全部是候选口径（经验值/案例值），你的利润账、合规黑名单、平台当前界面优先于库里任何数字。

## 二、包结构

```text
promotion-kb-mcp/
├── server.py              # MCP 服务（stdio，纯标准库）
├── kb.py                  # 本地检索/校验 CLI（服务依赖它）
├── smoke_test.py          # 冒烟测试
├── config.snippet.toml    # 各宿主配置片段
├── ★先读我.md             # 一页速查
├── 使用说明.md             # 本文件（完整版）
└── kb/                    # 知识库本体
    ├── cards/PK-*.md      # 54 张知识卡（一卡一知识点）
    ├── scenarios/SC-*.md  # 3 本手册：SC-断货重推 / SC-老品反超 / SC-排名恢复
    ├── taxonomy.yaml      # 受控词表（标签维度唯一来源）
    ├── kb_manifest.yaml   # 库元数据、产品线登记
    ├── knowledge_pack_for_promotion.yaml  # 导出给策略 Skill 的规则包
    ├── knowledge_index.yaml / learning_plan.yaml
    ├── gaps.yaml          # 开放缺口（仅 kb_record_observation 追加观察）
    └── sources/manifest.yaml  # 来源登记（原文切片不随包）
```

只读安全：9 个工具里只有 `kb_record_observation` 会写 `gaps.yaml`，其余全部只读。服务每次调用实时读卡，无需重启宿主。

## 三、安装（三步，任何宿主通用）

1. 解压到目标目录（路径可含中文；敏感宿主建议放英文路径，如 `C:/xk/promotion-kb-mcp`）。
2. 验证能起（解压目录下执行，通过即继续）：
```bash
python promotion-kb/../server.py --kb "<解压目录>/kb"
# 或：python server.py --kb "<解压目录>/kb"（取决于你解压后的相对位置）
```
手动输入一行 `initialize` JSON，回车后返回 `serverInfo.name=promotion-knowledge-base` 即正常，Ctrl+C 退出。或直接跑 `python smoke_test.py`（期望 `SMOKE PASS`，9 工具，54 卡）。
3. 把 stdio 配置写进目标宿主（任选其一；Windows 路径用正斜杠或双反斜杠；设 `PYTHONUTF8=1` 防中文乱码；也可用环境变量 `PROMO_KB_ROOT` 代替 `--kb` 参数）。

ZCode（config.json 的 mcp 节点）：
```json
"promotion_knowledge_base": {
  "type": "stdio",
  "command": "<python解释器路径>",
  "args": ["<解压目录>/server.py", "--kb", "<解压目录>/kb"],
  "cwd": "<解压目录>",
  "enabled": true,
  "timeout": 30000,
  "env": {"PYTHONUTF8": "1", "PYTHONIOENCODING": "utf-8"}
}
```

Claude Desktop（claude_desktop_config.json）：
```json
{"mcpServers": {"promotion_knowledge_base": {
  "command": "python",
  "args": ["<解压目录>/server.py", "--kb", "<解压目录>/kb"],
  "env": {"PYTHONUTF8": "1"}}}}
```

Cursor / 其他（.cursor/mcp.json 或通用 stdio）：
```json
{"mcpServers": {"promotion_knowledge_base": {
  "command": "python",
  "args": ["<解压目录>/server.py", "--kb", "<解压目录>/kb"]}}}
```

星空 Codex 公开版用户：直接运行安装包的“安装与更新”或“安装产品推广知识库”，安装器写入 `~/.codex/mcp/starsky-promotion-kb` 并配好上段，无需手写路径。非受管目录拒绝覆盖。

## 四、9 个工具（按调用顺序记）

| # | 工具 | 干什么 | 必填参数 |
|---|---|---|---|
| 0 | `kb_status` | 库状态：卡数/来源数/大纲完成度/开放缺口。任何决策前先调一次 | 无 |
| 1 | `kb_scenario_rules` | **拟方案首选**：按 产品类型×生命周期×场景 取规则 | `product_type, lifecycle_stage, scene`（枚举见第五节） |
| 2 | `kb_diagnose` | 按症状找诊断卡/阈值卡/案例卡 | `symptom`（短症状，见下） |
| 3 | `kb_query` | 按标签+文本检索知识卡 | `tags` 对象和/或 `text` |
| 4 | `kb_get_card` | 读单张卡全文（含证据与反方） | `id` 如 `PK-0032` |
| 5 | `kb_playbook` | 读场景手册全文 | `scene` 或 `pb_id` 如 `SC-断货重推` |
| 6 | `kb_products` | 列产品线登记（ASIN/阶段/目录文件） | 无 |
| 7 | `kb_list_gaps` | 列开放缺口 | `status: open/closed` 可选 |
| 8 | `kb_record_observation` | 跑数后回写实测观察到 gaps（不直接改卡） | `topic, observation`（+可选 metrics） |

`kb_query` 可选：`knowledge_type`（policy/mechanism/playbook/threshold/diagnostic/case_study 等）、`min_confidence`、`limit`（默认 10）。

## 五、受控词表速查（照抄 taxonomy.yaml，禁止自造词）

- `product_type`：标品 / 非标品 / 半标品 / 通用
- `lifecycle_stage`：立项期 / 新品期D0-30 / 成长期D30-90 / 成熟期D90+ / 衰退清仓 / 断货重启 / 通用
- `scene`：新品首推 / 断货重推 / 老品反超 / 排名恢复 / 换链接重上 / 旺季大促 / 淡季维持 / 通用
- `keyword_tier`：核心大词 / 次核心 / 精准长尾 / 流量词 / 防御词 / 捡漏词 / 通用
- `decision_metric`：曝光 / CTR / CVR / CPC / ACOS / TACOS / 自然位 / BSR / 库存天数 / 评价数 / 价格 / 通用
- 证据层级：A 官方事实 / B 权威课程 / C 第三方经验 / D 项目推论（须写验证法）/ V 厂商宣称（隔离，不进决策）

## 六、五条标准调用链（复制即用，按宿主工具调用格式传参）

链0 · 开场（每次必做）：
`kb_status({})` → 确认 `stats.cards` 有数、大纲可用，再往下走。

链1 · 断货重推（有库存保链 / 纯断货止损 / 到货放量三叉）：
```json
{"product_type": "标品", "lifecycle_stage": "断货重启", "scene": "断货重推", "include_handbook": true}
```
再 `kb_playbook({"pb_id": "SC-断货重推"})` 取 D-2/D0/D+3/D+7/D+14/D+30 节奏表。诊断先抽短症状：`kb_diagnose({"symptom": "断货后掉排名"})`。

链2 · 排名恢复（核心词掉出前三页/首页）：
```json
{"product_type": "标品", "lifecycle_stage": "成熟期D90+", "scene": "排名恢复", "include_handbook": true}
```
再 `kb_playbook({"pb_id": "SC-排名恢复"})` 走四阶段（跑词→上2页→上1页→冲顶部）。症状词要短：`kb_diagnose({"symptom": "掉位"})`、`{"symptom": "掉排名"}`，不要整段粘报表。

链3 · 老品被超反超战（2–8 周）：
```json
{"product_type": "标品", "lifecycle_stage": "成熟期D90+", "scene": "老品反超", "include_handbook": true}
```
再 `kb_playbook({"pb_id": "SC-老品反超"})` 做差距诊断。症状如 `kb_diagnose({"symptom": "老品流量下滑"})`。

链4 · S1 选品推广可行性参考（不单独立项）：
```json
{"product_type": "标品", "lifecycle_stage": "立项期", "scene": "通用"}
```
取推广难度与首月推广费口径，写入选品报告备选节；立项结论仍以利润/IP/供应链为主。

链5 · S5 巡检/复盘收尾：
`kb_diagnose({"symptom": "高点击低转化"})` 取原因树 → 每条建议写 `evidence_refs: [PK-xxxx]` → 跑数后 `kb_record_observation({"topic": "restock_relaunch", "observation": "实测与某卡一致/相悖…", "metrics": {"orders": 12}})` 回流。阈值超了只出信号，不自动改后台。

`kb_query` 示例：`{"tags": {"scene": ["断货重推"]}, "text": "Coupon 秒杀", "limit": 5}`；`kb_get_card({"id": "PK-0032"})` 看上首页四变量全文。

## 七、证据与引用纪律

- 每条建议带 `evidence_refs: [PK-xxxx]`；阈值注明 authority（A/B/C/D）与来源日期；D 级必须写验证法。
- 引用姊妹库广告执行细节时传 `KC-xxxx`（`kb_get_card` 兼容），本库不复制广告机制。
- 冲突时优先级：你的利润账、合规黑名单、平台当前界面 > 当前账户事实 > 本库规则。

## 八、排错

- 中文乱码：确认 `PYTHONUTF8=1`（或 `PYTHONIOENCODING=utf-8`）；Python 需 3.10+（仅标准库）。
- 路径：JSON 里 Windows 路径用 `C:/...` 或 `C:\\...`；`--kb` 必须指向解压后的 `kb` 目录。
- 改了库不生效：服务按 mtime 缓存、实时读卡，一般无需重启；新增卡后立即可查。
- `kb_diagnose` 返回空：把症状缩到 2–6 字（掉位/断货/掉排名/流量下滑/高点击低转化）再试。
- 工具数不对：`tools/list` 应为 9 个；少于 9 个先跑 `smoke_test.py` 定位。

## 九、更新与学习闭环

- 换新包：解压覆盖后跑 `smoke_test.py`，再调一次 `kb_status` 核对卡数与更新日期。
- 跑数沉淀：只调 `kb_record_observation` 写观察，不直接改卡；制卡与复核走知识库维护流程（validate/index/export），发布前跑脱敏扫描。
