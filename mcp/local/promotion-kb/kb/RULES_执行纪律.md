# 执行纪律（硬规则 · 所有会话必须遵守）

> 生效：2026-09-19 ｜ 来源：用户指令（2026-09-19 晚间明确"写进规则里面"）
> 适用范围：`05-产品推广` 工作目录下的一切执行动作（含 04 库联动、API 通道、浏览器通道、电脑控制通道）

## 一、推送前必须用户点头（R1 · 最高优先级）

**任何要进入用户后台的改动，必须先出"候选方案"，经用户明确同意（"推送到广告后台 / 可以推送 / 同意"等原话）后才能执行。**

涵盖范围（无例外）：

| 类别 | 具体动作 |
|---|---|
| **广告** | 新建/暂停/归档活动、广告组、关键词、定向、商品广告；改竞价、改预算、改竞价策略、改投放状态 |
| **Listing 文案** | 标题、五点、商品描述、后台搜索词（ST）、属性字段、A+ / 品牌故事 / 旗舰店内容 |
| **价格与促销** | 售价、销售价/促销价、Coupon、奥莱、秒杀 |
| 其他 | 任何会改变店铺前台或后台状态的操作 |

执行方式：

1. 出**候选包**（改什么对象、before → after、依据、预期、回滚方式），等用户点头；
2. 得到明确同意后再推送，推送后**逐项回读校验**并留回执；
3. **用户没点头 = 不推送**；"没反对"不等于同意；
4. 只在**读**的层面自由行动（API 只读、公开页面、后台截图查看、数据分析）。

> 例外（无需逐次点头，但同样属"读"或已授权范围）：只读查询、数据分析、文档产出、本地文件整理。
> **历史例外说明**：2026-09-19 晚建立的门条捡漏组两组（188890912061069 / 220429572299300）系在用户口头要求（"能不能捡漏广告去跑一跑"）后推送，用户事后已知悉；如需回滚可随时暂停/删除。
>
> **通道与权限现状（2026-09-19）**：
> - Ads API：**有写权限**（活动/广告组/词/定向/竞价/预算/否定词 均可推送，已多次成功）
> - SP-API：**读写权限均已开通**（2026-09-19 实测 Listings PATCH → `ACCEPTED`，US/UK 两站；此前记录的 403 系**方法用错**——Listings 更新用 `PATCH`，误用 `POST` 会被网关按无权限挡掉）。文案推送走 `scripts/amz_client.py: sp_patch()`。**R1 审批仍然适用**。
> - 无 API 通道、只能后台点：Coupon（券）、奥莱/秒杀报名、品牌旗舰店编辑、电脑控制类操作

## 二、内容合规红线（R2）

- **Q-Tips 系禁用**：`qtips` / `q tips` / `q-tip` / `qtip` 等变体**禁止出现在任何 Listing 文案**（标题/五点/ST/描述/A+/图片文字）；**广告竞价可用**（用户 2026-09-11 指令）。
- **敏感词三类**（PK-0042）：杀虫抗菌、医疗疾病、绝对化/认证类词一律不得进入文案与图片文字。
- **单变量纪律**：指定冻结的字段（如 `主推 ASIN 标题五点`）在冻结期内不得改动。

## 一·补：广告自动闸门（R1-EX · 用户 2026-09-19 授权"闸门授权"）

**这是 R1 的唯一例外**：对**监控清单内**的活动，命中下列条件时**无需逐次点头**，按规则自动执行。

**监控清单**（14 个：7in×2 / 500ct×2 / 300ct×4 / 尖头×4 / 门条×2）与规则实现在 `scripts/gate_check.py`（清单按活动名解析，脚本内置）。

| 触发条件（近 7 天，任一） | 动作 |
|---|---|
| A. 点击数 ≥10 且 **CPC > $1.20** | 首次触发 → 该活动**所有在投词/定向/组竞价 ×0.7** |
| B. 花费 ≥$8 且 **0 单** | 二次触发（已降过一次仍触发，或花费 ≥$15 且 0 单）→ **暂停该活动** |
| C. 花费 ≥$8 且 **ACOS > 150%** | — |

- 留痕：账本 `review_log_exec/gate_ledger.json` + 每次回执 `review_log_exec/evidence/gate_<日期>.json`；
- **取数失败（报表超时/异常）→ 不动作**，只报告（不盲动）；
- 触发背景：2026-09-19 `AI-测试-02`（7in）7 天 $24.31/27 击/1 单、**ACOS 243.59%**，病根＝广泛匹配 + 无否定词护栏 → 用户授权本闸门避免重演。

## 二·补：推送前双闸门（R2.5，2026-09-19 起强制）

每次推送到后台的改动，脚本必须**先过两道闸门**，未过则拒绝推送：

1. **合规扫描**：Q-Tips 侵权词 + PK-0042 三类敏感词（杀虫抗菌/医疗/绝对化认证）+ 枪械词；
2. **字段长度校验**：按字段上限校验字符数——**商品名称 `item_name` ≤75 字符**、**商品亮点 `title_differentiation` ≤125 字符**、后台搜索词 ≤250 字节、五点不建议超 200 字符/条。

> 教训（2026-09-19）：曾把 118 字符写进 `item_name`，**SP-API 静默 ACCEPTED、无 issues**，但控制台按 75 字符判超长并在前台呈现超长标题 → 结论：**API 返回 ACCEPTED ≠ 字段合规**，长度必须脚本侧自检。
> 同时：改五点/用途时要**连带检查 `title_differentiation`（商品亮点）**，枪械等内容可能残留在这里（当时就漏了一处 `gun cleaning`）。

## 三、安全与留痕（R3）

- **密钥/token/凭证不落盘、不打印**（凭证只从本地 env 文件读取）。
- **所有动作留证据**：改前/改后值、API 回执、截图；落 `review_log_exec/evidence/`，并在 `review_log_exec/D*_<日期>.md` 记账。
- **浏览器侧**：默认只读公开页面；不得登录任何账号。若用户明确开启通道（如紫鸟/电脑控制）并授权，才可在其登录态内操作，且**写操作同样受 R1 约束**。
- 涉及旧文件（Bulk 表、计划、合并表）**不得就地修改**：改动要走新版本 + 校验链。

## 四、违反后果与自查

- 每次执行前自查 R1：这次动作里有"推送到后台"的成分吗？→ 有则必须先要授权。
- 未获授权即推送 = 纪律事故，须立刻暂停动作、报告、并记录到当日执行日志的"遗留/事故"栏。
