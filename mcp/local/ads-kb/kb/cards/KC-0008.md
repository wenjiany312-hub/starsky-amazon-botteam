## 结论（一句话，可直接被下游引用）

广告架构的微观核心是"**出单搜索词往更精准的匹配方式转移**"：方案 1 自动出单→直接手动精准（一层漏斗，成本最低）；方案 2 自动→手动广泛→手动精准（两层，拓流更多）；方案 3 自动→广泛/词组分流 + 自动侧词组否定、手动侧精准否定 → 出单再进 SKAG（控制最强、结构最复杂）。**架构越复杂控制越强，但流量小的类目用复杂架构成本极高**——预算低从简，预算高才提高测试与转移频率。RES（Broad 拓流层）与 PER（Exact 出单保护层）按表现拆分，是这套转移的容器。

## 机制 / 原因

自动/广泛匹配负责"找词"（RES，流量增长），精准负责"收词"（PER，稳步增长）；转移把已验证出单的搜索词放进可控出价的精准位置，同时在原投放上否掉它避免内耗。层数越多，过滤越细，但每层都要预算和时间积累样本——小流量类目分不出足够点击给每一层。

## 操作 / 参数

- 选方案：日基础花费低 / 小类目 → 方案 1；预算中等、想拓流 → 方案 2；预算高、大类目、要控 ACoS → 方案 3（SKAG）。
- 转移触发：出单词（1 单）即转（阿波罗）；更保守口径 ≥2 单（KC-0003），按 CVR 置信度取舍（KC-0011）。
- 转移后**在原投放做否定**（精否/词组否），防止同词多处竞价。
- 标品 PER：Broad + Exact 承接；非标品 PER：出单词分散，建议 Phrase + Exact（SRC-0038）。
- 与星空六大打法映射：RES ≈ 海词/词组探索（broad_discovery、phrase_*），PER ≈ 贴标签/冲销量/拉自然位（exact_p1/p2）。

## 适用 / 不适用

- 适用：SP 关键词广告的新品期→成长期。
- 不适用：商品投放/受众投放的转移逻辑另立卡；SB 匹配类型规则不同。

## 反方 / 已知冲突

- 转移触发"1 单"可能把偶然出单词提前收进精准，浪费出价；"≥2 单"更稳但慢——并列不裁决。
- 官方对 SKAG 无立场；其价值来自可控性，副作用是活动数膨胀、依赖自动化管理（原文"越多广告活动越依赖优化和自动化管理"）。
