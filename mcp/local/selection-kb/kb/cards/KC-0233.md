## 结论（一句话，可直接被下游引用）

1-3 星差评按八类标准编码：尺寸 / 材质 / 结构 / 耐用 / 使用（说明书） / 场景不匹配 / 外观 / 包装服务，每条差评逐条归类（可多属）、独立打严重度 1-5 分，并按各类可操作性（HIGH 到 MEDIUM）排改良优先级——尺码表、说明书、包装是低成本高感知的先手项，结构问题才动开模（标准，2026-07-08）。

## 机制 / 原因

差评如果不编码，就只能得出「用户不满意」这种不可执行结论。八类把差评拆到「改什么部位」的粒度：sizing 可直接改尺码表、scenario_mismatch 可能只需在 Listing 里改场景定位（不一定要改产品）、structure 才涉及开模打样。严重度与可操作性双维排序保证工程资源先花在「高频 × 高严重度 × 低成本」格子上，而不是被情绪最激烈的评论带偏。

## 操作 / 参数

1. 抓取目标品 1-3 星差评，逐条归类到八类之一（可多选），记录子类别（如 sizing 下分 runs_small / chart_inaccurate / no_plus_size）。
2. 每条按该类标准打严重度 1-5：以「是否退货/是否健康隐患/是否影响核心功能」为锚点。
3. 统计各类频率 × 平均严重度，对照该类可操作性（HIGH/MEDIUM）排改良队列：先 HIGH（尺码表、二维码视频教程、彩盒包装、售后卡），结构类进打样验证后再排。
4. 中英关键词表辅助归类（如 slips down / Velcro broke / chemical smell / 太小了 / 硌），英文差评按原文关键词匹配。
5. 输出直接映射产品 PRD 改良方案；与 KC-0182 分流规则衔接——Listing 可解决的（说明书/场景定位）不进产品改型队列。

## 适用 / 不适用

- 适用：竞品差评结构化分析、自有产品 VOC 改良排期、KC-0232 六号文档「痛点写方案」步骤的分类底座。
- 不适用：好评挖掘（该走 Rufus/卖点语言体系）；单条差评的个案诊断（编码是为频率统计服务的）。
- 站点/类目差异：示例词表偏穿戴/家居非标品；标品类目（3C）需补「兼容性/参数虚标」等类目专属子类。
