## 结论（一句话，可直接被下游引用）

每日选品机会推送是「日常供给型」固定任务：product_scout 单角色全程主责（不套多角色接力），每天从 Amazon/TikTok/Temu/Reddit 四源各扫一遍，产出固定六段简报（机会 Top5-12 / 平台热点 / 季节节日 / 需求信号 / 不建议追 / 一句话），归档 `reports/选品机会/YYYY-MM-DD-*.md`，验收按四件套（路径/3 句摘要/结构化 Top 清单/是否值得今天深挖）；平台抓不到就标注缺口照常交付，全灭则如实标失败，绝不编造（B 级 SOP 原文，2026-06-07/08）。

## 机制 / 原因

雷达与单次调研的本质差异是「供给」而非「应答」：持续补选品刺激、防止只盯单平台（KC-0069 三渠道交叉的工具化日常版）。单角色不接力是因为日常雷达是大项目的小日常，多角色接力反而慢；但验收必须有硬口径（四件套），否则供给型任务最容易退化为「说做了」——所以路径+结构化清单+下一步判断三项都要可检查。季节段落强制「先看日历再选品」（未来 30-60 天节点，KC-0067 节奏的工具侧实现）。

## 操作 / 参数

1. 派单话术固定四源清单：Amazon（BS/New Releases/Movers & Shakers/类目页/评论信号）、TikTok（反复带货品/需求词）、Temu（热卖榜/套装化）、Reddit（真实吐槽/节日痛点）。
2. 每条机会必备字段：产品方向 / 来源平台 / 热度或需求信号 / 为什么现在值得看 / 风险提示 / 短期热度还是中期趋势。
3. 「不建议追的热度」至少 3 条并给放弃理由（噪音/太卷/侵权合规/季节错配）——该段缺失视为未完成。
4. 兜底：单平台失败 → 跳过并注明「今日 XX 未取到」继续出六段；全部失败 → 标「今日数据采集失败」写原因，不硬凑；素材少 → 至少保 Top3+季节节日+一句话三段。
5. 归档按日期一天一份，积累一个月后由内容角色汇「月度选品趋势」复盘。
6. 抓取纪律与降级阶梯见 KC-0203/KC-0204；本卡只管节奏、结构、验收。

## 适用 / 不适用

- 适用：AI Agent 团队的每日机会雷达固定任务、个人卖家的每日/每周扫描例行动作、公众号/周报素材供给。
- 不适用：替代立项深研（雷达只出「今天值得看什么」，不出能不能做）；把 8-12 个机会数当硬指标抄给无工具人肉场景。
- 站点/类目差异：四源与季节日历为美端口径；其他站点替换对应本地平台与节点表。
