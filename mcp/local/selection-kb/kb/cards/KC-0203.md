## 结论（一句话，可直接被下游引用）

抓取被反爬拦截不是任务失败：按固定五级阶梯降级（平台主技能 → Scrapling stealthy/dynamic 降频 → 本机 Chrome 辅助登录 → 公开替代源标注「替代来源」 → 带缺口交付），每份报告必须附「数据采集状态表」（平台/状态/技能/说明），缺该表任务视为未完成；禁止因单平台失败停整份报告，禁止把未抓到写成数据丰富（B 级热修原文，2026-06-08）。

## 机制 / 原因

反爬是常态而非异常，任务设计必须按「降级」而不是「成败」建模：直接停工损失整份报告价值，编造数据污染下游决策（KC-0036「查不到写 unknown 不写非刷」的采集层同源纪律）。采集状态表把「哪些结论有直抓证据、哪些只是替代信号」变成可检查的契约——报告消费者据此对三值判断打折，而不是被均匀可信的假象误导。替代源必须显式标注，否则 Reddit 缺席被 Google 补，证据等级就静默降级了。

## 操作 / 参数

1. 拦截识别三信号：快照只剩 1 个元素（Cloudflare）、跳转 google.com/sorry、提示无住宅代理——命中立即停止重试该平台，启用降级。
2. 五级阶梯逐级走，每一级失败才降下一级；Reddit 被拦后不要再试 Google 搜 Reddit（同样被拦），改用飙升新品/Temu 上升品/TikTok 同款/关键词热搜四类替代信号。
3. 报告固定附状态表：每个平台一行（成功/降级/失败 + 使用技能 + 抓取范围说明）。
4. Discord/交付回报必含：文件路径、Top3-5 机会摘要、数据采集状态摘要、是否有平台降级。
5. 每条机会标证据等级（A 直抓 / B 公开搜索 / C 趋势推断）与紧迫度（立即看/本周看/可观察），推断型机会不得排进主线当直抓结论。
6. 技术实现细节（反爬手段、Playwright 拦截）移附录，正文只留证据等级与缺口说明。

## 适用 / 不适用

- 适用：任何跨平台选品采集任务（每日雷达、类目扫描、站外水温）的反爬处理与报告验收。
- 不适用：单平台小任务可简化状态表；1688 登录墙有专门边界（KC-0205，用户帮不了验证码，走详情页链接路线）。
- 站点/类目差异：阶梯通用；「Amazon 必抓 + 站外三选二」的最低线按任务目标调整，但状态表不可省。
