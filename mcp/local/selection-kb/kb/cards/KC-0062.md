## 结论（一句话，可直接被下游引用）

VOC 流水线的可复用参数：清洗留存率 40-60%（<30% 采集过泛 / >80% 过滤过松）；LLM 深读每品类抽 150 条高分痛点语料即收敛；采集限速 1 req/s；单品类 clean 后 2-5 万条足够决策；版块 10-15 个混配。换品类只改配置（subreddits/关键词/词典），脚本复用。

## 机制 / 原因

这些参数都指向同一原则——不追数据量，追信号质量：56 万条语料里真正改变决策的是 8×150 条深读；清洗故意留 ~45% 闲聊噪音让 LLM 兜底，也不收紧正则误杀真信号。参数给了「跑出来的结果是否正常」的判读基准，避免复制者把偏差当数据特性。

## 操作 / 参数

1. 清洗后先看留存率落不落在 40-60%，越界先调采集范围/过滤正则，再往下跑。
2. 深读样本按「痛点词共现 × 高赞」排序取头部 150 条/品类，并行 agent 输出结构化 JSON。
3. 词典三件套（产品/痛点/推荐）输出提及量/痛点率/推荐率/月趋势四数，用于品类排序。
4. 断点续采用 created_utc 升序游标，第二次只采增量（state/ 游标）。
5. 中国网络环境：truststore 注入系统证书 + pip --trusted-host，属已知必踩坑。

## 适用 / 不适用

- 适用：把 VOC 流水线复制到新品类时的参数基准与结果判读。
- 不适用：把数值当跨平台真理（Reddit 语料结构变了要重校）；非英语市场（ASCII 过滤需重写）。
