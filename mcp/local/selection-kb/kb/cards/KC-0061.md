## 结论（一句话，可直接被下游引用）

社媒语料（Reddit 等）是需求的**表达**、领先销量数周到数月；平台工具（SIF/卖家精灵/Sorftime）是需求的**结果**、天然滞后。VOC 选品 = 社媒大规模采集提出痛点假设 → 平台数据逐条裁决，**蓝海三重验证**缺一不可：①社媒声量存在且在涨 ②痛点集中且现有品不解决 ③亚马逊需求增长且竞争未锁死。

## 机制 / 原因

单独看社媒：声量大 ≠ 有购买力（伪机会）；单独看平台：缝隙需求被平均数掩盖、词汇迁移看不见（案例：self cleaning litter box -27% → automatic litter box +64%，只盯旧词会误判品类萎缩）。真实链路是「先社媒抱怨/种草 → 再平台搜索 → 后成交」，在链路最前端布局才拿得到蓝海时间差。

## 操作 / 参数

1. Stage 1-3a 用脚本与词典从社媒语料聚合出每品类四数：提及量/痛点率/推荐率/月度趋势，用于排序（KC-0062 参数）。
2. 头部品类并行 LLM 深读痛点（保留英文原话 quote，作 listing 弹药）。
3. 跨品类交叉信号人工过一遍——品类交界处的机会（多宠介绍期案例）单品类标注看不见。
4. 每条信号过 SIF/Sorftime 双接口裁决：需求量级+同比+季节 + Top3 集中度+评论门槛。
5. 裁决记录对半开：晋级清单与证伪避坑记录同等保留（案例杀 2 晋 2 + 新增 2）。

## 适用 / 不适用

- 适用：寻找平台工具看不见的「场景×人群」缝隙；新蓝海方向的假设生成与证伪。
- 不适用：直接当销量证据（社媒热度不入利润账）；替代十查与难度双法（过验证后仍走正常流程）。
- 站点/类目差异：案例为美站宠物；语料版块与词典按品类重配。

## 证据

前导 vs 滞后对比表与三重验证（SRC-0494 §一）；裁决记录杀 2 晋 2（SRC-0494 §七）。
