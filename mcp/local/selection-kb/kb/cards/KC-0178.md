## 结论（一句话，可直接被下游引用）

S1（选品可行性研究）阶段的输出不是「做不做」，而是带条件的推进包：决策=GO_WITH_MODIFICATION（条件性推进）+ 三个关键闸门（①旺季最晚下单日是否已过；②普船 58-86 天时效 vs 库存见底日；③上架第 7-14 天补货决策窗）+ 行动边界（不上传、不下单、不改广告，先补样品/材质/包装/交期与真实法律检索）。报告必须附上游数据一致性审计（表行 vs 数据行、唯一 ASIN 引用 vs 完整详情）与「已获取事实/自动推导/缺失及影响」三层窗口（D 级实跑口径，2026-07-26）。

## 机制 / 原因

S1 的价值是把「数据能不能支撑决策」变成可审计的：先审计上游产物行数与口径（344 表行≠317 数据行），防止把关键词引用冒充产品详情；再把缺失字段（净重/包装/交期/MOQ/材质/法律检索）与「限制了什么」逐一挂钩，条件性财务只推演不承诺。三闸门把时间风险前置——档期、船期、补货窗任何一个错过，产品事实再好也要推迟档期（KC-0024 同向）。

## 操作 / 参数

1. 首屏决策件：电梯结论（需求是否成立、单罐不能对标套装销售额一类的口径修正）+ 当前动作 + 三个关键闸门。
2. 一致性审计：上游描述 vs canonical 实际逐项对（报告行数、表行 vs 数据行、唯一 ASIN 引用 vs 完整详情数、趋势点数）。
3. 数据窗口三栏：已获取事实 / 自动提取推导（峰值月、最晚下单日、财务贡献）/ 缺失及影响（缺什么、限制了哪个结论）。
4. 财务：条件性换汇（含 1.5% 缓冲）+ 15% 佣金 + FBA proxy + 60 天首批覆盖；全部标「条件性，不是批准预算」。
5. 阶段验收状态机：intake→condition_select→market_research→supplier→product_scrape→supplier_data_merge→IP→S1；每步标 complete/complete_partial/deferred + 证据文件。
6. B2B 变体（SRC-1174）：事实/推断/假设/建议/Unavailable 五级标记，工具不可用时字段保留 Unavailable 不以 0 代替；无本地售后=Stop 条件。

## 适用 / 不适用

- 适用：AI 选品工作流每个候选的可行性阶段收口、向老板交付「条件性推进包」、季节品档期判断。
- 不适用：替代立项终裁（人工 go/pivot/abort 仍是 KC-0060 第六步）；替代样品与法律检索本身。
- 站点/类目差异：船期与补货窗为美西海运口径；B2B 工业品需加售后 Stop 条件与认证准入链。
