## 结论（一句话，可直接被下游引用）

季节入口用**去年同月**榜/趋势验证方向；等当年节日临近才看数，窗口通常已过。接口返回空月份，回退核月度趋势，不得写成「非季节品」。

## 机制 / 原因

KC-0008 给提前量（常规 2–3 个月，强节日约 7 个月）。本卡给验证口径：当年临近数据是已经卷起来的结果，不是选品窗口。今年刚上架的季节链接是噪点。工具某月无返回，常见是接口空，不是需求不存在。

精铺课另有「圣诞须提前半年、1–3 月选品」经验时间线，与 KC-0008 的 2–3 / 7 个月**并列不裁决**：算窗口时两套都写上，缺货期就推迟或放弃（KC-0024）。

## 操作 / 参数

1. 锁今天与站点，按 KC-0008 看未来档期。
2. 验证：市场 MCP 或卖家精灵月份选择器切到**去年对应月**，不看今年近月上架。
3. 空月份 → 核月度趋势；仍无证据则标 `未验证`，不输出「非季节品」。
4. 再做偏季判定：旺季好且淡季不掉 → 优先；淡季归零 → 必须卡死时间线；节日热卖且档期已过 → 放弃。

## 适用 / 不适用

- 适用：节日/季节意向、Q4 备货、要写季节性结论。
- 不适用：常年需求品硬套季节公式。
- 站点/类目差异：节日因站点而异；6–12 月大表若为同构补全，必须用去年同月再验。

## 证据

seasonal-selection（SRC-0313/0319）；精铺课节日段（SRC-0030）。

## 反方 / 已知冲突

提前量两套口径并列：KC-0008 的 2–3 / 7 个月 vs 精铺课圣诞「提前半年」。不改阈值，缺窗口就推迟。
