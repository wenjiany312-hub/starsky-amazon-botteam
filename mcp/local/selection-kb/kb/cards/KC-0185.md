## 结论（一句话，可直接被下游引用）

AI 选品工作流编排三条防呆：①总控（ops-workflow 类）只负责判断步骤、检查产物、衔接下游，不替代单点业务 Skill；②合规防火墙——市场调研之后必须先做 IP/合规再做关键词拓展，且 IP 报告圈出的竞品品牌词不得进入 Listing、后台 Search Terms、图片文字或关键词广告（ASIN 定投仅在明确授权时允许）；③产物契约——每步产物按固定命名落盘（report/profile/yaml），总控用文件存在性推断进度，MCP 不可用必须标注数据边界，不虚构（B 级 SKILL 口径，2026-09-17 提取）。

## 机制 / 原因

编排的价值在防呆而不是省事：跳过 IP 直接拓词，会把竞品品牌词一路带进文案、图片和广告——下游每一层都会放大这个合规错误，返工成本随环节递增；总控替代单点则让业务判断退化成流程走过场。产物契约让「进行到哪一步」可以被机器检查而不是靠记忆，也让每个候选可中断、可续跑、可复盘。

## 操作 / 参数

1. 固定九步链：1688 抓取→市场调研→IP/合规→关键词→Listing 文案→图片/A+→广告架构→Bulk 上传→报表优化；顺序不可换。
2. 每步只允许消费上游产物路径；跨步骤保持产品身份与站点一致。
3. IP 报告输出 brand_risks 列表 → 关键词 Skill 预加载排除 → 文案/图片/广告三层复查品牌词为零。
4. 状态文件维护 workflow_state.yaml（current_step/completed_steps/artifacts/next_step/blocked_reason）；产物缺失时按命名规则推断进度。
5. MCP 不可用降级到抓取/文件/用户投喂，并在报告标注数据边界；不声称用了 MCP 数据除非真的调过。
6. 不覆盖旧报告，除非用户要求重生成——新版本另存并把状态指向最新产物。

## 适用 / 不适用

- 适用：多 Skill/多 MCP 选品链的编排与验收、新人接手已有 run 的进度恢复、产物质量抽检。
- 不适用：替代单点 Skill 的业务判断（难度、利润、供应商评估仍是各自 Skill 的事）；单次轻量调研可不走全链。
- 站点/类目差异：口径通用；B2B/工业品类目在 IP 步前加认证准入链（SRC-1174）。
