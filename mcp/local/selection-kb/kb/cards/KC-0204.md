## 结论（一句话，可直接被下游引用）

外部数据 MCP（Sorftime 等）不可用不算任务失败：加载无 MCP 主流程，只用打包内抓取 Skill（amazon-scraper / product-scraper / scrapling / local-chrome）完成调研；MCP 永远定位为增强来源而非唯一来源；无论哪种模式，Amazon 必须至少留一组真实前台证据，机会方向不足时至少给 3 个并写明不足原因（B 级 SOP/测试任务原文，2026-06-08）。

## 机制 / 原因

把 MCP 当主依赖会让整条流水线单点脆弱：接口超时/配额/权限任一故障即全链瘫痪。打包 Skill 路线把数据能力下沉到本地工具，MCP 降级为「有则更好」的增强——这与 KC-0185「产物按文件存在性推断进度」同属去单点化设计。Amazon 真实前台证据是底线，因为站外信号（TikTok/Temu/Reddit）只能证明「有热度」，成交侧真伪必须靠亚马逊榜单/搜索页锚定（KC-0069 三渠道中成交侧不可缺席）。

## 操作 / 参数

1. 模式判断：MCP 可用 → 增强/混合模式；不可用 → 加载无 MCP 主流程（daily-opportunity-no-mcp 类），报告开头声明数据来源模式。
2. 配额纪律：单任务总抓取 ≤15 次调用；每平台至少 1 次；失败 2 次即跳过并标注，不无限重试。
3. 无 MCP 模式下机会数保底：目标 5-12 个方向，数据不足至少 3 个 + 明确不足原因；每条机会仍须带方向/平台/信号/为何现在/风险五字段。
4. Amazon 证据底线不豁免：至少一组真实前台抓取（榜单、搜索页、ASIN 深抓任一），不得只给站外信号。
5. 输出双格式（.md + .html），分享版按证据等级分层（KC-0203 参数）；完成后回报摘要 + 双路径 + 采集状态总览 + 最值得深挖的 1-2 个方向。
6. 验收自查：调度者没越权自己抓数据、执行者确实走了无 MCP 路线、报告含状态表、没把 MCP 写成主来源。

## 适用 / 不适用

- 适用：MCP 断供/限流/无配置环境下的选品任务兜底、给无工具用户做分享版调研、评估 Agent 任务是否「假完成」。
- 不适用：把无 MCP 产出当与增强模式同权（缺 MCP 时销量/类目维度缺失要显式标注，结论降级为方向性）；纯人肉无工具选品（本卡是工具链兜底，不是无工具方法论）。
- 站点/类目差异：口径通用；AnySearch 等外部情报只作增强，不能替代亚马逊前台直抓。
