## 结论（一句话，可直接被下游引用）

1688 自动化抓取只有一条可行边界：直接访问 `detail.1688.com/offer/ID.html` 商品详情页（无需登录、可抓供应商数据）；搜索结果页（s.1688.com）强制登录墙 + 滑块验证 + JS 空壳，禁止尝试；遇到拦截立即上报索取详情页链接，禁止重试验证码、禁止让用户复制 cookie、禁止捏造供应商名或输出估算数据（B 级实测笔记，2026-05-19）。

## 机制 / 原因

搜索页与详情页的反爬强度是结构性的，不是参数能调的：搜索页是 1688 的风控主战场（重定向登录 + 云端 IP 识别 + 动态渲染），而详情页对未登录流量开放。关键认知是「云端浏览器 ≠ 用户本地浏览器」——Agent 的云端 IP 被识别后，用户在自己电脑上登录帮不了验证码，复制 cookie 也不可行，所以唯一人工解法是用户提供 detail 链接绕过搜索页。重试验证码只会浪费时间并可能加重风控；此时编造供应商数据是最恶劣的输出（KC-0058 详情页归档纪律的数据入口前提）。

## 操作 / 参数

1. 正常工作流：拿到 offer 链接 → DrissionPage/抓取工具直连 → 提取供应商数据 → 遇登录重定向标 [BLOCKED] 上报。
2. 拦截判断：页面显示「拖动滑块完成验证」= 风控拦截；跳转 login.1688.com = 登录墙——两者处理相同，均不重试。
3. 上报话术固定：说明拦截类型 + 请求用户提供 detail.1688.com/offer/ID.html 链接；用户无法代解验证码，只给链接。
4. 禁止三件：禁止验证码后继续重试；禁止要求用户复制 cookie；禁止不抓取就输出「估算」供应商/价格数据或捏造公司名。
5. 找不到详情页链接时的替代路线：走 KC-0188 相似品搜索（offer/图片反查）或人工浏览检索，不走搜索页自动化。
6. 详情页抓到的字段按 KC-0058 归档（offer 链接 + 询盘十项），按 KC-0053 七维评分消费。

## 适用 / 不适用

- 适用：1688 供应商自动调研、货源倒推流程的数据入口设计、Agent 遇 1688 拦截时的标准处置。
- 不适用：人工浏览场景（人可以正常用搜索页，本卡只约束自动化抓取）；已登录本机 Chrome 会话的抓取（KC-0203 第 3 级降级路线，仍只抓公开页面）。
- 站点/类目差异：1688 专属边界；亚马逊前台抓取的反爬走 KC-0203 降级阶梯，两者不可混用。
