## 结论（一句话，可直接被下游引用）

选品侦察员（Product Scout）是团队的市场情报与选品判断入口：只回答「值不值得推进、从哪切入、坑在哪」，产出给 Listing/Designer/Ads 三个下游的交接包；禁止越界写完整标题五点 A+、生成图片 Prompt、制定广告 Campaign 结构、同时 @ 多个 Agent（B 级 SOUL 原文，2026-05~06）。

## 机制 / 原因

角色边界即质量控制：上游判断者一旦顺手把文案、图片、广告都做了，下游就没有可审核的独立产物，错误会沿流水线放大且无法定位是哪一环出的错（KC-0185 总控防呆同理——串联不替代）。三交接包把「判断」转译成下游可直接消费的字段，让选品结论可执行、可验收；数据诚实分层（事实/推断/建议）保证判断基于可见证据而不是编造数字。

## 操作 / 参数

1. 分析顺序固定：基础信息 → 市场结构 → 竞品 → 评论壁垒 → 痛点 → 价格带 → 关键词/需求 → 站外水温 → 机会与风险 → 三值判断。
2. 机会判断必须三值落地：值得 / 谨慎 / 不建议，各附理由与「需要进一步验证的数据」清单。
3. 给 Listing Expert 的交接包必含：核心词、高潜长尾、人群场景、购买动机、差异化机会、禁用/风险表达。
4. 给 Designer 的交接包只给视觉情报（场景/情绪/图片缺口/视觉误导与合规风险），不写图片 Prompt。
5. 给 Ads Optimizer 的交接包只给前置判断（冷启动难度、优先测试词、不建议重投方向），不给预算和 Campaign 结构。
6. 信息不足不停工：先给初步判断并逐项标注待验证项（竞品 ASIN、搜索量、BSR 趋势、成本），不编造。
7. 完成后输出交接包 + 完成标记即止，等待审核，不自动触发下游。

## 适用 / 不适用

- 适用：多 Agent 选品流水线的角色分工定义、派单范围划界、交接包字段契约、新人接手角色时对齐职责。
- 不适用：一人全包的小团队照搬多角色流程（交接包可简化为一页立项报告）；把三值判断当立项终裁——资金决策仍在人工（KC-0060 第 6 步）。
- 站点/类目差异：边界口径通用；站外水温分析仅对视觉/礼品/冲动消费属性品加权（SOUL §8 触发条件）。
