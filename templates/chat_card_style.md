# 星空聊天卡片排版规范 V3（R01）

适用：已启动星空后的 S1–S5、广告终端与单点业务步骤。普通对话、装机排错和版本咨询自然回复；HTML 报告继续按原报告契约生成。

## 步骤卡

使用普通 Markdown 短行，不包代码块，不使用 HTML 标签或折叠。每步回复的第一块内容必须是完整步骤卡，卡前不放说明；用户说「简短 / 只给我看结论和需要我决定的事」也不能省卡。每张卡目标 ≤10 行，结论、模型、下一步必有；阅读偏好只作用于卡后的聊天说明，记录为 `reader_preferences.scope: chat_reply`，不影响报告深度。

| 行 | 规则 |
|---|---|
| ✅ / ⚠️ 标题 | 阶段、N/M、步骤名、进度条。验收未过用 ⚠️；不把完成报告说成验收通过。 |
| 🎯 结论 | 一句话，≤40 字，保留证据限制。 |
| 📊 关键数 | 最多 3 个业务数字；不以进度、产物数凑数，没有则省略。 |

| 🔌 MCP | 服务（工具 ×次数），最多 3 个，超出写「等 N 个」；失败写服务、工具和真实错误；未调用整行省略。 |
| 📚 知识库 | 库名与卡号，最多 3 张，超出写「等 N 张」；无引用省略。 |

| 📦 报告 | 只读本步 `reports: [{label, path}]` 清单，与悬浮窗、Finder 同名同文件；全部可读报告均给链接，网页报告优先；json/yaml 留在回执。 |
| 🤖 模型 | 只写宿主官方模型全称与档位：本步 X ｜ 下一步沿用 / 下一步建议调到 Y；建议不表示已切换。 |

Skill、MCP、知识库、工具、报告这五行只能读取本步回执的 `skills_called`、`mcp_calls`、`kb_cards`、`tools_run`、`reports`；不得用 roadmap、配置或记忆冒充实际执行。连续完成多步，本回合每步完整卡依序保留在最终回复，不合并步号、不用末卡替代前面的卡；已展示历史卡不重复，缺 reply_ack 的卡先补出。每步开始前运行 begin --stage Sx；缺上一步 reply_ack 时先完整出卡并 ack，成功后才执行业务。

## 回执与执行规则（不展示）

机检字段从聊天移入 `运行数据/流程控制/<阶段>/receipts/`，ack 与回归测试读取回执，不再要求用户可见的八个【】字段、字段表或机检折叠。原有阶段/步号/进度/本步 Skill/MCP/模型/结论/已生成文件/下一步/需要动作继续结构化留存，兼容历史回执；不删除历史备注、关键词或审计证据。
新增调用结构：`mcp_calls: [{server, tool, count, ok, error}]`、`tools_run: [{name, label}]`。真实失败、缺口与用户决策照常保存，精简显示不降低门禁。
模型执行策略（主窗口保持当前模型、确定性部分先用脚本、限定辅助任务）只读 `model_routing.yaml` 的 `execution_policy`；不把任务分工、升级条件或辅助策略长句拼进聊天。
卡片渲染清理已知宿主内部标签及其内容；插件规则不覆盖宿主更高优先级的引用要求。

## 阶段收尾与复制口令

交接卡同样 ≤10 行：✅/⚠️ 标题、🎯 阶段结论、📦 阶段报告、👉 下一板块、可复制口令。只有 `stage_acceptance.<阶段>.status = accepted` 才显示完成和下一阶段口令；其他状态列出未通过数量、优先补的最多 3 项，下一步写「补齐数据」。内部交接证据照常保存，未通过时不显示进下一阶段口令。
口令用单独一行可复制文本或只包口令的代码块；不折叠、不把整张卡包进代码块。当前阶段范围、用户授权、缺数与审批要求继续按原契约执行；已批准且未变化的事项无需重复审批。

R05 显式继续下一阶段：S1–S4 最后一步正式交付后，用户要进下一阶段（含 Hold、验收未通过），按 workflow_flow.py continue-next（S1 也可 continue-s2）记录扩范围，生成带缺口工作交接卡和复制口令；原样展示后本窗口停止，用户新开窗口粘贴口令进入 S2。非硬阻断缺项写入交接，原 S1 Hold 保留；侵权红线仍阻断，不授予采购、上架或改后台权限。

## 自检

- 卡片为普通 Markdown，目标 ≤10 行，结论、模型、完整报告清单和下一步齐全；不能为行数删报告链接或真实用户动作。
- 无 HTML 折叠、机检字段表、空 MCP 行、重复模型说明或内部标签。
- 下一步来自实际 N+1，调用与报告来自本步回执，验收状态如实显示。
- 需要用户选择时保留文字选项；业务门禁、历史备注和关键词保持原规则。
