# S1 统一事实与报告交付

适用 Codex 与 Claude 的 S1 共用业务层；模型路由沿用各宿主配置。

1. 先保存原始回包、采集时间与来源哈希。以 `scripts/s1_market_facts.py` 统一竞品详情快照、父体代表、价格分位与逐行台账。后补数据另存 `运行数据/S1_后补采集`，不得悄悄改写原快照口径；它只能更新已验证覆盖与后补证据区域。
2. 读取市场 Skill 的 `market_criteria` 结构与真实五维评分要求；缺数据写具体工具、真实错误或覆盖限制、来源及下一步。不能用样例分数、请求参数或工具数组顺序填补评分、自然排名、旺季排名。
3. 用户选款、现货参考、定制方案分别记录。无采购 SKU 时页价展示区间；按已知形态计算的页价/重量只作条件参考。定制方案先核 ODM、来图打样及隔层能力，不足三家合格厂家如实列缺口，不能用无关五金或现货商家凑数。
4. 使用成本模型计算实际和条件两类结果。条件利润展示零额外费用与预算上界两档及完整假设；上界不保证封顶。采购价、最终重量包装、数量或利润目标未知时，不得写成用户已确认。保留成本尺子、广告承受能力、允许到岸成本和当前费表来源。
5. 合规输入仅针对本轮选中产品；未知保持三态，不能把 `lead_time` 当成铅，也不能把竞品/参考货源其他款式当成本品风险。使用 `sync_ip_report.py` 更新主 IP 叙事与尺子；未查项给准确自查卡。完整待核可以研究交付，不等于采购或上架通过。
6. 报告生成前读取产品内 `报告呈现约定.yaml`，保留已确认主题、正文深度和局部布局。只维护一份正式 S1 MD 与 HTML，二者同源；纠偏稿的有效事实先并入，再归档 `_history`。不要把整份决策报告复制进市场或 CT 子报告。
7. 执行 `scripts/repair_s1_reports.py --root "产品根"`，再运行正式 `verify_s1_acceptance.py "产品根"` 并保存完整日志。此脚本只读现有研究资料重算派生报告，不调用后台写接口、不采购，不代替补取数据和分析。仅改排版且事实未变时可用 `sync_s1_decision_reports.py --root "产品根" --refresh-manifest`；禁止用刷新哈希掩盖旧事实。
8. 检查导航、README 和最终链接均指向正式报告；跨电脑图片采用项目相对路径。首屏无样品的设计使用规格卡，图片为参考时明确标记。手机目录默认折叠，图像展示副本不超过 800px/150KB，主文不用 Python 列表、整页空值表或自我道歉。
9. 验收退出码 1 是结构或必需来源阻断，2 是研究结构可交付但证据待补，0 才是全部检查通过。任何报告生成成功都不能自动写 `stage_acceptance.S1=accepted` 或采购通过；最终交接逐项说明剩余缺口和允许的下一步。
