# 统一资料接入层 · 后续 Skill 必读契约

本契约适用于沙龙工具包中的业务 Skill、全链总控和单点任务。目标是让用户可以在入口投喂未整理的目录、文件、附件、截图、表格、链接或历史报告，AI 先形成统一资料接入结论，再约束后续执行。

## 1. 何时必须先读

当前产品 run 存在以下任意文件时，业务 Skill 在任何分析、文案、视觉、广告、供应链或视频工作前必须先读：

1. 00_总控/starsky-fullchain-workflow/00C_资料接入与优化建议报告.md
2. 00_总控/starsky-fullchain-workflow/00C_data_intake_overlay.yaml
3. workflow_state.yaml 中 data_intake 的状态和路径

随后再读当前任务的 00B 单点接入单、阶段产物或运行时叠层，最后才调用 MCP 补数。

## 2. 统一读取顺序

1. 00C 报告：理解资料范围、优化建议、缺口和用户选择。
2. 00C Overlay：应用可用来源、事实边界、禁区、冲突和推荐 MCP 计划。
3. **资料包内的索引层（见 2.1）**：先读，再决定要不要展开原始文件。
4. 当前任务产物：00B、product facts、词库、Listing、图片清单、广告报表等。
5. MCP：只补当前任务需要且既有资料不足的字段，并记录实际调用或 skipped 原因。
6. 用户追问：仅在上述来源均不能取得、且字段构成当前任务硬缺口时提出。

### 2.1 索引层优先（强制）

资料包内若存在**索引/映射/速查类文件**，必须**先于同目录原始文件读取**，并按其指引决定展开哪些原始件。

识别特征（满足任一即视为索引层）：

- 文件名含：`映射表`、`速查`、`索引`、`说明`、`清单`、`manifest`、`inventory`、`README`
- 位于目录根部且为 `.md` / `.csv`，内容是对同目录其他文件的分类、用途或口径说明

强制行为：

1. **先读索引层**，据此判断本阶段需要哪些原始件；不得跳过索引直接遍历 PDF/XLSX。
2. 索引层给出的**口径、阈值来源、使用边界、阶段归属**优先于阅读者自行推断。
3. 索引层与原始件冲突时，**记录冲突**并以原始件为事实、以索引层为口径说明；不得静默取其一。
4. 若某类资料的 `stage_targets` 含当前阶段，而 00C 的"本阶段可用来源"表未列入，必须写明**为何不注入**；不得无声略过。

### 2.2 派生值必须可溯源（强制）

资料包中经过预计算的字段（落地成本、计费重、占比、评分等）**可以直接使用，但不得只引用结果**。

引用任一派生值时，必须同时给出以下之一：

- 该文件提供的**计算式列**（如 `每件头程计算式`、`落地成本计算式`）
- 或自行还原的推导链：**输入字段 → 公式 → 结果**

禁止行为：把 `落地成本USD = 0.436` 这类预算结果直接写进报告，却不说明它由哪些字段、哪条费率、哪个线路算出。**读者无法审计的数字等同于未标注来源的推断。**

若索引层已声明费率/线路/口径（如"义乌交货·包税DDP·¥7.7/kg"），报告必须原样带上该口径，不得省略。

### 2.3 注入必须传导到下游报告（强制）

00C 里"本阶段可用来源"表中列出的每一条，**必须在该阶段的业务报告中被实际消费或显式弃用**。

实测反模式：00C 完整列出了 7 类来源并引用了索引层，但下游的阶段报告一条都没提 —— 资料在接入层被读了，却没有传导下去。**这等同于没有注入。**

强制行为：

1. 阶段报告必须含一节「本步资料注入」，逐条列出：`source_id` → 用在哪一段 → 得出什么。
2. 00C 已列入但本阶段未使用的来源，必须写明**为何不用**（不适用 / 时效过期 / 与本轮事实冲突 / 阶段不匹配）。
3. 不得只在 00C 出现而在业务报告中消失。任何"接入层读了但下游没体现"的来源，视为注入失败。

#### 2.3.1 source_id 区间必须展开到影响结论的具体文件

允许用区间（`TEST-034–046`）表示"这一类都读了"，**但凡对结论产生实质影响的来源，必须展开到单个文件并说明它贡献了什么**。

实测反模式：注入表写 `TEST-034–046 | 家居收纳关键词资料 | 消费分类、SIF 清洗、否词和跟踪方法`。
这一行覆盖 13 份文件，其中包含 **SIF / H10 / 卖家精灵三套互不相同的归类方法** —— 读者无法判断最终采用了哪一套、为什么。**区间引用在这里变成了一个新的黑箱**，与 §2.2「派生值必须可溯源」是同一类问题。

**判定标准**：区间内的文件若存在**互斥选项**（多套方法、多个版本、多种口径），必须展开。

| 情况 | 写法 |
|---|---|
| 同类同质，无需选择（如 7 份敏感词表全部合并去重） | ✅ 可用区间：`TEST-014–020 \| 敏感词表 \| 合并去重后作过滤源` |
| **存在互斥选项**（三套归类法选一套） | ❌ 不可用区间，必须展开 |
| 只有部分文件被实际使用 | ❌ 不可用区间，须列出用了哪几个、其余为何不用 |

展开时必须写清**选型理由**：

```markdown
| source_id | 文件 | 本步消费 |
|---|---|---|
| TEST-036 | SIF关键词清洗归类方法.pdf | ✅ **采用**——本轮导出表为 SIF 格式，字段口径一致 |
| TEST-037 | 卖家精灵关键词归类方法.pdf | ⭕ 未采用——导出源不匹配；其"场景词"维度已并入六维标签 |
| TEST-038 | H10关键词归类方法.pdf | ⭕ 未采用——同上 |
| TEST-041 | 广告否词模板-V5.xlsx | ✅ **采用**——作为否词池基线，与本轮 IP 黑名单合并 |
```

**"未采用"也要写。** 三套方法只选一套是正确的，但不说明为什么选它，等于把选择过程藏起来了 —— 下次换类目时无人知道该不该换一套。

### 2.4 叠层的执行语义必须落地（强制）

企业资料包中的 `hard_rules`、`validated_thresholds`、`defaults` 若写成 **if-then 形式或带触发条件**，业务报告必须逐条落地为具体动作，或写明为何不适用。

**只在规则表里列出编号（如"已参考 T-04/T-12/T-13"）而正文无对应动作，视为未执行。**

强制行为：

1. 规则含"必须同时输出 ①②③"这类结构时，三项缺一即判该章节不完整。
2. 规则给出推导理由（如"覆盖 60 天 < 提前期 58-86 天，等库存见底来不及"）时，理由必须进入报告，不能只留结论。
3. 阈值来源标注为**编造/测试值**的，可以引用但必须同时标注"不可用于真实决策"；来源为**真实推导**的，必须带上推导链。
4. 硬规则（禁区类）在本阶段无命中时，也要写"已检查，无命中"，而不是完全不提。

> 优先级不变：叠层仍低于当前产品事实与本轮 MCP。**"低优先级"指冲突时让位，不指可以不执行。** 无冲突时叠层规则是必须执行的。

## 3. 约束优先级

从高到低：

1. 当前产品事实、页面抓取与本轮 MCP 的可验证数据。
2. 平台合规、IP 与用户确认的硬规则。
3. 用户投喂的历史资料、案例、SOP、图片和报表。
4. 标注的默认值或 AI 推断。

历史资料可以影响策略、表达、否词、视觉构图或起始广告骨架，但不能覆盖当前事实、合规或 IP 结论，也不能把竞品素材当成本品素材。

## 4. 没有 00C 时

- 用户没有投喂资料：写 data_intake.status=not_requested，直接继续，不把 00C 变成新的阻塞。
- 用户投喂了原始资料但没有 00C：先执行资料接入。资料无需整理；建立只读 inventory、00C 报告与 Overlay 后再进入业务任务。
- 新资料在执行中到达：更新 00C 为 revision_needed，按 impact_scoped 只重算受影响产物，保留旧版记录。

## 5. 每步记录

每个业务 Skill 的数据解释窗口或 handoff 至少说明：

- 读了哪些 00C 来源和约束。
- 哪些字段来自 MCP、用户资料、现有产物或推断。
- 哪些资料只作为参考，不能写进前台或上传文件。
- 后补资料会影响哪些产物。

不能把未读资料、MCP 失败结果或 AI 推断写成已验证事实。
