# S1 产品开发决策透视

保留九步骨架、原研究深度、历史备注与关键词；先完成已授权的研究，缺证仍交付报告，不能把交付完成当成值得采购。

## 先读配置，再研究

读取已确认用户偏好，产品覆盖用户、用户覆盖模式默认；本轮明确范围最高优先。字段注明来源与适用条件，冲突时展示差异，不静默覆盖。广告前目标、广告后净利目标分开，未确认保持空值。不得把案例的40%、8元/kg、200元/票或数量当通用默认。

从 `templates/s1_decision_inputs.yaml` 初始化产品根输入（已存在不覆盖），按 value/unit/status/source/observed_at/valid_until 保存证据。用户口述、页面字段、厂家确认、官方费用、第三方代理与假设区分；有值不等于已证实。

## 按产品特点拆细

| 层次 | 必须回答 | 补证重点 |
|---|---|---|
| 需求 | 谁在何种场景需要，替代品哪里不足 | 真实需求线索、反证、覆盖率；组件销量不能证明整套需求 |
| CT | 每个组件的图片、SKU、规格、数量、材质、阶梯价、MOQ、库存、重量和链接 | 页面展开尺寸与最终包装尺寸分开；图片为参考或实拍必须标明 |
| 组合 | 增加了什么价值，组件尺寸和使用方式是否适配 | 适配未验证不写已成立，数量与主副件对应 |
| 价格 | 同形态同配置市场价格在哪里 | 优惠、日期、货币、形态差异；组件售价相加不是整套支付意愿 |
| 成本 | 采购、转运、装套、包装、标签、物流、分摊、平台及其他适用费用 | 区分缺失、不适用、已包含与确认0；不得重复计费 |
| 利润 | 市场价下利润、目标利润所需售价、未知费余量、允许成本 | 条件情景与完整证据计算分开；最低佣金/阶梯收费按实际规则 |
| 厂家 | 装套、包装、标签、箱规、成套报价、有效期与交期 | 外购组件接收、缺件责任、质量检查和后续配合 |
| 风险 | 品牌、图片、专利线索、声明、适配、质量及包装 | 已查与未查分开，不能靠擦标宣称权利问题解决 |
| 拿样 | 支持与反对证据、未满足项、下一项补证 | 建议不等于采购授权；样品与首批SKU分开 |

尺寸敏感产品重点检查最终包装与费用档位；季节品倒推拿样、生产、运输和测试窗口；多供应商组合明确每次交接；单品简化组件数量但不删风险与成本证据。

## 同源生成与失效

成本账沿用 `05_cost_inputs.yaml` / `05_cost_model.yaml`，记录输入摘要；修改后先复算成本，再生成报告。产品根决策输入只负责组件、研究、厂家证据和范围，不手填“实际达标”覆盖成本计算。

核对组件数量/SKU、包装和厂家报价与成本输入一致后，用 `scripts/s1_decision_binding.py --root "产品根"` 取得配置摘要，填入成本输入的 `product_configuration_sha256` 再复算。此摘要只绑定已核对配置，不代替事实核查；禁止不更新成本就机械换摘要。配置变化后旧成本不可用于拿样通过。

组合成本 `offers[].evidence` 逐项记录 main_qty、extra_cny_per_unit、extra_one_off_cny、package_cm、package_weight_kg、fba_fee 的事实单元；其 value 必须匹配该方案实际计算值，并有确认来源与有效日期。未确认的备选方案保留条件结果，不阻断已完整核验且有市场价格依据的选中方案。

活动第9步必须执行 `scripts/sync_s1_decision_reports.py --root "产品根" --compact-receipt "00_总控/starsky-fullchain-workflow/运行数据/流程控制/S1/receipts/09.json"`，直接同源生成完整阶段 MD、HTML 与稳定回执。决策模型、来源、原报告字节和修订信息合入回执，不先跑 legacy sync、独立透视或例行历史修复；原文、备注和关键词完整保留。已有输入及授权不重新审批；未知字段保留 null，不以报告生成替代商业验收。

缺少 s1_decision_inputs.yaml 时命令真实阻断且不写文件：先报告缺项，按本轮已知事实与真实授权建立输入，再执行同一 compact 命令；不得编造值或默认 scope 来通过。随后提交含 report_md、report_html、decision_yaml（稳定09.json的 /s1_stage_data）的回执，record 执行原业务验收并刷新导航；验收失败也交付完整报告、缺项与警示，保持 pending。

独立显式历史修复/同步仍可执行 `scripts/sync_s1_decision_reports.py --root "产品根" --legacy`，按原规则保留快照、同步清单和研究历史；它不属于活动第9步的例行命令。旧无模式调用兼容原行为，不用刷新清单掩盖事实变化。

价格、包装、供应商、汇率、类目费用或关键证据变化后，旧判断失效并重新校验。过期报价只能作历史/情景；未配置有效期不伪称长期有效。

## 阅读与输出

先显示组合和判断、关键成本与限制，再展开完整研究。段落一主题、通常不超过3句；相同维度用表格，复杂产品配图。HTML正文与展开区同标准，手机宽度可读；MD标题分级、空行、图片和表格清晰。不能删掉原文以制造短报告，不能把重要缺项藏进折叠区。

## 阶段边界

仅 S1 不引导自动 S2。继续补证、值得拿样、暂停/淘汰与九步游标独立；值得拿样仍需用户采购授权。样品验证、测款、补货仅留接口，不自动执行。稳定盈利窗口、净利目标、风险预算、质检标准待用户确认。
