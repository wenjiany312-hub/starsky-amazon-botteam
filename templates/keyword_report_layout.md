# S2 词库固定报告与共同判断方法

SIF、SellerSprite、西柚共用这份阅读结构；每个主词包仍遵循 Keyword Package 2.0 的单源、原始字段和 Hash 契约。布局由模板版本决定，普通产品运行不重写 HTML。

## 一、固定八节（决策在前，明细在后）

| 顺序 | 章节 | 必须回答的问题 |
|---|---|---|
| 1 | 结论与现在要处理的事 | 原始/唯一/可用/待核/排除各多少；可用词总量与最大入口；季节峰值；哪条声明挡住了多少量；最需要处理的 ≤3 件事 |
| 2 | 核心词 → 一级词 → 二级词 | 核心词根（含 MCP 精确词与长尾占比、事实状态）；Exact-P1 全量；Exact-P2 前 30 与总数；门槛与依据 |
| 3 | 埋词位置 | 标题/亮点/五点/描述/ST/属性/问答/兼容复核各有多少候选、代表词是什么 |
| 4 | 广告分池 | 各池词数、打法与代表词；否定建议（词组/精确，先复核）；商品定投候选；不是投放授权 |
| 5 | MCP 补数与季节 | 调了哪些工具、结果与通道；季节峰值与强度；主词趋势、当前位置、距峰值周数与行动提示；精确 vs 长尾；头部竞争 |
| 6 | 词库体检 | 数量守恒、判定原因分布、流量集中度、字段填充率、六维入口、声明解锁、品牌/IP/排除词根、高量非本品、待复核队列、污染词根、最强反方 |
| 7 | 选词工作表 | 可用词全量，待核/排除按量取前列；筛选“全部、文案、新品广告、待核、排除”；全部唯一词在 CSV |
| 8 | 来源与证据 | 数据来源、本品事实登记（状态与依据）、限制、输入指纹与校验 |

页面体积跟词数无关：逐词只进工作表一行，不内嵌原始 JSON；完整字段与血缘在 `keywords.csv`、`report_model.json`。第五节没有补数也保留，写清原因和影响。缺失不改章节顺序，不用图片或装饰趋势代替数据。

## 一B、HTML 阅读形态（s2-unified-2.1 起）

- 左侧电梯目录：八节 + 每节小标题/折叠块，点即跳转，跳到折叠块自动展开；可锁定（跟屏）也可收起；当前节自动高亮；有「全部展开 / 全部折叠」。手机宽度目录放顶部。MD 版全部展开，不折叠。
- 核心不折叠：01 结论与主力词速览（周量前 10，写明层级、文案位置、广告池）、02 核心词根与一级词前 20、03 埋词位置卡、04 广告分池卡、05 季节判断与主词需求、06 体检摘要与最强反方、07 工作表。
- 可折叠（标题写条数）：一级词其余、二级词、否定建议、MCP 调用明细、词根精确/长尾、头部竞争、月度趋势图、06 各明细表。
- 03/04 用途卡：每个位置/广告池一张卡，写词数与打法，周量前 10 以词标签显示；更多用「在选词工作表查看全部」按钮筛选 07，不在卡里重复铺词。
- 超过 12 行的表放入限高滚动框、表头固定；07 工作表同样框内滚动。
- 判定原因分布：共用规则原因照原文计数；逐词复核的一次性理由按「状态 · 判定类别」归组并给 3 个例词，不逐词成行。

## 二、判断维度先于排序

每个 keyword_id 贯穿来源、判断、文案与广告用途：

| 维度 | 内容 |
|---|---|
| 身份 | 原词、normalized_keyword、中文、产品词根 |
| 需求 | 主分类为产品词/属性词/其他；多标签为功能、规格、材质、场景、人群、兼容、痛点 |
| 本品匹配 | direct / adjacent / mismatch / unknown，判断理由与 fact_refs |
| IP/声明 | 可用、待证、禁用、限定用途复核；关联 S1 与企业限制 |
| 文案用途 | Title、Highlights、Bullet 编号、Description、ST、暂不使用；候选与已用分开 |
| 广告用途 | 新品精准测试、词组扩展、探索观察、品牌/竞品另审、否定建议、暂不投 |
| 指标 | 各自来源、日期/周期、单位、语义和 missing_reason |
| 修订 | 原决定、新决定、理由、时间与人工确认状态 |

既有 D1–D6 标签保留做兼容，不代替主分类与本品资格。唯一词按主分类统计，多标签次数不能加总冒充唯一词数。

**资格顺序：当前事实与 S1/企业限制 → 本品匹配 → 可用用途 → 同源可比指标排序。** 高流量、平台高相关、共同覆盖都不能授权本品没有的功能。待证/禁用词保留在 records 研究账本，退出可用文案与默认广告池。

竞品品牌不进消费者文案/ST；已确认自有品牌可用于 Title。兼容词须有商品证据及 S1 指定用途许可。品牌隔离与广告否定分别判断，否定建议记录范围、匹配方式、拦截理由与误伤检查，不自动扩大到全账户。

## 三、来源选择与 MCP

继承用户选择或 manifest 的 chosen_keyword_skill；仅一个导表来源已就位时沿用该来源。没有来源选择时默认优先 SIF 的适用能力；用户明确“仅用导表/不调用”时不调 MCP。

先检查当前任务实际工具清单与 schema，再确定参数、逐 ASIN 分页、截断状态、时间范围和批量。授权/配置、工具暴露、协议连通、业务返回分别记录；只有本轮业务返回有证据才标 used/partial。工具未暴露为 skipped，真实调用失败为 failed，不凭历史成功写本轮已调用。

- 同源补数以新 source_id 并列保存，保留原始返回与脱敏调用摘要，不覆盖导表原值。
- SIF、西柚、Sorftime、SellerSprite 跨源补充作为独立 evidence/context 记录，不写入主包冒名补空，不平均跨源指标。
- 先补本品可用的高价值词，再处理判断分歧与季节敏感词；不因有工具就全量扩搜。
- 缺数保留 null 与原因。提供已完成范围、缺口、判断影响和实际可重试入口，不生成无证据指标。

## 四、时间与季节判断

默认尝试两个完整年度的可比历史，作为项目分析配置而非接口保证；只取到一年就降低确定性，只有一周不能判全年峰值。显示来源、窗口、同比/峰值依据、可能的促销或缺货影响、行动窗口；事件影响只有有证据才写成原因。

历史数据留历史视图。当前排行只比较相同语义与可比较周期；不同年/月、周/月、搜索量/曝光量、集中度/CVR 都不能混排冒充同一指标。搜索量合计称“选定词集合的搜索量”，不称去重买家流量。只有可解释的时间序列才生成趋势图；空值不当零、插值不冒充观测。

## 五、固定入口与下游

插件根运行：

```powershell
python scripts/s2_report.py --package "<keyword_package.yaml>" --context "<context.json>" --output-dir "<report-dir>"
```

有文案加 `--listing "<listing.json>"`，有基线加 `--baseline "<baseline.json>"`。字段以 `s2_report_input.md` 和脚本 `--help` 为准。输出包括 `keyword_report.html`、`keywords.csv`、`report_model.json`、`validation.json`、`manifest.json`；文案输入对应 `listing_report.html`、`listing.md`。Listing 固定十节见 `../skills/amazon-listing-copywriter/references/listing-report-contract.md`。

报告渲染只读输入。context 里的判断供审核展示；正式下游用途资格须写入所选 keyword_package、重新 finalize Hash 后交接。路由可将输出映射到 06/07 旧命名，并记录映射与输入指纹；禁止现场写 render_*.py 或另造 HTML 绕过。

## 六、验收口径

检查原始行→唯一词→所有 disposition 的数量守恒、字段语义、事实/IP资格、用途、覆盖与输入指纹。覆盖分为原词出现、词形/分词覆盖、语义关联、未覆盖，由实际文本计算。

不设置 KB、表格、进度条、场景卡或保留率下限。保留率异常只触发有证据的分类复核；事实不足保留空状态。CSV 和完整来源账本保留被筛出的研究词，不能只交若干热词。

固定模板通过代表结构和计算可复核；自然度、收益、建议合理性需人工审核。广告候选仍需策略、审核及执行授权。DEMO/TEST_ONLY 继续保留不可上传标识。
