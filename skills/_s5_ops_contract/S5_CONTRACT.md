## 进 S5：店铺配置只做一次，每轮只确认范围

先运行 `s5_connect.py route [--root <产品根>]`，原样展示返回的 `ask`。接入指南仍在悬浮窗第一项；首次卡后停，等待用户选接法。

1. **首次入口**：两种接法是「① 手动表格」「② 接 ERP 自动取数 + 飞书日报」。ERP 子选择是领星、赛狐、优麦云，用哪个接哪个，按官方接入指引操作，入口卡不逐个标通道状态。两条路线都介绍准备材料、能做什么、成本表。
2. 回 1 → `route --set manual` → `check`，只带成本表和报表投喂，不配置或提示飞书。回 2 → `route --set erp`，问用哪个 ERP，再 `route --set lingxing|saihu|youmaiyun` → `check`。凭据、店铺、飞书、成本表一次一步一起检测；用户明确说「先不要」时 `check --skip-feishu`，保存这条路线的选择。
3. **如实提示**：赛狐、优麦云本轮仅保存凭据；选择后必须说「凭据已存，这条通道还没接通，本轮先用手动表格」。不把已存文件、已配好或接入检测当作取数成功。领星连接也必须有真实响应才可称接通。
4. **以后进入**：已配置返回一行「沿用：领星 + 飞书日报（已配好）。本轮看全店还是这个产品？」；明确跳过日报时不声称已接日报。用户回「沿用」直接进入所选范围；换路线只检查未配好的项目，已配过的不重配。检测到新通道只问一次是否换，不自动切换。没有回复不算同意。
5. **全局记录**：`~/.starsky-codex/config/s5_setup.json`（Claude 为 `~/.starsky-claude/config/s5_setup.json`）保存版本、默认路线、所有路线配置状态、店铺选择、日报就绪/跳过状态和成本表引用。密钥仍在现有本机凭据文件，不写入此记录。旧产品 `S5_运营板块/s5_route.json` 在首次读取时迁移，之后产品夹只记本轮范围。`--root` 可省略，没有产品时用 `ops_workspace`。
6. **范围**：全店 / 当前产品 / 指定 ASIN / 某父体下所有变体。对应原流程 `ingest --scope store`、默认 product、`--asin`、`--parent`。无产品根时先确认全店，不猜产品映射。

安装带 `routes.d/api.yaml` 时追加「③ API 直连 · 广告终端」。选 ③ 用 `route --set api` 的 `onboarding` 执行结果直接进入终端接入向导（status → 必要时 install/start → open setup）；日常「今日巡检 / 复盘某产品广告 / 文案缺口」都交终端，不要求用户再记打开终端口令。配好店铺授权、飞书（可明确跳过）、成本表后再检查。终端配置由路线检测脚本直接读取，不要求再填一份。 <!--flagship-->

终端内七步与文案缺口映射见 `starsky-ads-terminal/references/S5复盘覆盖核对.md`。原 S5 复盘与审批/Bulk/观察流程继续保留，只有完整链路验收后才能考虑删除。 <!--flagship-->

### 诊断顺序（两条路线通用，先看总盘再动手）

1. 取数：按日期区间拉（ERP 自动，手动读下载表）。
2. 先看总盘：报告第一节「单量拆解」定位单量变化在哪一端；对每个有问题的产品，助手用 SIF / Sorftime / 卖家精灵 / 西柚核对**市场**（核心词搜索量趋势，同期对比）、**竞争环境**（竞品价格、排名、新品、断货）、**流量**（曝光、点击、访问是否达标），一句话结论写进 `evidence.yaml` 的 `breakdown_check`。没核对就不出报告的「结论」，报告会标「未核对总盘」并给提醒。**不要因为某天卖得差就砍价格、砍广告预算。**
3. 再给建议：结合本地广告知识库（`ads_knowledge_base` / `promotion_knowledge_base`）和第三方数据，写每条动作的原因和依据。
4. 出报告给用户判断。ERP 路线：批准后领星能写的一键同步；手动路线：出上传表，用户到后台「批量操作」上传，并引导核对。

### 文案（手动 / ERP 通用，永远由用户到后台手动改）

- 当前文案来源：用户贴标题 / 五点 / ST，或给产品链接（助手用内置浏览器打开读取，整理成 `_投喂_广告报表/当前文案.json`：`title`、`bullets`、`search_terms`）；ERP 路线可从领星 / 已有 S2 文案读。
- **有 S1 / S2 排查记录**（从 S1 一路做过来的品）：自动读取黑名单（品牌 / 侵权词、受限宣称）、S2 带下来的禁用词、产品 CT，改稿撞到任何一条 → 报告出「必须改」，审批被拦，用户拿不到这条改稿。
- **没有排查记录**（老品直接进 S5，或只拉数据做诊断的品）：**不拒绝出改稿，但必须醒目提醒**——报告文案区最上面有红框「改文案前请先自己确认：没有做过 IP / 敏感词排查」和自查清单；助手讲方案时**先说这一句**，明确告诉用户「改不改由你判断，但改之前你要自己确认改后没有侵权词和敏感词」。批准文案改动时，用户必须明确回一句「我会自己核对，确认没有侵权词和敏感词」，助手才用 `approve --listing --ack-ip`（用户没回就只批广告动作）。
- **明显的问题不管有没有排查记录都指出来**：绝对化 / 促销 / 医疗疗效 / EPA 抗菌 / FDA 背书这类受限用语，和合规尺子里的已知商标陷阱词（Q-tips 这一类，报告会写出商标所有者和通用说法），助手自己不会写进改稿，撞到就是「必须改」。
- **助手能做的额外帮忙**：网络和 MCP 通时，对改稿里的核心词 / 新增卖点短语先做一轮预排查（SIF / Sorftime 看品牌词属性，给出 USPTO 检索链接 `compliance_ruler.py` 的 required_searches），把可疑的词列给用户「这几个词有风险，建议换成…」；查不出问题的也**不说「没问题」**，说「我这边没查出明显问题，最终请你自己确认」。想要完整排查，让用户说「IP排查」（`amazon-ip-risk-assessment`），结果留在 S1 目录，以后自动读取。
- 用户审核后，指导他到卖家后台手动改，改完核对页面。

## 单量拆解：先定位是哪一端，再动手（两条路线通用）

诊断报告第一节是「单量拆解」（`02_诊断方案.json` 的 `order_breakdown`，依据广告知识库 KC-0163 / KC-0164）：本期对比上期，把单量变化拆成广告单 / 自然单，再看广告曝光、点击率、广告转化率、TACOS，定位到一端——市场端、广告曝光端、点击端、转化端、自然端、利润端（样本不足 5 单只标「样本太小」）。

- 给用户讲方案时**先讲这一节**：「单量掉在哪一端 → 所以本轮做什么、先别做什么」，再讲具体动作。不要一看单量掉就同时加广告、降价、改图。
- 定位在**转化端 / 市场端**的产品，本轮自动不出加价、加预算、广告位加价（进观望，写明原因）；转化端先查差评、价格、Listing、变体库存，市场端先用 SIF 看搜索量 / 季节。
- ERP 路线（领星）按产品拆，能看到自然单；手动报表路线只有广告数据，对比上一轮同范围快照、只看广告这一侧，并提示用户看后台业务报告的总订单 / 会话，或接领星。
- 飞书日报「今日方案」带拆解摘要（哪几个产品、单量从几到几、卡在哪一端）。

## 手动报表路线（不需要接任何系统）

用户在广告后台「批量操作 → 创建并下载电子表格」选日期、勾选「商品推广搜索词」，一个文件就有全部活动 / 广告组 / 关键词 / 投放 / 商品广告 / 否定词 / 广告组合（带后台 ID）和搜索词。单独下载的「商品推广搜索词报告」是按天分行、没有 ID，只在没有批量表时用（脚本自动按词合并，有批量表就忽略它，避免重复计算）。

```text
1. <python> <home>/skills/_s5_ops_contract/scripts/s5_optimize.py ingest --run "<产品根>" [--input "<文件或文件夹>"] [--scope store] [--sku X]
   默认只看本品（S4 ad_plan / S2 文案里的 SKU 所在活动）；用户说分析全店才 --scope store。中英文下载表都认。
2. … diagnose --run "<产品根>"   利润账取 S4 策略（客单价、目标 / 保本 ACOS）；全店时每个活动用自己的客单价。
   规则：点击 <10 只观望；无单点击够 → 降 30%；无单花费超两单目标成本 → 暂停；出单但 ACOS 高 → 按目标折算降价；
   出单稳且 ACOS 低 → 加价（不超出价天花板）；搜索词 ≥2 单 → 进同产品精准组（没有就给该 SKU 新建精准活动，自动带广告组合）；
   搜索词点击够、花费超一单目标成本无单 → 否定精准；别人家 ASIN → 否定商品；带产品 CT「本品不是」的词 → 否定词组。
   实际 CPC 高于竞价的会提示查广告位加价。现文案读 S2 定稿（或投喂夹的 当前文案.json），出单词没埋的列缺口，现文案里的品牌词 / CT 冲突词列为问题。
3. 助手：ads_knowledge_base kb_diagnose / kb_scenario_rules 取 KC 号、SIF / 西柚查现窗数据与机会词 → 填 evidence.yaml；
   每条动作写 advice：「建议执行」或「暂缓」（知识库门槛没过：日出 <5 单不降 ACOS〔KC-0006〕、活动未满 2 周〔KC-0024〕、
   点击 <20〔KC-0003〕、ACOS 在目标 ±15% 内〔KC-0005〕；或 SIF 显示该词市场本身打不起而本账户表现更好）。
   「全部同意」只批建议执行的，暂缓的要用户点名才批。kb_summary 写门槛结论与 SIF 机会词。
   文案要改就在 listing_proposal.yaml 写改后标题 / 五点 / ST（change: true，每处改动一句理由）。
4. … report → 03_优化前后对比.html：一眼结论、广告改前→改后（为什么 + 依据 + 数据）、观望、文案改前→改后（黄底=新增）、数据与方法。
   退出码 2 = 必须改（改后文案含品牌词 / CT 冲突词、ST 超 249 字节等）。发可点链接给用户。【等你】
5. 用户回「全部同意」/「同意 A01、A03，不要 A02」/「文案也改」→ … approve --all | --approve A01,A03 --reject A02 [--listing] --note "<原话>"
6. … bulk → 05_上传包/S5_优化上传_<轮次>.xlsx（照用户下载表的表名、表头和语言，只写要改的行：已有对象用真实 ID 更新，新词创建）
   + 从这里开始.html（上传步骤 + 文案逐栏复制）。首次在中文后台上传建议先传两三行试试；操作列不认「更新 / 创建」时加 --operation-lang en。
7. 用户上传、改文案后回复结果 → … receipt --status uploaded --note "<原话>"：72 小时看方向、7 天看转化；下一轮重新下载表格从 1 开始。
```

- 出单词转精准后，来源组的否定精准留到下一轮（精准组跑出数据再做），不在同一张表里断流。
- 审批后报告改过就要重新审批；没有批量表（没有 ID）只能看建议，不出上传表。

## ERP 路线：领星 / 赛狐取数 + 批准后写回（用户开通了开放接口）

板块划分：S5 = **广告优化** + **文案优化**（现在）；以后加 **供应链**（备货、发货、报关单、货物合同，领星有补货建议 / FBA 发货计划 / STA / 移除订单接口）。

```text
1. <python> …/s5_optimize.py ingest --run "<产品根或 ops_workspace/站点>" --source lingxing --sid <店铺 sid> --start <日期> --end <日期> [--scope store]
   只读：活动 / 广告组 / 关键词 / 投放 / 广告商品 / 否定词 / 广告组合 / 广告位设置与按天广告位报告 / 按天搜索词。凭据在用户目录 config/lingxing_config.yaml。
2. diagnose → 助手填 evidence.yaml（知识库 + SIF，advice 建议执行 / 暂缓）→ report →【等你】批准 → approve
3. <python> …/s5_lingxing_writeback.py --run "<同上>" --sid <sid>             # 预演：核对后台现值，列出要写什么
   <python> …/s5_lingxing_writeback.py --run "<同上>" --sid <sid> --execute   # 用户明确同意后才真写
```

- 能写回：改竞价 / 暂停（关键词、商品投放）、出单词加进已有精准组、否定关键词（精准 / 词组）、否定 ASIN、改日预算、改广告位加价（三个广告位一起提交，没改的保持现值）。
- 写不了：新建活动 / 广告组（领星没有接口）→ 仍出上传表。
- 写前核对后台现值，被人改过就跳过；原始返回先落盘；写后回读 + 查领星操作日志，回执 `06_写回回执.json`。
- 冷却期：7 天内写回改过的对象，下一轮诊断自动观望（KC-0024 双周复盘），不连续加码。
- 预算规则：预算花满 90% 以上 + 达标 → 加 30%；花满但 ACOS 超 2 倍或花两单成本没单 → 降 30%（KC-0029）。广告位：出单 ≥2、点击 ≥10、ACOS ≤ 目标 70% → 加 10 个点；有加价但 ACOS 超 1.5 倍（点击 ≥20）或花两单成本没单 → 减半。

### 每天的闭环（ERP 路线）

1. 北京时间 9 点，本机定时任务（不用 AI）：`daily_patrol_data.py` → `s5_daily_health.py`（昨日利润 + 产品健康灯）→ `s5_daily_plan.py`（领星拉 7 天、开新一轮、规则诊断、出报告）→ `feishu_push.py`（卡片带「💰 昨日利润」「产品健康」「📋 今日方案 N 条」）。
2. 用户看到红点回电脑说「看今天的广告方案」→ `s5_optimize.py status` 看到哪一步 → 助手补知识库 / SIF 依据、出报告 → 用户确认 → 写回 / 上传表 / 文案改稿。
3. 产品健康：保本 ACOS 是广告亏钱线、目标 ACOS 是方向；🟢🟡 产品本轮不收缩，只有 🔴 出降价 / 降预算；投入期最多 14 天。成本来自用户成本表（`s5_cost_table.py --set <站点> <表>`）。
