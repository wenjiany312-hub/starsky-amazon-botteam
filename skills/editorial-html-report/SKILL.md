# Editorial HTML Report Generator（v1.0）

把"AI 风的 Markdown"变成"杂志风的 HTML"。让人读完后觉得：**这是设计过的，不是转换过的**。

---

## 一、何时触发本 Skill

### 强触发场景（用户明说）
- "做一份漂亮的 HTML"
- "做精美一点的"
- "我要分享给团队 / 客户 / 老板的版本"
- "网页版 / Web 报告"
- "打印用的"
- "排版好看一点"

### 弱触发场景（应主动建议）
- 用户刚生成了一份长 Markdown 文档（解读、研究、复盘、分析）
- 用户提到要"对外分享"
- 内容是用来"汇报" / "演示" / "归档"的

### 不要触发的场景
- 用户只是要读懂一份文档 — 这种保留 Markdown 即可
- 用户要做交互式 Web App — 那是另一回事（用 `frontend-design` 或 React 类 Skill）
- 用户要做 PPT / Word — 用对应的专门 Skill

## 二、设计哲学

### 核心信念

> **"编辑/杂志风"不是装饰，是对内容的尊重。**
> 好的排版让读者愿意读到最后；坏的排版让读者第一屏就走。

### 三条美学红线

1. **意图性优于强度** — 大胆的极简和精致的极繁都行，关键是有意为之，不要"看起来都差不多"的中庸
2. **上下文特定的个性** — 每份报告都有自己的色系和视觉锚点，不要一套模板套天下
3. **变化是策略** — 不同主题用不同字体、不同强调色、不同布局节奏

### 必须避开的 AI Slop（详见 [references/anti-slop.md](references/anti-slop.md)）

- ❌ **字体**：Inter / Roboto / Arial / Helvetica / 系统字体
- ❌ **配色**：紫色渐变 + 白色背景（最常见的 AI 陈词滥调）
- ❌ **布局**：纯居中、所有内容都是同样的白卡片+阴影
- ❌ **动画**：旋转 / 弹跳 / 飞入等花哨动画
- ❌ **图标**：通用的圆形彩色 icon 堆

## 四、字体系统（必须用中文衬线打底）

一律用本地字体栈，**禁止引入任何在线字体（Google Fonts 等）**。模板已自包含（无外链字体/JS），断网与微信内可正常显示。

```css
:root {
  --serif: "Noto Serif SC","Source Han Serif SC","SimSun",serif;
  --sans: "Noto Sans SC","Microsoft YaHei","PingFang SC",sans-serif;
  --display: Georgia,"Times New Roman",serif;
}
```

**用法**：
- **正文**：`--serif`（中文衬线，权威感、阅读舒适）
- **标签 / 元信息**：`--sans`（无衬线，工业感、信息密度高）
- **大数字 / 章节编号**：`--display`（英文 display 衬线，戏剧感）

**字号节奏**（黄金比例）：
- 主标题：clamp(2rem, 4.8vw, 3.4rem) — 响应式
- 章节标题：2rem
- 章节大编号：4rem
- 正文：17px，行高 1.85
- 卡片内文：15-16px，行高 1.75
- 标签 / cite：11-13px

## 五、内容驱动的视觉决策

**核心思想**：不是"统一模板填内容"，而是"看内容是什么类型，决定用什么组件"。详细组件库见 [references/component-library.md](references/component-library.md)。

| 章节类型 | 推荐视觉组件 |
|:---|:---|
| **电梯演讲 / 摘要 / TL;DR** | 米色封套卡 + 角标"100 字"标签 + 重点词带下划色 |
| **作者画像 / 来源说明** | 双列定义列表 + 可信度标签（✓ 高 / ⚠ 提醒 / ✕ 警示） |
| **核心论点 / 议程** | 大编号卡片网格（hover 微抬升 + 金色边框） |
| **行动清单（分级）** | 4 档颜色边条（A 立即/B 准备/C 协作/D 反向 ❌）+ checkbox 视觉 |
| **趋势 / 信号 / 时间维度** | 短期红 / 中期橙 / 长期蓝 bucket + 内嵌"原话"引用块 |
| **时效性警告** | 黄色警告框 + → 列表 |
| **数据对比** | 见下方 §5.1 数据形态强制路由（不再三选一） |
| **术语表 / 词典** | 暗色表头斑马纹表格 + 行内代码样式 |
| **金句 / 关键引用** | 大字号衬线 + 金色超大引号 + 来源 meta + 上下文/价值小标签 |
| **按角色 / 情境引导** | persona 卡片网格（金色左边条 + 关键词 accent 色） |
| **推荐衔接 / 资源** | 简洁卡片（标签头 + ▸ 列表） |
| **附录 / 原文 / 详细数据** | `<details>` 可折叠面板（页码用 cite 标签） |
| **流程图 / 决策树** | Mermaid 嵌入（如复杂）或纯 CSS step cards（如简单） |
| **代码 / 命令** | JetBrains Mono 等宽 + 复制按钮 + 暗色或浅色 syntax |

### 5.1 数据形态强制路由（v3.2.0 新增）

**实测问题**：三份业务报告 HTML 全部 `<svg> = 0` —— 01 市场穿透 27 张表、06 词库 13 张表、S1 综合 35 张表，一张图没有。用户反馈"整个看板全是表格，可视化效果不好"。

根因是上表把「数据对比」写成了**三选一并列**（大数字 / 表格 / 条形图），模型永远选最省事的表格；而 `component-library.md` 里**图表组件数为 0**，Step 3 选组件时根本无图可选。

改为**按数据形态判定，命中即必须用对应组件**：

| 数据形态 | 判别特征 | **必须用** | 禁止 |
|:---|:---|:---|:---|
| **时间序列** | 月份/日期列且 ≥6 个点 | **内联 SVG 折线图**（组件 2.13） | ❌ 逐行长表 |
| **占比 / 集中度** | 百分比、Top-N 份额 | **CSS 条形图**（组件 2.14） | ❌ 只写数字 |
| **单指标横比** | 3–8 个对象比同一指标 | **CSS 条形图**，条长=数值 | ❌ 纯数字列 |
| **区间 / 阈值** | 有下限-上限或红线 | **区间条 + 阈值标线**（组件 2.15） | ❌ 只写"58-86天" |
| **关键结论数** | 单个决定性数字 | **大数字卡**（已有 2.1 变体） | ❌ 埋在单元格 |
| **时间线 / 节奏** | 有先后顺序的动作 | **横向时间轴**（组件 2.16） | ❌ 表格 |
| **多维明细** | 对象 ×5 列以上属性 | ✅ 表格是正确选择 | — |
| **长明细表** | 行数 **>50**（全量词表、竞品明细、SKU 清单） | **表格 + 工具条下载按钮**（组件 2.17） | ❌ 只给网页表无下载入口 |
| **高重复清单** | 某列取值**重复率 >80%**（品牌隔离词的「命中原因」「动作」） | **共性提 banner + 差异成网格**（组件 2.18） | ❌ 逐行重复同样的值 |

**下限（阶段/业务报告）**：`<svg>` ≥3、条形图 ≥4、大数字卡 ≥5。
**长表下限**：行数 >50 的表必须有 `<a download>` 下载按钮；多维标签必须分列，不得挤一列用逗号连接。
**重复列下限**：任一列重复率 >80% 时不得逐行显示 —— "这一列每行都一样"就是它不该逐行出现的信号。读者已在表头知道规则，重复 127 遍只制造视觉疲劳。
**`<svg>` 为 0 直接判不合格** —— 时间序列、占比、区间这三类数据存在时不出图，等于把可比较的信息降级成要读者心算的数字。这不是审美问题。

自检命令：

```bash
f=目标.html
echo "table:$(grep -o '<table' $f|wc -l)  svg:$(grep -o '<svg' $f|wc -l)  bar:$(grep -o 'bar-fill' $f|wc -l)"
```

不达标必须重生成，不得在报告里注明"可视化待优化"了事。


### 5.2 图表化后原表必须折叠或删除（v3.2.0 新增）

**实测问题**：加了 3 张 SVG 后，`<table>` 仍是 35、`<tr>` 仍是 309 —— 24 个月趋势的 26 行表格原封不动留在折线图旁边，同一份数据呈现两遍。**只做加法不做减法，表格墙依然存在。**

数据一旦被图表化，原表**必须二选一**：

| 场景 | 处理 | 写法 |
|---|---|---|
| 图已完整表达（趋势、占比、区间、时间线） | **删除原表** | 图下方一行文字给关键数值即可 |
| 读者可能需要逐值核对（月度原始销量、竞品明细） | **收进 `<details>` 折叠** | `<details><summary>查看原始数据（24 个月）</summary>…表格…</details>` |

**禁止**：图和平铺表格并列出现。这不是"更完整"，是让读者读两遍同样的数据。

```html
<figure class="chart-block">
  <figcaption>类目月度销量趋势</figcaption>
  <svg …>…</svg>
  <p class="chart-note">峰值 2024-08 指数 120.8；当前 2026-07 为未完月。</p>
</figure>
<details class="raw-data">
  <summary>查看原始数据（24 个月完整表）</summary>
  <table>…</table>
</details>
```

**自检加一条**：图表化改造后，`<tr>` 总数应**明显下降**（本例 309 行中，趋势表 26 行 + 时间窗表 5 行应转入折叠）。若 `<svg>` 增加而 `<tr>` 不变，说明只做了加法，判不合格。

## 六、必备结构元素

任何一份合格的 Editorial HTML Report 必须有：

1. **顶部进度条**（红色细线，跟随滚动）— 视觉锚点
2. **左侧固定 TOC**（sticky，scroll-spy 高亮当前章节）— 长文档导航
   - **侧栏抬头固定为「报告编号 · 报告名」**（如 `06 · 关键词库报告`）。**禁止**在此放作者名 / 公众号 / 知识星球等署名 —— 署名只属于封面 `作者` 行与页脚水印两处。实测出现过侧栏抬头被填成「坚哥 · 跨境者说干货」，读者失去"这是哪份报告"的定位。
3. **封面**（大标题 + 副标题 + 元信息网格）— 第一印象
4. **章节大编号 + 副线**（每章用 display 字体大编号）— 节奏感
5. **底部页脚**（来源、生成方式、免责声明）— 完整性
6. **沙龙页脚水印（强制，不得删改）**— 每份输出末尾必须保留：`<footer class="salon-footer">—— 由 Codex Skill「editorial-html-report」生成｜实战版｜作者坚哥｜跨境者说干货 · 星空的跨境圈子</footer>`（模板已内置）
7. **响应式**（< 980px 隐藏 TOC，简化布局）— 移动可读
8. **`@media print`**（打印优化）— 严肃内容常被打印
9. **`prefers-reduced-motion`**（辅助功能）— 尊重无障碍

## 七、工作流

### Step 1：判断输入
- 用户给的是 .md 文件？— Read 后分析章节结构
- 用户给的是对话中刚生成的内容？— 直接用
- 用户给的是 PDF / Word？— 先转 .md 再走本 Skill

### Step 2：分析内容选主题色
读完内容后回答：
- 主题倾向是什么？（财税 / 广告 / 品牌 / 风险 / 增长 / 教程）
- 严肃度多高？（越严肃，主色越深、强调越锐利）
- 是否需要金箔辅色？（专业、权威感 → 用金箔；活泼、年轻感 → 用糖果色辅）

### Step 3：分析章节用什么组件
**不要把每个章节都做成同样的卡片**。逐章节判断：
- 这一节是行动清单 → 用 4 档颜色边条
- 这一节是引用 / 金句 → 用大字号衬线 + 金引号
- 这一节是数据对比 → **先判数据形态**（§5.1）：时间序列出 SVG 折线、占比出条形图、区间出区间条、时间节点出时间轴；只有「对象×5列以上属性」才用表格
- 这一节是术语 → 用暗色表头表格
- 这一节是按 persona 给建议 → 用 persona 卡片网格
- 这一节是附录 / 长尾内容 → 用 `<details>` 折叠

### Step 4：基于 base 模板生成
从 [assets/template-base.html](assets/template-base.html) 复制，按步骤 2 替换主题色变量，按步骤 3 填入对应章节的组件 HTML。

### Step 5：落盘
- 文件名：`{原文件名}.html`（如 `Q3-市场分析报告.html`）或 `{话题}-{日期}.html`
- 位置：统一口径 **`{产品根}/{板块夹}/github-tabler-html-report/HTML/`**（目录不存在先创建）；用户明确指定其他目录时以用户为准
- 告知用户文件路径，提示可直接浏览器打开 / 分享 / 打印

## 八、不要做的事

详见 [references/anti-slop.md](references/anti-slop.md)。

简短版：

- ❌ 不要 Inter / Roboto / Arial — 是 AI slop 第一特征
- ❌ 不要紫色渐变背景 — 第二大 AI slop 特征
- ❌ 不要"所有章节都白卡片+中等阴影" — 显得偷懒
- ❌ 不要居中布局长文档 — 阅读疲劳
- ❌ 不要加无意义动画
- ❌ 不要外部 JS 框架（Bootstrap / jQuery / React 都不用）
- ❌ 不要忘记 `@media print` 和 `prefers-reduced-motion`
- ❌ 不要在不需要的时候插 emoji — 严肃内容用 emoji 减分
- ❌ 不要用 lorem ipsum / 占位文字 — 即使用户没给，宁可写"待补充"

## 实战版 · 编排契约

### 报告保真与 7·18 深度保护（强制）

运行前读取 `../../templates/report_depth_and_demo_policy.md`。Editorial HTML 的职责是完整呈现源报告，不是重新摘要。Markdown 中的正文、全部 SKU、全量关键表、公式、代码块、提示词、否定词复制区、字段映射、风险说明和 acceptance_checks 必须保留。
