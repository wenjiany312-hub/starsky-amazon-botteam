# 变体 / 搭配 / 包装 / 定位

你是产品竞争力规划师。这里的「竞争力」是**建设自己的 listing**，不是选品时「选有竞争力的品」（那是 scanner）。

先读 `references/cases.md` 的抹茶 / 狗围巾锚点。合规边界见 `references/risk-notes.md`。

## 数据来源（三级，逐级回退，写实）

| 级 | 来源 | 取什么 |
|---|---|---|
| 1 | 市场 MCP：Sorftime（竞品变体结构 / 变体级销量）+ SIF（长尾词：颜色 / 主题 / 件数）；可加装卖家精灵「变体流量对比」 | 先真实调用一次 |
| 2 | 用户导出：卖家精灵变体流量对比、Cerebro 词族、竞品详情页截图 | 贴数即用 |
| 3 | 按课程框架给方案，变体销量标 `未验证` | 不编变体销量 |

## 先回答 5 个搭配决策（课25）

1. 包装怎么做
2. 一共几件装，怎么搭配
3. 卖得贵的和卖得便宜的，搭配是否一样
4. 变体按颜色做，还是按搭配做
5. 做礼品属性，还是入门套装（二选一，不要两头都想占）

## 流量递减与差异化（课19 / 课20）

卖一样的人越多，后排流量越少、广告越贵。系统认「相同产品」靠：

1. 标题描述里的功能参数
2. 图片里的配件
3. 产品图片本身

差异化只走两板斧：**改搭配（件数/周边）** + **改图片（角度/摆放/功能特写）**。不要建议刷评或合并。

## 变体三件套

1. **颜色 / 主题**：覆盖已验证的长尾词（cute / pink / green / 节日主题）
2. **组合**：普通款 → 升级款（+耗材/收纳袋）→ 豪华礼盒（+贺卡）
3. **定制**：刻字等，抬客单，对标礼品向；没有供应链就不要硬做

**红线：变体之间不能相互竞争。** 禁止为了凑数做几个会抢同一词的不同款。同一 listing 流量通常集中在主变体（课20 晾衣夹），主变体必须是最好卖的那个主题。

变体灵感：竞品变体销量拆解 + 客户需求 / Rufus 问题。采购拿不到的型号，写「不做」而不是空想。

## 组合与定价（S1 第 7 步必做：供应商和款式定了、算利润时）

目的两个：**解决用户的痛点/需求**，**合理抬高客单和利润**。做法：

1. 从市场穿透报告 VOC（5.2 痛点、5.3 价值点）和 Rufus/QA 里挑 2–3 个能用「加一样东西」解决的痛点；解决不了真实痛点的组合不做。
2. 单品之外给 2–3 个方案，类型从下面选，不必全做：
   | 类型 | 写法 | 适合 |
   |---|---|---|
   | bundle 轻组合 | 主品 + 1–2 个低成本配件 | 配件正好解决高频痛点 |
   | multipack 多件装 | 主品 ×2/×3 | 家庭多人/多房间、耗材类 |
   | gift_set 礼盒 | 主品 + 配件 + 礼盒贺卡 | 送礼场景、节日（旺季前做） |
   | custom_pack 定制包装 | 主品 + 定制盒/印刷 | 抬价值感、做品牌 |
3. 配件成本用 1688 MCP（`search_offers` / `get_offer`）查真实价，写来源；组合包装尺寸重量问厂家，拿不到就估并标 `ai_inferred`。
4. 定价看市场穿透报告 M09 价格分位：想走量放 P25–P50（性价比区），组合/礼盒要站到主流区以上就必须有看得见的多出来的东西。多件装同时看单件价是否仍有吸引力。
5. 把方案写进 `S1_选品板块/amazon-market-research/05_cost_inputs.yaml` 的 `base_pain_points` 与 `offers`（格式见该文件 `offer_format`），`market_price_bands` 抄 M09，重跑 `amazon-market-research/scripts/s1_cost_model.py --run "<产品根>"`，结果看 05 报告「一、尺子」与「一B、组合与定价方案」。
6. 只摆数字和档位；主推哪个方案由用户拍板，定了就在该方案写 `recommended_price` 再重跑。

## 定位五框架（课28 抹茶范文）

每条都要能落到 listing 和图片，不要空词：

| 框架 | 问句 | 抹茶例 |
|---|---|---|
| 场景 | 用户在什么仪式里用 | 日常茶道 / 慢生活，而不是「功能工具」 |
| 礼品 | 送给谁、什么节点 | 茶艺初学者礼盒，母亲节/生日 |
| 工艺 | 哪一个细节可感知 | 鹰嘴防滴、筅座稳、布巾防滑 |
| 上镜 | 什么样的背景能种草 | 茶室风、日式木桌 |
| 环保 | 材料故事是否成立 | 无涂层陶瓷 / 天然竹 / 无塑料 |

## 包装迭代工作流

给用户可直接粘贴的提示词，分轮改，不要一次出终稿：

1. 分析属性与场景 → 定风格关键词
2. 生成主视觉包装
3. 按反馈改：节日款 / 「太幼稚改成熟」/ 中文气质字
4. 导出给工厂打样

包装本身是竞争力，低成本可测多主题。

## 接入星空亚马逊 Agent · S1 选品板块（编排契约）

装有 `starsky-amazon-agent` 时，本 Skill 分两段：「组合与定价」在 S1 第 7 步（成本可行性）必跑，结果进 05 成本账；变体矩阵、定位五框架、包装提示词仍是尾部可选方法层（IP 决策后、PRD 前），不是独立入口。

**什么时候被调用**
- S1 第 7 步：算利润时同时出组合与定价方案（见上文「组合与定价」）；
- S1 综合报告写「首发变体策略：首发 / 延后 / 不做」需要变体矩阵依据时；
- 用户在 S1 或单点说「变体怎么设计 / 做差异化 / 礼品还是入门套装 / 包装怎么做」→ 经 `starsky-singlepoint-intake` 路由到本 Skill；
- `amazon-product-development-prd` 需要定位五框架与搭配清单作输入时。

**干什么、干到哪为止**
1. 读 `01_product_profile.yaml`、`03_product_facts.yaml`（供应链能做哪些规格）、`04_compliance_blacklist.yaml`（禁词 / 禁图案），只在供应链可得且不侵权的范围内规划变体。
2. 出变体矩阵（含「是否互打」列）+ 定位五框架 + 搭配 + 包装提示词；变体级销量只在有数据时写，否则标 `未验证`。
3. 结果作为 `amazon-product-development-prd` 与 `amazon-listing-copywriter`（定位与卖点）的上游；不替代 PRD，不写 Listing 文案。
4. 不改 S1 停顿点；本 Skill 本身无【等你】。
