# S2竞品候选池 v0.1

只做候选建议，不代替S1难度，也不自动确认。现有R02分层、本品排除、独立父体、真实来源、本人确认和不足范围确认门禁不变。

1. 从S1产品事实和当前画像生成4–5个不同形态入口词，用户一次确认；画像词表按品类填写，不在代码内固化工具卷包词。自有品牌/父体、价格带和节点来源必须可追溯，未知留空。不会改S1竞品算法。
2. 宿主实际调用当前可用工具并原样保存响应，脚本不联网。默认5词×3页搜索+类目/本品2次+名称5次+新品1次约23次，依据工具计点、当前任务范围和有价值的补齐项收缩；不偷偷批量加调用。serp是月销量排序的**返回顺序**，不是自然搜索排名。
3. 每次调用追加现有调用口径清单：tool、arguments、response_path、channel、date及source_type（serp/bsr/name/new/seed/enrich/user_added）。种子、用户指定单品和新品也登记。价格直接USD，偏离10倍仅标警告，绝不缩放。
4. 执行 `competitor_candidate_pool.py --run 产品根 --profile 画像 --manifest 调用清单 --out 产品内输出目录`。只读登记响应；列出同目录未登记文件，绝不自动读它们补证据。输出enrich_todo只补非无关候选缺父体/节点的前60条（可配置），宿主按需要真实查询并追加enrich调用后再跑。退出2表示待补齐，3表示待判，1输入错误，0完整。
5. 全部规则确定性：统一大小写、标点、复数；形态与收纳词、完整入口词、结构差异、配件、替代、包含工具、自有家族、节点、相对价格、入口频次。规则顺序按本轮包；形态和包含工具矛盾归灰区。品牌型号里碰巧有roll不能单凭价格带变成同款：直接/同类都要求真正的形态上下文。上下文可以是前后相邻，或隔不超过2个画像声明/入口词里的连接词（如up、tool、storage），这避免把“Roll Up Tool Bag”漏掉，也不把“Stack-N-Roll Outdoor Gear Organizer”当卷包。
6. 六类 direct/variant/substitute/accessory/irrelevant/own_family；灰区待判。相关分基础6/4/2/1/0，自有不打分；+min(入口词数,3)，节点一致+.5，搜索与BSR兼有+.5，上限10，一位小数。版本0.1.0，改权重须升scorer_version。每族最多推荐1个，direct/variant最多20；不足如实报缺口，不用配件/替代补数。
7. 灰区宿主可交starsky-worker，只允许class五枚举和该行存在的feature_codes，备注≤30字；记录model、time、gray_todo_sha256。指纹不变复用；越界拒收保留待判。理由仍由规则拼装，模型备注不混入理由。
8. 直接使用脚本05A确认表，不另让模型重写候选顺序/理由。本人确认选项后，合并到现有candidate_review；新流程必须保留candidate_pool版本/路径/SHA。现有R02分层先由真实BSR/新品证据形成，再本人确认，不能用返回顺序伪造BSR。`竞品门禁_用户确认后.json`只是结果摘要，不是门禁输入。

产物：candidate_pool.json、candidate_review.draft.json、05A确认表、pool_summary.json，必要时补齐/灰区清单。理由对应响应路径和SHA，重复同输入、同输出目录逐字节稳定。原始响应、真实用户回执不打进插件；回归只用裁剪公开商品列的夹具。
