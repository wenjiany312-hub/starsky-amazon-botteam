# 运行与口径

## 首次接入

1. 复制 `config.template.yaml` 到发布包之外，填写非空 `store`、绝对 `workspace`，并在 `markets` 中逐站填写 `market`、IANA 时区、Ads 与 SP-API 配置的绝对路径；成本文件可选。
2. 通过 Codex 的工作区依赖工具取得 Node 和已安装 Data 插件的真实路径，分别填写 `node_executable`、`data_plugin`。运行 `python ops_console.py --config PATH prepare` 初始化 Data App，生成稳定项目标识并写回 `dashboard_project`。模板中的空路径不能启动 `serve`；缺少依赖时如实提示，不猜测路径、不替换受保护运行时。
3. 运行 `status`，分别确认广告域和销售/库存/Listing 域。配置存在只算待验证；目标域真实只读调用成功才算可用。
4. 运行 `collect`。异步广告报表未完成时保留 pending，本轮继续展示上次成功快照及其时间，不重复记成新数据。
5. 运行 `serve`，浏览器打开 `http://localhost:9766`。页面只展示本机已采集快照。

## 每日运行

按站点当地午夜结束一个自然日后运行 `scheduled-run`：US 的 America/Los_Angeles 日界对应北京时间夏令时 15:00、冬令时 16:00；UK 的 Europe/London 日界对应 07:00、08:00。09:00 汇总当时已完成的数据；同次运行可以对应不同站点日期。未完成的异步广告报告保持待续拉，不能因为跨日就宣称归因成熟。

在 Codex 当前任务创建跟进时，可安排北京时间 07:00、08:00、09:00、15:00、16:00 调用同一 `scheduled-run`，由 IANA 日界和本地采集状态去重。插件安装不会自行登记定时任务。计算机需开机且运行环境可用，错过时可手动执行续拉。今日 SKU 明细使用截至请求时点的销售；API 的整日桶标签不意味着当日已经结束。

广告报表使用明确的 7 天归因字段。最近一日可以展示为早期信号，但在归因成熟前降低结论强度。销售总额、广告归因销售额、订单和 purchases 保持原字段语义。

## 审核与导出

建议进入 `pending` 后由人批准或拒绝。批准记录绑定店铺、站点、来源、原生对象 ID、现值快照、规则版本和建议哈希。导出前人工核对当前对象、范围和现值；上下文变化、对象缺失或重复导出时停止并复核。

首版导出是候选交付，用户仍需在对应后台或既有 Bulk 流程中人工执行和核验。没有处理回执或新的只读快照，状态不得写成已生效。

## 看板范围

本地终端包含九页：店铺总览、出单明细、广告诊断、商品与文案、文案建议、库存补货、成本与收益、待审核、优化复盘。成本页消费每站 `cost_file`，按 SKU 和当日实际销售关联；成本不完整时显示覆盖率与缺口，不计算全店利润。计算口径见 [costs.md](costs.md)。

商品页选中 SKU 后显示五种文案字段、采集版本、关键词信号。亮点暂未取得时可点“录入商品亮点”填入当前内容；“保存到本地”后持续显示，可再修改或清空。该记录只写外置运营目录的 SQLite，接口采集与插件升级不覆盖；它与 Amazon 返回值分开标记。多个窗口同时修改时旧修订会被拒绝，刷新后再编辑。

广告方案为可讨论草案。实体分页未完整时，不能证明某精准词尚未投放；缺预算、竞价、库存或相关性确认时标明待补，不把草案当可直接开启的广告。分时调价、自动发现好词并自动投放，以及带限额的后台一键执行属于后续版本。

## 可选 MCP

```text
python ops_mcp.py --config PATH
```

该进程只提供：`ops_status` 查看来源状态和新鲜度，`ops_patrol` 读取已生成巡检摘要，`ops_report` 读取指定本地报告。三者不触发后台修改，也不替用户批准建议。配置路径与凭据继续保存在发布包之外；安装或运行该入口不得自动覆盖用户已有的 MCP 条目。
