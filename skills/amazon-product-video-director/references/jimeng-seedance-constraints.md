# 即梦 Seedance 2.0 平台约束速查（Amazon 产品视频专用）

> 本文件供 `amazon-product-video-director` 执行时引用，不单独触发。

## 输入限制

| 输入类型 | 数量上限 | 格式 | 大小 |
|:---|:---|:---|:---|
| 图片 | ≤ 9 张 | jpeg/png/webp 等 | 每张 < 30 MB |
| 视频 | ≤ 3 个 | mp4/mov | 每个 < 50 MB，2–15s |
| 音频 | ≤ 3 个 | mp3/wav | 每个 < 15 MB，≤ 15s |
| **总文件数** | **≤ 12 个** | — | — |

## 输出参数

- 单段生成时长：**4–15 秒**（可自由选择）
- 分辨率：480p–720p
- 自带音效/配乐

## Amazon 产品视频硬性约束

1. **禁止上传写实真人清晰可辨识面部**（手模、背影、虚化侧脸可接受；正脸特写会被拦截）
2. 每条 clip 优先 **1 张首帧垫图 + 最多 1 张结构锚点图**，避免多图导致产品变形
3. 动作段相机尽量 **静态或慢推/慢拉**，禁止 orbit / 环绕产品
4. 字幕、品牌 slogan、价格、排名声明 → **后期剪辑叠加**，不写进即梦 prompt
5. 产品外观以 **1688 垫图 / Listing 主图 / 结构真值表** 为唯一真值

## @ 引用语法（每条 clip 必须写清）

```
@图片1 作为首帧，产品外观细节参考 @图片2
场景参考 @图片3 的家居环境光线
0–3秒：慢推镜头，产品占画面中心 30%，手部从画面右侧入画轻触产品
3–6秒：固定机位，展示核心使用动作，产品结构保持不变
音效：轻柔环境白噪音 + 轻微产品交互声
风格：现代美式 DTC 产品广告，柔和自然光，电影级质感，浅景深
```

### 引用用途对照

| 用途 | 写法示例 |
|:---|:---|
| 首帧 | `@图片1 作为首帧` |
| 尾帧 | `@图片2 作为尾帧` |
| 产品外观 | `产品细节 100% 参考 @图片1，不得变形` |
| 结构锚点 | `产品结构锁定参考 @图片2` |
| 场景/背景 | `场景光线参考 @图片3` |
| 运镜 | `运镜参考 @视频1 的慢推效果`（少用） |

## 分段策略（防变形，强制）

| 总时长 | 推荐段数 | 每段时长 |
|:---|:---|:---|
| 15s | 3 段 | 5s |
| 30s | 5–6 段 | 5–6s |
| 45s | 7–8 段 | 5–7s |

**禁止**：一条 30s prompt + 8 张图一次性生成整片（产品极易变形）。

## 产品保真封印句（每段 prompt 末尾必加）

```
产品结构严格锁定，禁止变形、拉伸、增删部件、改变颜色材质比例；
不得添加未包含配件；不得出现品牌 Logo、价格、排名声明、竞品；
人物仅为模糊手模或背影，禁止清晰正脸。
```

## 电商产品展示常用运镜

| 术语 | 适用镜头 |
|:---|:---|
| 慢推 / 慢拉 | 产品全貌、收尾定格 |
| 固定机位 | 功能演示、结构展示 |
| 俯拍 | 平铺、配件摆放 |
| 极致特写 | 材质纹理（需结构已锁定） |
| 一镜到底 | 仅用于场景转场，产品段慎用 |

## 常见错误

1. 只写「参考 @图片1」不说参考什么 → 模型乱用
2. 同一段同时要求「固定镜头」和「环绕镜头」→ 指令冲突
3. 4s 内塞 3 个场景切换 → 物理不可行
4. 上传 5 张图但 @ 标注不全 → 素材浪费或误用
5. 用动态机械动作 + 无结构锚点 → 产品变形高发

# 工程化落地契约（2026-07-26 新增·即梦成为默认平台后补齐）

> 此前本文件只写平台参数与 Prompt 语法，缺少落地工程部分，是视频板块最薄弱的一环。
> 以下四节对齐 Grok 路径已有的工程化能力，使即梦可作为**默认平台**独立跑通。

## video_production_jimeng 目录契约

```
video_production_jimeng/
├── START.txt                   # 用户一句话触发说明
├── JIMENG_RUN.md               # 人工执行入口：逐段贴什么、点什么
├── image_manifest.yaml         # clip 清单 + 引用图编号 + risk + 路径
├── images/
│   └── clip_XX/
│       ├── 01_primary.jpg      # @图片1  主体保真基准（必有）
│       ├── 02_anchor_*.jpg     # @图片2  结构/细节锚点（high 段必有）
│       └── 03_scene_*.jpg      # @图片3  场景/氛围参考（可选）
├── prompts/
│   └── clip_XX.txt             # 中文 prompt + @图片N 引用 + 封印句
├── exports/                    # clip_XX_*.mp4（下载后回填）
└── concat_final.py             # 可选：本地拼接
```

**与 Grok 包的关键差异**：即梦是**网页人工操作为主**，没有官方批量 API。因此 `JIMENG_RUN.md` 必须写成**可照做的操作清单**（第几段、传哪几张图、贴哪段 prompt、选什么参数），而不是给 Agent 读的自动执行入口。

## 生成顺序（强制）

```text
1. 先出 clip_01（最能代表产品的一段）
   → 人工验保真：主体形状/颜色/材质/数量是否与 @图片1 一致
   → 不一致：改 prompt 或换 primary 图，不要继续往下跑
2. clip_01 通过后，再批量跑其余段
3. high risk 段（结构复杂/多部件/透明材质）单独跑，每段验完再下一段
4. 全部通过后统一下载到 exports/，按 clip_XX 命名回填
5. 回填后跑 14C 验收，再拼接
```

> **不要一次性把所有段都提交。** 第一段就变形的话，后面全是白跑 —— 即梦按次计费，且变形通常是 prompt 或 primary 图的系统性问题，一次暴露一次修。

## QA 清单（每段必过）

生成后逐条核，任一不过即重跑该段：

| # | 检查项 | 不过的典型表现 |
|---|---|---|
| 1 | **主体形状**与 @图片1 一致 | 罐体变胖/变高、盖子形状漂移 |
| 2 | **颜色/材质**未漂移 | 透明变磨砂、竹木变塑料 |
| 3 | **数量**未增减 | 3 个罐变成 4 个 |
| 4 | **结构件**位置正确 | 提钮位置偏移、分格数变化 |
| 5 | 无**多余物件**凭空出现 | 画面里多出未随附的配件 |
| 6 | 无**文字/logo**幻觉 | 罐身出现无意义字符或伪 logo |
| 7 | 首尾帧可**与相邻段衔接** | 拼接后跳变 |
| 8 | 画幅与用途匹配 | 主图视频要 9:16，SBV 要 16:9 |
| 9 | 未出现**人物面部特写**（除非有授权模特） | 合规风险 |
| 10 | 与 `04_compliance_blacklist.yaml` 无冲突 | 出现禁用元素 |

**第 1-5 项属于产品保真硬伤，不接受"差不多"。** 亚马逊主图视频里产品变形属于误导性描述。

## 批量与降级

| 场景 | 做法 |
|---|---|
| 段数 ≤ 5 | 网页逐段跑，人工验完再下一段 |
| 段数 > 5 | 分批：先跑全部 low risk 段，再逐个跑 high risk 段 |
| 无官方批量 API | **如实说明需人工操作**，不得声称可自动批量 |
| 生成额度不足 | 只出 prompt 包与操作清单，状态标 `prompt_only`，不谎称已出片 |
| 反复变形超过 3 次 | 停止重试，回到垫图层换 primary 图或简化分镜；继续烧次数无意义 |

## 与 Grok 路径的选型

| | 即梦 Seedance（默认） | Grok Imagine（备选） |
|---|---|---|
| 产品保真控制 | **强**（@图片引用 + 封印句） | 中 |
| 批量能力 | 弱（网页人工） | **强**（xAI API 可批量） |
| 适合 | **电商产品视频**（保真优先） | 大批量、对保真要求较低的素材 |
| 沙龙演示 | **默认走这条** | 仅用户显式指定 |

> 选型原则：**产品视频优先保真，不优先效率。** 变形的片子再多也不能用。
