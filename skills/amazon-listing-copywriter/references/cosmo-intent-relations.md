# COSMO 意图关系：文案审阅方法

[Amazon Science 对 COSMO 的说明](https://www.amazon.science/blog/building-commonsense-knowledge-graphs-to-aid-product-recommendation)介绍通过商品、用途、人群等常识关系帮助推荐。本项目据此采用明确表达使用意图的方法，不推断 Listing 字段权重、最低关系数量、固定重复次数或排名提升。

## 从属性走向购买判断

写作时按需要检查：

| 关系视角 | 审阅问题 | 需要的依据 |
|---|---|---|
| 产品身份 | 这是什么，与相邻产品有什么不同 | 当前 SKU 的产品类型与售卖范围 |
| 功能与用途 | 用来做什么，怎么做到 | 已确认结构/功能与必要测试 |
| 人群与对象 | 谁会用，处理什么对象 | 本品适用范围；不能从搜索词直接推定 |
| 场景与地点 | 何时何地使用，前提是什么 | 真实场景及产品条件 |
| 兼容与边界 | 能装/能配什么，哪些不适用 | 尺寸、型号、许可与确认清单 |
| 买家目标 | 这条信息帮助买家做什么判断 | 问题来源与支撑收益的事实 |

可将旧关系标签作为内部分析词典保留，但只记录本次有用、有证据的关系，不要求填满全部标签或达到固定覆盖数。

## 表达检查

先记录问题与 `fact_refs`，再写能支持的收益或条件。例如确认分格结构可解释分开放置，不能自然升级为防混味或防水。缺事实的“典型使用场景”仍是待核假设。

优先自然、具体、易懂的句子。可写“用途—事实—边界”，不强制每条出现 so/which means/for，也不强制同一核心词占据每个段落开头。

## 证据边界

- 意图关系解释产品信息，不替代材质、承重、静音、单手操作、认证或兼容测试。
- VOC 与购物助手问题说明关注点，不证明本品性能。
- 标题、五点和描述中的覆盖从实际英文计算；语义关系不等于原词出现。
- 研究结论与项目写法分开表述，不给“算法评分 100”“必收录”等结论。
