# 从买家问题写出有依据的文案

这是项目写作方法，不是 Amazon 排名公式。先遵循 `amazon-title-policy-2026.md` 的字段与事实规则，再用本方法组织表达。

## 1. 建立买家问题与事实对应

读取已确认产品事实、用户决定、词包、竞品和 VOC。每个拟写点记录：买家问题、问题来源、产品事实 ID、可表达的收益、适用边界、拟放字段。没有真实问题来源时可记录为编辑假设，不能冒称买家原话或高频痛点。

| 输入 | 能支持什么 | 不能自动支持什么 |
|---|---|---|
| 本品已验证/用户明确确认的规格、结构、附件 | 对应范围的产品陈述 | 更高等级性能或额外保证 |
| 当前本品图像 | 画面中可直接观察的形态 | 材质成分、承重、防水、认证 |
| 竞品标题/五点/评论 | 买家关注点、表达顺序、常见信息缺口 | 本品拥有同样功能、已解决竞品差评 |
| 搜索词/平台标签 | 搜索意图与市场信号 | 本 SKU 的适配或声明资格 |
| 场景库 | 已记录的人群、场景与问题 | 未经事实支持的新用途与效果 |

收益应能由 `fact_refs` 解释。例如已确认“附带两个独立盒子”可支持“分别收纳两类小物”；不因此写“防漏”“气密”“永不丢失”。收益存在额外测试条件时，留在审核区，并写明需要什么证据。

## 2. 有样本时做针对性竞品分析

继承确认竞品池，不重复扩池。按当前产品需要检查身份、关键规格、使用方法、适配边界、附件、保养和痛点等维度；记录实际取到的 ASIN、日期、字段和缺失。

比较“竞品写了什么、证据是什么、本品是否有资格回应、放哪里更清楚”。有问题才批判，有可借鉴处才记录；不强制每个竞品凑一条缺点或填满固定维度表。样本不足时照常输出有依据的本品草稿并说明对比较结论的限制。

## 3. 先判产品资格，再分用途与优先级

每条词保留产品词根、主分类（产品词/属性词/其他）、多标签（功能、规格、材质、场景、人群、兼容、痛点）与产品匹配（direct/adjacent/mismatch/unknown）。主分类去重统计，多标签不能相加冒充唯一词数。既有 D1–D6 保留供兼容使用。

- 产品匹配和声明许可通过后，才比较同源、同语义、可比时间窗的需求与竞争信号。
- L1/L2/L3 是编辑优先级，不是上架或广告授权。核心概念自然部署在最有帮助的位置，不要求每条 Bullet 前 80 字符重复 L1。
- 待证/禁用功能词保留研究记录和理由，退出当前可用文案与默认广告池。品牌隔离不等于全账户否定。
- 已确认自有品牌可保留在标题；兼容词按具体许可和商品证据处理，不能从销量推导兼容。

## 4. 组织每个字段

Title 先让人识别产品，Highlights 补充关键事实。每条 Bullet 围绕一个购买判断，可用“收益/结论 → 支持事实 → 场景或适配边界”组织，不强制每句采用同一种连接词。

写完朗读检查：是否像自然回答、信息是否重复、数字和单位是否清楚、每个效果能否指出依据。美国站根据买家理解需要采用合适单位；换算保留原值与精度，不制造测量精度。

长描述按实际使用过程、规格、售卖范围与边界分段；不用内部免责声明补长度。A+ 或 Q&A 在被要求时扩展已证实信息。事实不足以支撑五个不同卖点时，保留固定 B1–B5 槽位，说明缺失或写简短事实，不虚构性能和场景凑数。

## 5. 记录真实覆盖和修改

`keyword_ids` 表示写作意图，实际覆盖必须从最终英文另算，分为原词出现、词形/分词覆盖、语义关联、未覆盖。语义相关不标 exact；未完整出现不承诺收录。

逐字段记录英文、中文、买家问题、事实/VOC引用、待核项和审核状态。基线存在时逐字段记录前后内容与迁移理由；用户只改一处时保留其他字段及人工备注。最终版、HTML、Markdown、覆盖账本必须对应同一输入指纹。

## 人工审核重点

- 买家能否读懂“是什么、给谁、怎么用、解决什么、凭什么、哪里不适用”。
- 每项声明是否仍在事实和 S1/企业限制范围内。
- 中英文是否同义，英文是否可独立复制。
- 未覆盖词和缺失事实是否说明影响；更长、更多卡片或更高重复率都不作为质量证据。
