# Listing 字段规则与政策来源

本文件集中管理字段规则；写作方法与报告结构分别见同目录的 `competitive-copy-methodology.md`、`listing-report-contract.md`。本轮规则依据 2026-09-12 项目资料审阅记录，适用范围需写入 `policy_profile`。遇到站点、类目或后台规则变化时核对当前官方字段，不把旧配置推广到全部商品。

## 字段口径

| 字段 | 当前口径 | 写作与审阅 |
|---|---|---|
| Title | 本轮 US 非媒体类 ≤75 字符，含空格；项目目标68–75 | 已确认自有品牌 + 产品类型 + 首要差异/规格；品牌未知不虚构，正文预留 brand_reserve（12 字符：品牌名＋空格），即正文目标56–63 |
| Item Highlights | 同范围 ≤125 字符，含空格；项目目标110–125，标题校验通过才可就绪 | 用短句或短语补充有依据的事实；3–5 项为组织建议，事实数量不足不凑项 |
| B1–B5 | 每条 ≤500 字符的保守项目上限 | R02项目目标200–250字符；结构、尺寸用法、材质、场景人群、礼品各一条，不是平台最低长度；先确保自然、具体、不重复 |
| Description | 以实际后台字段规则为准 | R02项目目标1200–1500纯文本字符，同时给≤2000字符HTML表示；只用p/br/b/ul/li且无属性，不宣称后台标签支持 |
| Search Terms | 项目采用 ≤249 UTF-8 字节保守上限，含空格；写作目标 230–249 字节 | 空格分隔、词去重、去禁用品牌；优先前台未用的新合格词；不足时按用户授权自动复用已批准核心词，必要时有界重复，保留质量警告和来源，不宣称算法增益 |
| Q&A | R02五条五个不同意图，按Alexa for Shopping（前身 Rufus）表达 | 只写能由本品事实回答的候选问答，来源与审核单独保存 |

字符数从最终英文计算；ST 从最终 UTF-8 编码计算。Description 展示英文纯文本字符数与可选 HTML 源码字符数，两者不混作一种口径。媒体类或其他站点规则未知时可出按已知上限约束的待核草稿，报告标明适用性未确认，不能称为平台合规通过。

## 标题与亮点的分工

- 产品身份和最重要的差异优先。保留已确认自有品牌；标题68–75为项目质量目标，缺事实时明确缺口；不设品牌一律禁入或颜色一律移走的规则。同一个有意义词最多2次；无全大写、促销语或禁用特殊字符。
- 规格、颜色、适配对象是否留在标题，取决于识别当前 SKU 的价值和实际政策/事实。兼容品牌按 S1 具体证据与允许用途复核；竞品品牌不能作为自有品牌或普通 SEO 词。
- Highlights 承接重要增量信息，避免机械重复标题。标题和亮点均可作为搜索输入，不据此推断固定权重或“200 字符总收录预算”。
- 改写旧标题时保存基线、原/新计数、保留项、迁移字段、排除理由；高价值词失去覆盖时说明去向或未覆盖原因。

## 事实与格式

页面/图片标注规格（如材质、尺寸、插袋数）可带真实来源进入草稿，样品核对记在审阅区；承重、防水、耐磨、防刺穿、单手操作、静音、全适配、认证、质保与比较效果必须有对应测试/证据。疑问句、竞品描述、示意图和 VOC 都不能自动证明这些性能。

英文消费者字段不含中文译文或审核标签；中文翻译忠于英文。待核项放在 `review_metadata`，不能塞进 Description 的末段充当内部免责声明。

报告使用的段落、粗体与 CSS 只服务本地审阅。Amazon 后台标签能力未确认时以纯文本为导出默认；需要源码视图时标明其用途，不称报告 HTML 可直接上传。

- [不支持的 HTML 标签说明](https://sellercentral.amazon.com/seller-forums/discussions/t/d2712113d23ba4ccaede5a1bfd81f945)：报告排版与后台标签支持分开核对。

R02数值以运行时 `validate_listing_copy.listing_rules()` 的同一有效快照计算和展示，H批次接入统一登记表。不要在报告模板另写一套常量。项目目标不足保持质量缺口，不编造事实或用无关词凑数。ST优先排除全部前台字段（含描述、属性、QA）已出现的词；不足时自动取既有研究/CT许可词，再用已批准核心词回退至230–249字节，必要时有界重复。不得添加品牌/禁用/假规格/错形态词；没有安全核心才给出明确失败。
