# 出图文档规范（v1.0 · 2026-08-11）

⛔ **一个板块一份文档，所有信息在里面，不许散落。**

套图先回答买家：这是什么、干什么、解决什么问题、功能/材质哪些能看见。
高级 A+ 每组必须 Desktop 1464×600 + Mobile 600×450，手机端单独构图。
尺寸沿用 Skill 原表：主图 1600×1600，副图 1600×2000。

实测痛点：提示词、垫图选择、图上文案、后台关键词分散在方案 md、manifest、
overlay_tasks、聊天记录里 —— 到了网页端出图时要翻四五个地方，回来上传后台
又要再翻一遍。

## 四、后台关键词怎么挑（⛔ 不许现编；⛔ 不画进图）

必须从 `S2_文案板块/{关键词Skill}/keyword_package.yaml` 或关键词库报告里选。这栏给 Amazon 后台「图片关键词 / Alt Text」上传框，**不要**写进 ChatGPT 生图 Prompt 的画面要求里。

满足：

1. 每张 **5–10 个英文短语**，逗号分隔
2. 只描述**图上真实可见**或产品资料可证实的内容
3. 每张至少 **2 个是本图独有**的画面/功能短语，⛔ 整套不许复制同一组词
4. ⛔ 禁止：竞品品牌、促销词、绝对化词、airline approved、与图片无关的高流量词
5. 附中文核对行 + 来源映射（哪些来自可见画面、哪些来自词库）
6. 章节标题必须写成：`后台图片关键词（Amazon 上传用，不生成到画面上）`

## 四点五、网页端张数（2026-09-09 实测：只出 6 张）

ChatGPT Images 网页端常在第 5/6 张停住。出图文档必须把张数写死，否则少图会被当成完成。

主副图文档开头固定写：

```text
HARD COUNT: generate exactly 7 images — IMG01 + IMG02 + IMG03 + IMG04 + IMG05 + IMG06 + IMG07.
Do not stop at 6. If only 6 exist, immediately create the missing IMG07.
```

高级 A+ 文档开头固定写，并强制两批发：

```text
HARD COUNT: generate exactly 10 images — M1D M1M M2D M2M M3D M3M M4D M4M M5D M5M.
Do not stop at 5. Do not stop at 6. Do not crop Desktop to make Mobile.
BATCH 1: five Desktop 1464x600. BATCH 2 immediately after: five Mobile 600x450, new compositions.
```

文末必须有核对照片 ID 清单。少一张就不算完成。

## 六、⛔ 与 overlay_tasks.yaml 的关系

本文档是**给人看的**；`overlay_tasks.yaml` 是**给渲染器读的**。
两者的「图上文字」必须一致 —— 文档改了文案，`overlay_tasks.yaml` 也要同步改，
否则成图上的字和文档对不上。

⛔ 不要把文档当成第二个真源：**渲染器只认 `overlay_tasks.yaml`**。
