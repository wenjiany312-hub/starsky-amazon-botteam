# 选品证据方法论（amazon-selection-squad-method）

> 标【默认值】的阈值是工程默认，不是原文事实；跑 1–2 个真实品类后由复盘分析师校准，写回 selection_kb。

## 一、六条原则（全队通用）
1. **边界**：每个角色只对一份交付物负责；两个角色的产出能用同一句话描述，就是重叠，交给运营总监合并
2. **单一背景卡**：背景写成文件、不写在对话里。开工第一句是「读背景卡」，不是「你再说一遍」
3. **三层证据不混层**：观察（对手的页面事实）→ 证据（买家的带分母原声）→ 决策（我方动作）。下一层只引用上一层的结论和定位，不重跑上一层的采集；竞品表里不写「我们该做什么」，评论表里不写「建议改高度」
4. **分母纪律**：任何「很多 / 普遍 / 严重」都要写成 `X/N（X/N%）`，并写样本口径（变体范围 · 时间窗 · 去重规则）。写不出分母的，降级为「待验证线索」
5. **动作阶梯**：改信息表达（几乎零成本、可逆）< 改组合（中成本）< 改产品（开模、不可逆）；默认从最低一级开始排除，低一级被证明无效才升级。「暂不改」是正经选项
6. **最小盯盘**：监控只盯「能推翻现有结论的最小字段集」；没变化就沉默

## 二、背景卡（运营总监每个批次写一份）
位置：`{{WORK}}/products/_batches/<批次>/00_背景卡.md`。所有角色开工先读它，不再口头交代。
```
批次 / 站点：
品类方向 / 目标售价带：
参考 ASIN（有就写，不是我方在售）：
我方条件：目标成本 / 供应链能力 / 工艺限制 / 履约方式（未知写「未知」）
已排除方向：
输出位置：{{WORK}}/products/<SKU 短号>/S1_选品板块/
已挂载工具（实际 tools/list，不是「已安装」三个字）：
已挂载技能：
```

## 三、S1 竞品观察：先找对对手，再看差异（选品侦察员）
1. 用参考 ASIN（或候选品的头部 ASIN）**反查核心搜索词**
2. 按搜索词找**流量重叠**的 ASIN，组成 10–20 个候选池（上限，不是指标；10 个说得清就不扩）
3. **归并父子变体**：同款不同色、不同包装不是不同对手
4. 五维打分选出 1–2 个对标 ASIN【默认值】：

| 维度 | 权重 | 5 分的样子 |
|---|---|---|
| 流量重叠度 | 30% | 共享 ≥3 个核心词且都在首页 |
| 价格带契合 | 20% | 落在目标售价带内，评论量证明这个价位能成交 |
| 变体配比可比 | 20% | 件数 / 尺寸组合清晰、能复制 |
| 卖点结构可借鉴 | 15% | 五点覆盖买家最在意的 3 个场景，有参数支撑 |
| 生命周期 | 15% | 成长期（还在涨、已过验证期） |

   - 总分 ≥4.0 且流量重叠 ≥4 才进对标池；**总分 <3.5 的即使是类目第一也不对标**（流量结构不同，学不了）
   - 对标池全是衰退期老链接：说明这个价位带已被占满，回 S2 看需求侧有没有没被满足的场景，不硬挑「最强对手」
5. 拆对标 ASIN：套装件数与尺寸配比、长宽高、每件折算价、价格区间、五点主打场景、父子变体关系；每条承诺标「页面宣称 / 有参数支撑 / 待实测」
6. 交《竞品观察表》，必须回答三问：**按什么比例配套装？承诺了什么？主打哪些场景？**

## 四、S2 需求证据（VOC）：把评论变成分母（选品侦察员，闸门 1 批准后）
1. 先写样本口径：变体范围、留评时间窗、去重规则、有效样本 N（卖家精灵 MCP 拉评论，**按页翻完**，每页条数和总条数都记下来；拉不到写「页面信号」）
   - 单个对标 ASIN 文字评论不足 100 条：把 1–2 个对标 ASIN 和流量重叠池里同款型的 2–3 个 ASIN 合成一个样本池，**分 ASIN 列出各自 N**，合并 N ≥100 才按下面的分档下结论；合并后还不足 100，结论一律降级为「线索」
   - 「评分数（ratings）」≠「文字评论数（reviews）」，分母只用实际拿到正文的条数
   - **采样上限（卖家精灵评论接口每页最多 20 条、每页约扣 1 次额度；2026-11-11 实测 1129 条要翻 57 页）**：每个 ASIN 最多取 **300 条正文（约 15 页）**，按接口默认顺序从新到旧取，样本口径里写清实际时间窗；一个 SKU 的样本池合计最多 **600 条（约 30 页）**；一个批次评论分析合计最多 **70 页**，超了先问运营总监
   - 卖家精灵评论没有评论 ID：原声定位写「ASIN + 作者 + 日期」，去重用 ASIN + 作者 + 日期 + 正文，样本口径里注明「弱去重」
2. 按 8 族打标（人群、场景、功能、质量、服务、体验、市场、情感），每族 2–3 个二级维度，按品类自定，凑成约 22 维
3. 统计频次：`严重度 = 提及条数 / 有效样本 N`【默认分档】

| 分档 | 占比 | 处置 |
|---|---|---|
| 系统性 | ≥15% | 真实产品或页面问题，S3 必判 |
| 局部 | 5%–15% | 先查是不是集中在某一个变体或场景 |
| 长尾 | <5% | 默认不改产品，先查是不是页面预期问题 |
| 单条 | 1/N | 只当线索，不能作为动作依据 |

4. **正反同呈**：每条痛点配一组「负面原声 vs 正面原声」，说明是不是同一个属性（例：「正好放进书桌抽屉」vs「放不进梳妆台抽屉」——盒子没变，是抽屉变了）
5. 原声必须可定位（变体 / 时间 / 评论 ID），不改写数值、不脑补尺寸
6. 区分属性：真实使用缺陷 / 购买尺寸不符 / 页面预期误差
7. **三口径分离**：评论提及率 ≠ 客服工单率 ≠ 退货率。没有后台数据只能说第一个
8. 交《需求证据表》

## 五、S3 产品机会判断：四选一（选品侦察员出初判，财务管家、仓管物流补代价）
每个核心问题走判定树，**每一步写「为什么不是上一级」**：
```
Q1 痛点真实存在吗（≥5% 且有原声）？ 否 → 【暂不改】，记为线索
Q2 满意同一属性的买家 ≥ 痛点 3 倍吗？ 是 → 预期错配，倾向【改信息表达】
Q3 能用主图 / 五点 / A+ / Q&A / 场景对照图在下单前劝退错配买家吗？ 能 → 【改信息表达】
Q4 痛点集中在配比 / 组合（某尺寸用不上、某尺寸不够）？ 是 → 【改组合】
Q5 现有供给确实没解决，且我方供应链能覆盖新增成本和模具？ 是 → 【改产品】
其余 → 【暂不改】，预算留给下一个品
```
- 「没查到供给」≠「市场空白」；不把单条差评翻译成新功能
- 每项判断写六件套：人群与场景 / 痛点与现有供给对照 / 动作类别与改进假设 / 正反证据 / 我方条件匹配度与新增代价（钱和天数）/ 下一步验证清单（含继续条件和放弃条件）
- 排除理由模板：选【A】因为……；不选【B】【C】【D】各因为……
- **【改产品】一律不自己推进**：交运营总监发老板决策卡（开模、改结构属于资金和不可逆决定）
- 交《产品机会判断》

## 六、最小盯盘（复盘分析师，上架后对 2–5 个对标 ASIN）
- 每周一次（建议周二上午 10 点，Grok Routine），只看三个字段：**价格变动是否超过 10%**、**主图和五点是否新增功能或尺寸声明**、**在售变体有没有增减**
- 分级【默认值】：L0 没变化 → 只写日志、不打扰；L1 价格 ≤10% 或五点措辞微调 → 记入周报；L2 价格 >10%、新增功能 / 尺寸声明、变体增减 → 发简报（新旧快照 + 差异点）给运营总监，判断现有结论是否失效
- 上线前先问：「如果它一个月都没报警，我会不会觉得白花钱？」会 → 字段选错或阈值太松

## 七、四句验收问句（运营总监验收任何交付都问）
1. 这个结论的分母是多少？样本口径写一下：变体范围、时间窗、去重规则
2. 相反方向的证据有几条？列出来，并说明和这条痛点是不是同一件事
3. 这条是页面宣称、有参数支撑，还是待实测？
4. 如果这个判断是错的，会是哪种情况？需要什么证据才能推翻它？
答不上来就退回重做。

## 八、卖家精灵 MCP 能力位
接入后以 `tools/list` 实际返回为准，第一次接入由运营总监把工具清单写进背景卡；各角色按清单调用，不自己猜工具名。
| 能力位 | 谁用 |
|---|---|
| Listing 详情 | 选品侦察员、文案算法师、复盘分析师 |
| 关键词反查（找流量重叠） | 选品侦察员、文案算法师、广告优化师 |
| 评论样本 | 选品侦察员 |
| 类目 / 市场数据 | 选品侦察员 |

**成本**：采集一次、复用多次。S2 的评论样本落盘，S3 只读文件不重爬；候选池不超过 20；盯盘只采三个字段。
