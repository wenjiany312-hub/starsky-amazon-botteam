## 核心心智：精铺不是精品，也不是铺货

| 模式 | 目标 | 特征 |
|------|------|------|
| 精品 | 一个爆款吃3-5年 | 大量广告+持续优化，门槛高 |
| 铺货 | 海量SKU碰概率 | 人力密集，库容压力大 |
| **精铺** | **低竞争产品，少量广告，2-3个月回本盈利** | **在卷之前先赚一波，不奢望单品长期** |

**精铺核心逻辑**：把"和一万个对手竞争"缩小到"只和几个对手竞争"。

## 选品三要素模型（所有方法的底层框架）

无论用哪种选品方法，最终都要回答三个问题：

| 要素 | 核心问题 | 精铺好入口 | 精铺坏入口 |
|------|---------|-----------|-----------|
| **人群** | 谁在用？谁买？照顾谁？ | 消防员、新手妈妈、卡车司机、住校生、空巢夫妻 | for men、for women、for kids（太泛） |
| **场景** | 在什么环境/节点/状态下用？ | 毕业典礼、婚礼当天、冬季修车、露营夜间 | daily use、home、outdoor（太泛） |
| **需求/痛点** | 解决什么问题？ | 防漏、防尴尬、稳定固定、降低焦虑 | 好看、方便、多功能（太泛） |

**不需要三者都强，只要从其中一个切进去即可。**

### 三要素底层原则
- "适合所有人，等于没有人群"
- "我看得懂的产品我都不要" — 看得懂=大多数卖家也看得懂=容易卷
- 看不懂的产品=专业场景专用需求=做的人少=竞争低

## 重点方法实操流程

### 方法1：人群选品法 🔥（最高优先级）

**核心理念**：从"适合所有人"切到"具体人群"。

**人群来源四方向**：
1. **职业**：医生/护士/消防员/电工/卡车司机/动物园饲养员
2. **身份阶段**：新手爸妈/住校生/空巢夫妻/远程办公人群
3. **兴趣圈层**：高尔夫/露营/钓鱼/宠物/烘焙
4. **照顾对象**：照顾小孩/老人/术后恢复者/宠物

**实操步骤**：
```
STEP 1：用大模型拆人群
Prompt："请按职业、身份阶段、生活变化、健康状态、兴趣圈层等维度，
列出100个具体人群"

STEP 2：在卖家精灵关键词选品中搜索人群词
如：firefighter, nurse, new mom, truck driver
不要过早加销量过滤，先看结果池

STEP 3：精准度验证
前10个产品中≥7个是同一种产品 → 关键词精准，可深入
结果很杂 → 关键词太泛，Pass

STEP 4：看不懂的优先研究
看得懂的产品 → 你也看得懂别人也看得懂 → 易卷
看不懂的产品 → 专业场景专用需求 → 竞争低

STEP 5：数据验证（用SIF MCP或其他工具）
搜索量、竞争密度、头部评论数、广告依赖度
新品机会：是否有365天内新品打入前排
```

**⚠️ 注意**：人群词只是入口，最终产品词不一定含人群词。

---

### 方法2：ABA关键词排名趋势选品法

**核心逻辑**：ABA排名爬升=需求在增长

**实操步骤**：
```
STEP 1：在亚马逊品牌分析中，输入关键词并细化
STEP 2：下载不同时间段数据报告（对比季度/年度变化）
STEP 3：关注三个信号：ABA排名大幅上升、点击份额增长、转化份额增长
STEP 4：发现新增属性词
  如：car repair kit → winter car repair kit（+雪铲）
  属性词=细分场景入口
```

---

### 方法3：痛点配件选品法 🔥

**核心逻辑**：主体产品竞争太大精铺打不起 → 不做主体，改做它的**配件、补偿件、改良件**

**实操步骤**：
```
STEP 1：锁定一个高需求但竞争激烈的主体产品
STEP 2：反问"这么多人买，使用中有什么新痛点？"
STEP 3：下载评论（1-3星差评）
STEP 4：AI分析差评，整理痛点+解决方案
STEP 5：围绕痛点开发配件产品
```

**庭院遮阳伞案例**：
- 主体（遮阳伞）：品牌集中、评论高→不适合精铺
- 配件方向：
  - 底座（原有支撑不稳、不抗风）
  - 收纳绑带（收伞后固定）
  - 桌面孔堵头（遮阳伞收走后桌面留孔洞）

**⚠️ 区分**：
- 痛点配件法：围绕主体产品自身问题，**往深处挖**
- 关联产品法：看买这个的人还顺手买什么，**往宽处挖**

### 方法4：关联产品选品法

**三种找法**：
```
方法①：Bought Together 数据
在亚马逊产品页找"Frequently Bought Together"
或用特殊URL查看关联购买

方法②：Rufus AI提问
"买这个产品的人还会买什么？"
"这个场景下还需要什么产品？"

方法③：品牌分析→购物篮分析
查看类目关联购买数据
```

### 方法5：站内反馈/Rufus选品法

**Rufus反向提问方向**：
- 同场景可延展产品："除了这个产品，这个场景下还需要哪些产品？"
- 买的原因："为什么客户买这个产品而不是别的？"
- 需求→产品词："某个需求对应的产品关键词是什么？"
- 需求评估："这个需求是小众还是值得做？多大？"
- 场景反推："给出一个场景，让Rufus反推需要准备哪些产品"

**三方向评论挖掘**：
1. **评论痛点挖掘** — 差评→痛点→解决方案
2. **QA板块挖掘** — 用户高频问题→未满足的需求
3. **Rufus选品** — 如上所述

### 方法6：组合选品法 🔥🔥

**核心区分**：

| | 显性组合（不推荐） | 隐性组合（推荐） |
|---|---|---|
| 本质 | 把相关产品放一起 | 给用户一个解决方案 |
| 特点 | 需求容易看见、差异化弱 | 解决痛点/缓解尴尬/降低焦虑 |
| 例子 | 洗车套装、露营大套装 | 女性外出应急包、婚礼焦虑包 |
| 问题 | 所有人都看得见、容易复制 | 需要深度洞察 |

**隐性组合判断标准**：
- ✅ 该产品是场景下必须的吗？
- ✅ 能否解决用户痛点？
- ✅ 能否降低尴尬或焦虑？
- ✅ 是否围绕同一个场景闭环？
- ❌ 如果子产品可有可无，**不要加**

**找组合产品三方法**：
```
方法①：从情绪和痛点找场景
  "面试前担心突发状况""婚礼当天担心尴尬""外出时担心形象问题"
  → 再根据场景拆产品

方法②：大模型辅助拆场景
  Prompt："某产品解决女性外出头发乱、形象不佳的焦虑，
  请推荐更多类似场景，需要用组合产品解决用户情绪或痛点"

方法③：用Kit关键词找
  - 在卖家精灵关键词选品中搜索"kit"
  - set更多偏显性，kit更容易找到隐性组合
  - 案例：酸面团入门套件、寿司制作套件、蜡烛制作套件、拉链修理包
```

### 方法7：节日选品法

**核心前提**：**必须提前半年布局！**

**时间线**（以圣诞节为例）：
```
1-3月  → 选品
5-7月  → 推链接
8-9月  → 备货
11-12月 → 销量高峰
```

**数据选择**：
- ❌ 看当年数据：节日还没到/数据出来时已错过窗口
- ✅ 看**上一年同期**数据

### 方法8：类目节点选品法

**最笨但最有效的方法**：
```
前提：有2万+类目节点数据
STEP 1：优先看自己熟悉或感兴趣的大类
STEP 2：从大类下的子类目一个个点进去看
STEP 3：不只看BS榜和新品榜，按子类目从头看到尾
STEP 4：记录平时想不到的产品
```

## 选品验证清单

找到候选产品后，必须验证以下维度（按重要性排序）：

### 数据维度
- [ ] 搜索量是否稳定/增长？（用 SIF `market_get_keyword_demand`）
- [ ] 竞争密度如何？头部评论数？（用 SIF `market_get_keyword_competition`）
- [ ] 广告依赖度？广告关键词数量？
- [ ] 365天内是否有新品进入前排？（重要正信号）
- [ ] 售价区间和利润空间？

### 风险维度（必须排查）
- [ ] **侵权/专利**：用瑞关、智慧芽等工具排查
- [ ] **认证要求**：后台合规检测、问平台客服、问3-5家认证服务商交叉验证
- [ ] **供应链可行性**：供应商容不容易找到？
- [ ] **生命周期**：需求是短期还是长期？

### 竞争维度
- [ ] 前10条是否≥7条是同一种产品（精准度）
- [ ] 是否有品牌垄断？
- [ ] 评论门槛是否可跨越？
- [ ] 广告竞争是否激烈？

### 精铺适配度
- [ ] 是否能切到具体人群/场景/需求？
- [ ] 是否能快速盈利（2-3个月）？
- [ ] 是否适合少量广告启动？

## 关键金句

> 适合所有人，等于没有人群。

> 人群越具体，需求越容易被挖出来。

> 我看得懂的产品我都不要。

> 看不懂的产品，做的人就少。

> 精铺不是指望一个产品吃一辈子，而是要在卷之前赚一波。

> 组合产品不是堆东西，而是解决痛点。

> 显性组合是把东西放一起，隐性组合是给用户一个解决方案。

> 任何一个子产品，如果在场景里可有可无，就不要加。

> 开发新品之前，先把老品拓展开。

> 选品没有捷径，要大量看类目，把三要素融入到日常分析中。

## 快速使用指南

### 收到"帮我选品"任务时：
```
1. 确定切入点：人群？场景？需求/痛点？

3. 用选品验证清单逐项核查
4. 输出结论：优先推进 / 保留观察 / 暂不建议
```

## 接入星空亚马逊 Agent · S1 选品板块（编排契约）

装有 `starsky-amazon-agent` 时，本 Skill 是 **S1 的灵感与方法层**，不是独立终点：

**什么时候被调用**
- S1 新手快速选品卡里用户选了 **E 精铺选品**；
- 或用户在任意启动语里说「精铺 / 精铺选品 / 低竞争选品」→ 路由到 S1 并以本 Skill 开场。

**干什么、干到哪为止**
1. 按用户给的切入点（人群/场景/痛点，没给就先问一句选哪个）跑 1–3 种方法，产出**产品灵感池**（10–20 个方向，用 output-templates 的模板）。
2. 用三要素模型初筛出 Top 3–5，写明每个方向的入口逻辑与精铺适配度。
3. **【等你】用户选定 1–3 个方向后停**，把方向作为输入交给 `amazon-market-research` 做 MCP 数据验证（搜索量/竞争密度/新品信号按其取数下限执行）。
