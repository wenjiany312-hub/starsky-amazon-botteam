阶段验收通过且范围包含下一阶段时给可复制口令，用户新开窗口接着跑。本窗口不得自行 `init` 下一阶段。

S5 另开窗口。第 1 步必须先跑接入闸门（领星 / 文件投喂状态）；详见 `_s5_ops_contract/S5_CONTRACT.md`。 <!--basic-->

## 三张卡，各只出一次

| 卡 | 何时出 | 次数 |
|---|---|---|
| 环境检查卡 | 本窗口选定板块后、第一条业务回复前 | 每个窗口 1 次 |
| 路线图卡 | 进入本阶段第一条业务回复（或用户问「到哪了」） | 每个阶段窗口 1 次；问进度可重出，只标当前位置 |
| 步骤卡 | 每个子步骤结束 | **第 N 步整窗只出 1 张** |

禁止：把第 1 步到当前步整段重贴；用「已续跑到第 N 步」散文代替步骤卡；只写在推理过程里。  
同一回合连跑多步，每步都要留卡片记录，可明确合并显示（如「2/9 + 3/9」）；不得静默跳步，已展示历史卡不重贴。

S4 第 1 步印的「七步表」= 本阶段路线图，不是每一步都再印一遍九步表。之后每步只出统一步骤卡。

## 步骤卡 V3

格式只按 `templates/chat_card_style.md` V3：普通 Markdown 短行，目标 ≤10 行，不包代码块、不用 HTML 折叠。必有阶段与 N/M 步骤标题、🎯 结论、🤖 模型、👉 下一步；业务数字和实际 Skill / MCP / 知识库 / 工具 / 报告有内容才加，无用户动作不加 🙋 行。

五类执行明细只从本步回执读取，不用配置或记忆补写。模型仅写宿主官方全称与档位（R04例外：仅导航悬浮窗/导航页去掉GPT-/Claude厂商前缀，版本和系列保留；对话与报告不变），本步和下一步同一行；下一步取 N+1。机检字段留在 `运行数据/流程控制/<阶段>/receipts/`，ack 与测试读取回执，不要求从聊天读旧八字段。

验收未过用 ⚠️，列出未通过数量和最先补的最多 3 项，下一步写补齐数据。只有 `stage_acceptance.<阶段>.status = accepted` 才显示阶段完成和下一阶段口令。卡前最多一句说明，卡后不引用规则原文；未变化的已批准事项无需重新审批，业务输入、合规和授权门禁继续执行。

步数：S1=9 · S2=7 · S3=13 · S4=7（上线后的优化进 S5）· S5 运营=5（取数 → 诊断 → 报告审批 → 落地 → 收尾；进场先选路线：手动报表 / 领星 / 赛狐）；复盘口令另走契约复盘轨，不占巡检步数。

## 阶段口令（换窗用）

| 已完成 | 文件 | 下一窗 |
|---|---|---|
| S1 可行性报告 + HTML | `_NEXT_S1到S2.md` | 文案（词库 + Listing） |
| S2 词库/场景/Listing HTML | `_NEXT_S2到S3.md` | 视觉 |
| S3 主副图 + A+ + 视频（或用户明确跳过视频） | `_NEXT_S3到S4.md` | 新品广告课堂 |
| S4收尾（方案已批准、Seller SKU已确认、正式表原生校验通过） | `_NEXT_S4到S5.md` | 运营 / 领星 |

阶段报告落地后保存交接证据；只有验收通过且范围包含下一阶段时 `emit-transfer` 并显示口令。换窗操作随口令简短说明：

1. 同一产品项目 **新开 Codex 窗口**
2. 按宿主模型选择器查看简短建议，保留用户当前选择
3. **整段复制** ```text``` 口令粘进去

验收失败、partial、Hold、已授权后补照常保留内部交接证据和限制，不自动显示进下一阶段口令；卡上给两条路：补齐数据后重新验收，或用户回「继续 下一阶段」由 `continue-next` 生成带缺口交接口令、新开窗口承接（S1–S4 均适用；S1 侵权红灯、S2 合规 needs_changes 仍阻断）。

### 用户随时要口令

用户说「生成交接口令 / 要进 S2 / 要进 S3 / 要进 S4 / 要做新品广告」时：

- 本阶段验收通过且报告已落地 → `emit-transfer`（已有 `_NEXT_` 先核对当前范围与证据）
- 报告未落地 → 先按顺序正式完成剩余步骤，不得让用户自己编口令，也不得另写报告代替
- 已正式交付但验收未过（S1–S4）→ 用户要进下一阶段时走 `continue-next`（带缺口交接口令）

同窗禁止 `init` 下一阶段。

## S3 必须守住的体验

1. **挑垫图**：先看完全部 1688/实拍，尺寸图 / 套杆图必须占位。见 `_visual_suite_contract/SUITE_CONTRACT.md`。
2. **网页端投喂**：只给人两个扁平夹 `GPT网页端投喂_主副图/`、`GPT网页端投喂_A+/`（MD + 已编号垫图）。
3. **图要解决问题**：每张图回答一个买家问题（是什么、怎么用、材质结构、痛点），对准本站审美；不编未核实规格。
4. **视频二选一或跳过**（第 9 步必须停，等编号）：
   - `1` = 三段短视频（约 5 秒 × 3，可后拼）
   - `2` = 一段约 10 秒整片（Listing 主图视频位，课堂建议）
   - `3` = 先不做视频，直接出 S3→S4 口令  
   平台默认即梦；不要把「默认 15 秒 / 3 段」当成已选。
5. 主副图 / A+ / 视频任一段用户说「先跳过」，记 `deferred` 并携带限制；整体阶段验收通过后允许换窗进 S4。
