# 品牌旗舰店设计与优化方法（适用所有站点）

美国、英国、欧洲、日本站同一套方法：模块逻辑、版式、验收规则一样，只有语言与用词随站点变（如英国 colour、garden、cotton buds）。
来源：AkoSlale 美国站旗舰店优化复盘与英国站改版实跑（2026-09），以及 Amazon Ads 官方 Stores 规格、建店指南、移动端指南。案例经验不能覆盖官方要求。

## 三种入口

| 入口 | 必做 | 可跳过 |
|---|---|---|
| 从 0 建店 new_store | 品牌备案资格、商品矩阵、页面命名与导航、基础素材、后台模块能力 | 旧店诊断 |
| 已有店改版 redesign | 现店盘点（逐页：保留 / 调整 / 新增 / 移除）、停售与缺失子体、已有认可资产 | 已验证有效的品牌资产不重建 |
| 局部优化 partial | 只动用户点名的页或模块，其余锁定 | 全店重排 |

以整个品牌产品组合为单位，不把某一个产品的 S3 完成当作全店完成。

## 十步执行顺序

1. 确认范围：站点、品牌、入口、要解决的问题。
2. 熟悉真实产品与店铺：商品矩阵（子 ASIN、系列、款式、长期主推、当前在售状态、证据）；改版先盘点旧页面、模块、链接。
3. 先学规则与后台能力：官方模块、内容规则，加上当前账户实际可见的模块、必填字段、尺寸、链接选项。
4. 规划购物路径：首页负责品牌与分流，品类页负责选款与购买；每页写「买家进来要解决什么」。
5. 建立模块映射：页面 → 区块 → 后台模块 → 图片 → 原生字段 → 链接 → 验证状态。后台做不出的自由排版（三等宽卡片、筛选）只能叫概念预览。
6. 先做一个代表样块，在后台实测：模块、字段、链接、电脑、手机都核过，认可后再复制同类。
7. 分批产出、局部修改：复用已认可的图，缺哪块补哪块；同一场景图在首页和品类页复用（创意母版），不重复出图。
8. 交付可照做的上传包：每块写清后台模块路径、上传哪张图、复制哪些字段、链接到哪、双端核验。
9. 逐页验收：实际双端预览、ASIN 与显示卡片数、链接、旧内容清理；用户认可后按授权提交审核、上线。
10. 上线后复盘：保存改版前后日期与数据口径；访问与订单变化结合库存、价格、流量看，不单归功于装修。

## 已被认可的首页入口版式

- 后台模块：带文本的图片 → 叠加文本；中号、左对齐、右上角；前缀、正文留空；链接样式选按钮，按钮标题 Shop now。
- 图片：左约 70% 真实产品场景，右约 30% 浅色文字区，放一两句辅助文案（图内文字）。标题和按钮由后台原生显示，不画进图。
- 案例实测尺寸：美国 3000×1280、英国约 1920×820。不是所有模块的通用标准，以当前后台提示为准。
- 首页每条产品线只保留品类名、一句用途、一个入口；尺寸、颜色、套装差异放品类页。

## 文字分工

- 默认用后台原生字段（可访问、可检索）；图内文字只放辅助说明，并记录为什么放、手机上能否读清。
- 图中文字不能再写一遍后台标题；价格、评价、折扣、库存交给原生商品模块，不烘焙进图。

## 链接与商品

- 按钮文案必须与实际跳转一致：写 Explore / 系列入口就链接店铺页面；只能链单品时按钮改成 Shop now 之类的单品说法。未创建的页面不编 URL。
- 商品网格 4 件及以上才用、每页至多一个；少于 4 件用商品模块逐个放。
- 粘贴 ASIN 后逐个对照显示的卡片数；少显示先查可购性和身份，不为凑整齐删商品。
- 长期主推与当前可购分开：缺货的主力保留位置，购买与投放资格另验；停售款从入口、图文、视频、商品模块一起移出（不等于删除 Listing）。

## 手机端

- 桌面认可不能代替手机验收：标题字号、图内小字、裁切、按钮都要在真实手机预览看。
- 支持独立手机图的模块单独出手机图；页头左右各 15% 可能被裁，关键内容放中间安全区，Logo 可能盖住左侧约 900px。

## 状态分开记

事实就绪 → 模块已实测 → 设计已认可 → 上传图齐 → 后台双端预览 → 已提交审核 → 上线已核。任何时候不用一个「完成」代替全部。

## 反例（都已写进脚本检查或验收）

- 本地 HTML 很漂亮但后台做不出 → 未实测的模块标概念预览。
- 图中标题与后台必填标题重复 → 报错。
- CTA 写系列却链接单品 → 报错。
- 商品网格少于 4 件 / 一页两个网格 → 提示或报错。
- 停售款还挂在店里 → 报错。
- 手机字小或过大 → 未做手机验收的图文块逐一提示。
- 用户说当前效果 OK → 锁定该版本，不为几像素反复重绘；改动记进修改记录。
