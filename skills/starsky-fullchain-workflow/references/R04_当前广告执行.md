# R04 当前 S4 广告执行

新案例优先于历史九步、独立架构审核和缺SKU时出DEMO的说明；旧案例按原编号继续，不把旧第六步映射成新SKU步。步骤、产物、停顿、模型只读当前路线图，不另写一张执行表。

## 七步与三个停顿

1. 读现有S1成本、S2小索引、最终文案、S3图片清单及00C，保存上游接入回执；不问一次已有答案。
2. 按本地 KC-0113 六问判断产品，优先已确认且来源未变化的类目打法，否则 KC-0114 通用母版。没有知识库MCP也照常读取内置知识卡。
3. 只问日预算、目标ACoS（对照保本）、损失上限、测试期、单次最高出价与进攻/控成本；用户要逐词定价/不投或按金额分活动预算时一并写进参数。保存本人原话和当前参数指纹（`03_盘子参数.json` + `03_盘子本人确认.json`），随即按第4条登记机会词并 `prepare`。首次停顿。
4. 原生词包许可和最终文案共同筛词，图片承接另查实际图位；不以埋词候选清单冒充最终文案。探测当前会话可用的SIF/Sorftime/卖家精灵/西柚，至少有一家可用就实际检索当前类目长尾/季节机会；保存完整响应及当前任务、工具、SHA回执。用 `s4_launch.py opportunities --source <实际调用与候选记录>` 登记，脚本不假装调用MCP。可用但失败如实显示，只有确实未接源才写“未补机会词：未接数据源”。候选不自动获得广告许可；需要S2核对时只留候选，不私改词包。当前建议竞价用响应JSONPointer绑定；没有当前响应时用有日期的S2 CPC。
5. 第3步定盘子后用 `s4_launch.py prepare`（`--strategy`、`--package`、`--parameters`、`--decision` 四个参数缺一不可）调现有广告编译器生成方案与原生报告；方案只能由 prepare 产出，不另做简报工作稿、不直接调编译器，否则 approve 当场拒绝。第5步第一屏是打法、花多少、每单赚亏、一件决策。用户一次批准当前方案，`approve` 生成架构审核记录；这是第二次停顿，不再另问研究批准/架构批准/出表批准。
6. 没有SKU则保存上架前方案，停在此处。列全部实际颜色/变体，每行选择本次投/不投、Seller SKU、可选ASIN；复述对应关系，本人明确确认后 `sku` 才原生出表及独立校验（`--mapping` 写行列表或 `{rows:[…]}`，`--decision` 的 mapping_hash 按行列表算）。用户只想先看表时，可用本人确认的临时 Seller SKU 走同一命令，交付写明上传前替换。第三次停顿内部可以填写后核对，不新增一次方案审核。拒绝货号、ASIN、DEMO、空值、重复及未确认的可疑格式。默认暂停状态，资格未知不宣称已可投。只补SKU不得改变活动/预算/词/出价。
7. 四步上传指引和正常 `_NEXT_S4到S5.md`。不加第四个确认；不上后台。沿用S5手动路线入口 `S5_运营板块/_投喂_广告报表/`，下载批量表后说“优化广告”。

## 续跑与调用

“填 SKU”“继续 S4”先读当前状态、方案审核和内容指纹；已批准且未变就进入第六步，不重跑1–5。方案内容变了回第5步，用户盘子变了回第3步。第三方数据、知识卡、文案或价格变化时如实提示影响范围，不复用过期批准。

脚本以当前宿主安装记录的Python调用 `<home>/scripts/s4_launch.py`，动作 `intake / prepare / opportunities / report / approve / sku / import-playbook`。`prepare` 的参数与确认文件来自当前用户消息，不能由模型补造本人原话；`sku` 绑定实际映射和本人确认。所有可读产物路径由路线图 `artifact_paths` 唯一定义。机检日志放阶段总览，不堆在主目录。

“导入类目打法”“把这份资料作为类目打法”沿用00C资料登记和category-adapter：原始文件只读、保留SHA，先从资料生成类目画像初稿，再由本人确认用途生效。不把类目卡示例当事实；类目/站点或来源变化则回通用母版。结构与预算必须实际采用已确认卡，不只改报告标签；费用和承受力仍以本品当前成本为准。

新版SP允许账户资格未知时制作上架前暂停方案（规划状态单独标识），不写成“账户资格可用”；明确不具备资格仍拦。SB/SD维持原资格和素材门槛。平台是否接受、可售状态、券资格仍须上传前核实。

报告只一份当前版，旧版归历史。起始按市场建议价、固定竞价、第三天无曝光+15%到上限；保本只算赚亏止损。市场价高于承受力则给封顶亏损/改善利润/低价慢跑三选一，按本人选择调整，不能暗自压价或加预算。引用 KC-0053/0105/0146，并区分官方与经验卡。报告和卡片用共用可见术语扫描；来源字段只在末尾证据节出现。
