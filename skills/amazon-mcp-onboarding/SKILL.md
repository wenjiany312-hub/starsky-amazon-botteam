# MCP 接入与分配（运营总监专用）

目录和默认分配在 `{{KIT}}/mcp/third_party.yaml`；分配表 `{{WORK}}/config/mcp_assignment.yaml` 不存在就从 `{{KIT}}/config/mcp_assignment.yaml` 复制一份再改（`{{KIT}}` 下的文件升级时会被替换，不要写在那里）；结果写到 `{{WORK}}/config/mcp_assignment.yaml` 和 `{{WORK}}/team.md`。

## 一、识别
1. 读老板给的文件。格式不限：清单、配置片段（JSON / TOML / YAML）、服务商后台截图都可以
2. 按 `third_party.yaml` 里每个服务的 `aliases`（别名）和 `url_hints`（网址特征）认出是哪家。认不出的，单独列出来问老板「这是哪家的服务、给谁用」
3. 每个服务记下：名称、接入方式（远程网址 / 本地命令）、地址、认证方式（Key、Token、OAuth 登录）、文件里**有没有密钥**

## 二、密钥（红线，先做这一步）
- **任何回复、文件、日志里都不能出现密钥的原文**，提到时只写「已提供（末 4 位 xxxx）」
- 老板的文件里**带了密钥**：
  - Grok Bot：用平台的安全方式保存（安全密钥卡 / Vault / 连接器的密钥框），**不写进 `{{WORK}}/` 下的任何文件**；接完后提醒老板「清单文件里有密钥，建议删掉这个文件」，老板同意后由你删除
  - OpenBot / StarSky：写进团队包的 `mcp/.env`（不分享、不提交），或者平台「应用 / 插件」页的密钥框
- 文件里**没带密钥**：接入时用安全填写框请老板填，**不要**让老板把密钥贴进聊天。老板已经贴进来的，提醒他去服务商后台重新生成一个

## 三、匹配角色
1. 默认按 `third_party.yaml` 的 `roles`；老板在清单里写了「给谁用」的，按老板写的
2. 发一张**确认卡**给老板（一张表就够）：

| 服务 | 认出来是 | 有没有密钥 | 分配给 | 备注 |
|---|---|---|---|---|
| SIF | ✅ | 已提供（末 4 位 a1b2） | 选品侦察员、文案算法师、广告优化师 | |
| 西柚 | ✅ | 待填 | 选品侦察员、文案算法师、广告优化师 | |
| ??? | ❌ 认不出 | — | — | 请告诉我这是哪家 |

最后一行写回复示例：「确认」，或者「确认，另外给风控官加上 Sorftime，把西柚从广告优化师去掉」

3. 老板以后随时可以说「给 XX 加上 YY」「把 YY 从 XX 去掉」，你改分配表并通知相关角色

## 四、接入（按平台）
| 平台 | 怎么接 | 分配怎么生效 |
|---|---|---|
| Grok Bot | 远程服务（https 网址）：在对话里「添加自定义 MCP 服务器」，名称 + 网址，要密钥的放在请求头里；本地命令启动的服务：「按命令添加」，密钥放环境变量。都会弹确认，老板点 Add it；要 OAuth 的会出连接卡。加完在 Settings → Plugins → Yours 能看到 | 连接器是**账户共享**的，所有 Bot 都看得到。分配靠规则：每个角色只用分配表里给它的 MCP（软约束），你在派单时写明可用的 MCP |
| OpenBot | 「你的应用」里添加；你出一份清单，老板照着点 | 「你的技能 / 你的应用」页每个助手单独开关：你给老板一张「助手 × MCP」开关表 |
| StarSky（DSH） | 「连接插件」里添加 | 以 StarSky 设置为准 |

### 本地 MCP（团队包自带：1688_scraper + 3 个知识库）
| 平台 | 怎么接 |
|---|---|
| Grok Bot | 云电脑连不到老板电脑上的 MCP，所以**装在云电脑上**：运行 `bash {{KIT}}/mcp/local/install_grokbot.sh`，按它最后打印的 4 条命令，用「添加自定义 MCP 服务器（by command）」逐个注册，名称必须是 `1688_scraper`、`selection_knowledge_base`、`ads_knowledge_base`、`promotion_knowledge_base`（星空技能按这些名字找）。建议老板打开 Settings → Computer → Route traffic through this computer，让 1688 看到老板电脑的 IP |
| OpenBot / StarSky | 老板电脑上已经装好的就直接用；没装的按 `mcp/local/1688/★先读我.md` 装 |

体检：1688 做到第 ② 层（`ping` 通、列出 5 个工具）就算接好；第 ④ 层要真实打开 1688，等到第一次找货时再做，需要登录就请老板接管。知识库第 ④ 层：查 1 次「新品期 出价」。

## 五、四层体检（每个服务都要做）
| 层 | 通过的证据 | 还不能说明 |
|---|---|---|
| ① 已配置 | 配置条目存在，密钥字段非空 | 连不连得上 |
| ② 可连接 | 能列出这个服务的工具，初始化成功 | 账号有没有认证、有没有额度 |
| ③ 已认证 | 一次只读请求成功，或身份检查通过 | 所有接口和站点都有权限 |
| ④ 实际可调用 | 按 `verify` 做一次**最小范围**的真实查询，拿到真实数据 | 整个选品或广告流程都没问题 |

- 第 ④ 层会消耗服务点数：**只查 1 个对象**（老板自己的 ASIN、类目或关键词），计费不明时先问老板
- 只读：不调用任何写接口，不批量抓取
- 失败按这个顺序排查，并把原文报错给老板：密钥为空或填错 → 401/403（密钥值、字段名、服务是否启用）→ 点数不足或套餐到期 → 超时、连接拒绝、代理 → 配置格式错误
- 体检结果写进 `{{WORK}}/config/mcp_assignment.yaml` 的 `connected`：服务、状态（①–④ 到了第几层）、检查时间、用的工具名

## 六、收尾
1. 写 `{{WORK}}/config/mcp_assignment.yaml` 的 `assignment` 和 `connected`
2. 更新 `{{WORK}}/team.md` 的「数据工具」一节
3. 通知每个角色：「你可以用的 MCP：A、B；没接上的：C（用页面信号或老板导出的文件代替）」
4. 给老板一张交付卡：接上了哪些、各到第几层、分配结果、还缺什么、下一步

## 七、不要做
1. ❌ 在任何地方写出密钥原文，或者让老板把密钥贴进聊天
2. ❌ 用模型猜的数据冒充 MCP 返回的数据；没调通就写「未接入」
3. ❌ 体检时批量查询、调用写接口
4. ❌ 把认不出的服务硬套到某一家
