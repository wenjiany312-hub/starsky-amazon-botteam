# R03 产品说明书：S3 的共同事实入口

第 2 步盘点所有图片和视频（包括补充图片/自拍、厂家）；对每个视频运行 `scripts/video_keyframes.py sheet`，必须实际查看带秒数的全部对照表，不能只读文件名或首帧。第 3 步按关键秒数 `export` 导出真实状态帧。工具报解码依赖缺失时如实补依赖或列缺口，不假报看过。

依 `templates/product_manual_schema.yaml` 整理事实后运行 `scripts/product_manual.py <产品根> build --input <结构化资料>`。复杂度自动按有无开合、安装、连接判断，用户可明确更正。L0 只交紧凑身份卡和场景；L1 以上逐项说明结构位置、活动方式、真实状态、动作方向与易错点；L2/L3 增加安装、工具耗时、连接和指示状态。

用户本人 → 厂家 → 1688 → 竞品使用参照 → 一般经验。优先级用于排查来源，不用于擅自抹平冲突。折法/卷法、插袋数、实际装载状态等矛盾逐项列出。没有真实画面的状态写待补，和素材/视频共用 `00_产品资料/拍摄清单.md`；不把假设放进产品操作画面。

把说明书 HTML 确认页交给用户，第 3 步暂停一次。用户明确确认并给出冲突处理后，用 `confirm --input` 记录 `decision: {source: user, message: 原话}` 与 `resolutions: {冲突ID: 具体处理}`。一般“继续”不解决来源冲突。确认记录绑定内容和来源指纹，不代替用户原话或实际观察。

视觉总规划、垫图、提示词、A+、视频、结构验收统一用 `product_manual.read_confirmed` 取事实；要使用某个状态/动作时传 required_states/required_actions，待补即拒绝该用途。产品使用说明书改变后重验下游，不拿旧批准套新图。

第 11 步可给用户一行 S2 Q&A 改进建议，只引用已证实的用法；不自动改写 S2 成品。业务运行发现工具缺陷先诊断并给选项，不在产品目录自写绕门禁脚本。
