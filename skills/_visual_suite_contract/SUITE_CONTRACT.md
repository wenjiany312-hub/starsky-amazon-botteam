# 本品转化套图契约（2026-09-09）

主副图、高级 A+、普通 A+ 共用。视频不走本契约，继续用 `amazon-product-video-director`。

## R03：产品认知共同入口（覆盖旧版仅凭静态垫图的做法）

先按 [产品使用说明书规范](references/产品使用说明书规范.md) 看完素材和视频对照表、生成并确认 `00_产品资料/产品使用说明书.md/html`。主副图、A+、视频仍用各自现有实现，但产品结构/状态/动作统一读取该说明书；缺画面保持待补。S3 新案十三步，第 11 步交付核心视觉，品牌故事/旗舰店在 12/13 按需做。旧案保留原步骤编号。

素材盘点/总规划用本契约 `scripts/visual_suite.py`：`<产品根> inventory --input <扫描设置>` 全量图片/视频分类，标签至少含装载效果/使用场景/结构/细节/尺寸规格/包装/工厂/重复中适用项，并写价值与风险；未实际查看的素材仍标待查看。补图路径为 `00_产品资料/补充图片/{自拍,厂家}/`，用户说“已补图”就重扫，内容未变的标签保留，同画面优先自拍。

第 5 步 `plan --input <visual_suite配置>` 交 HTML 确认页，不让用户翻 YAML：IMG01–07 每图解决不同买家问题，所有颜色共用同一任务表；高级 A+ 默认 7 个模块，最少 5 个，每模块桌面/手机各一张，替代历史 R8 固定 5 模块 10 张要求。主图白底无字。视频形态不在此问，品牌两项在核心交付后按需做。明确确认后 `confirm --input <用户决定>` 绑定当前说明书与素材指纹，以及规划的画面内容（图位任务、图上文案、垫图、结构、颜色）；只改技术字段不需要重新确认，画面内容变了才重新确认。只差尺码的变体（如 绿色L / 绿色XL）写规划时自动合并成一个颜色，共用一套图，尺码差异放在尺码图里；不同颜色才各出一套。素材或事实变化先重验，所有下游通过 `load_plan` 读取。

## R03 提示词与投喂

原有 `scripts/pack_gpt_web_feeds.py <产品根>` 自动识别 R03 `visual_suite.yaml`，重验说明书/规划、词库许可、结构 ID 和三层合规后打包。关键词分两种，不要混用：`keyword_embed` 是画进图上文案的词（可选，0–3 个；第 5 步写规划时自动从文案里已有的许可词预选，缺了只记提示，不拦打包；只有许可被撤销的词仍留在图上才拦）；“后台图片关键词”是上传 Amazon 时填的检索词，不画进图。词库只做限定 SKU/可写权限的限量读取，数量冲突和禁止事实不写。道具可以出现，但必须明示 Tools not included；垫图不意味着把原图直接贴进版式。主图白底无字，其他图文案直接生成；叠字仅用户明确要求时用。`提示词.txt` 和 `投喂说明.md` 分开，后者不粘进生成提示词。默认 B 同一个对话生成一整套，A 只作少量返修；回填仍要实测尺寸、OCR、结构与合规。

## R03 验收与交付（当前规则）

默认高级 A+；资格未核实只提示“提交前在 A+ Content Manager 确认”，不得自动降为普通 A+。普通 A+ 仅用户明确选择时做，按其模块尺寸验收。默认 7 个高级 A+ 模块、最少 5 个，实际 N 个模块 × 桌面/手机 = 2N 张；手机独立构图。

回填用现有 `scripts/视觉生产包.py <产品根> prepare --kind listing|aplus`，输出可看的验收页，实际查看候选图后 `accept --input <复核回执>`；`check` 重验整套。默认目录为 `出图_主副图`、`出图_高级A+`（按需 `出图_普通A+`），各自包含 `01_投喂包`、`02_回填/放这里`、`02_回填/最终版/_历史版本`、`03_返修包`。原始下载保留，不要求用户改名；有歧义才给对应文件和选择项。后处理、文案、三层合规、结构、道具声明、变体颜色全部验收后才算最终版。低置信度 OCR 先复核，不算通过，也不直接占一次返修。写实 AI 人物/手标记在尺寸、裁切、命名后最后写入并读回；真实拍摄按来源核对。每图位最多返修两次，不影响其他已验收图片。

第 11 步运行 `python <home>/scripts/s3_stage_report.py <产品根>` 生成当前 MD/HTML 报告；不是拼长文凑体积。报告显示真实数量、缺口、人物标记、视频待补及对 S4 的影响；建议补进 Q&A 的问题只提示，不自动改 S2。必需项通过后正常换新会话进 S4；品牌故事和旗舰店是最后两步，有需要再做、不做标“未做”。等待用户出图回填是正常等待，不是失败或再次授权。

以下保留的是旧版流程与 R8 实测历史；其中固定 5 模块 10 张、无资质自动降级、逐图新对话、默认叠字、旧扁平投喂目录及旧步骤号不再约束 R03 新案。旧案按原路线继续；不在案例里改已安装插件或绕过验收。

## 一句话

用本品垫图锁死产品样子，按这个站点的买家问题和关键词，**一次出齐一整套销售图**。不要默认识竞品图，不要一张一张写互不相干的 Prompt。

## 硬锁

1. **本品样子只认垫图。** 外观、形状、尺寸、结构、颜色一律不准改。垫图来自 1688 / 实拍 / 用户放入的本品原图。
2. **AI 不准出门找竞品图。** 禁止自动抓 BSR、新品榜、确认池 ASIN 的主副图当审美老师。禁止把 `amazon-visual-benchmark-learner` 当 S3 默认第 2/3 步。
3. **竞品图只当出图方案老师，而且必须人投喂。** 只有用户把参考图放到 `S3_视觉板块/_投喂_风格参考/` 时才许学：图位节奏、场景怎么融、字多密、整体气质。不准学竞品外形，不准当本品垫图，不准抄商标和版式。没有这个文件夹就跳过学习。
4. **未核实规格不准编，但垫图里已有的卖点图必须用。** 航空认证、承重承诺、面料商品名、防水、认证标等 `null/deferred` 项保持空，不准为了凑套图去编。反过来：1688/实拍里已经存在的**尺寸图、行李箱套杆、开口、网窗、车载、内部结构**不得因为「规格未复尺」就被丢掉。这些图要占主副图或 A+ 的图位。图上只复述该垫图看得见的结构或该尺寸图上已写的数字，不准另编一套磅数/航空词。
5. **先剧本，后整套 Prompt。** 禁止只交单张提示词。必须先有 `visual_suite.yaml`，再一次性写出主副图 + A+（高级或普通）的整套出图包。
6. **平台规矩仍在。** 主图白底、主图无字、不能写 Best Seller / #1 / 价格 / 竞品品牌。这是亚马逊规则，不是学竞品。
7. **图片是买家的窗口。** 整套图必须让人一眼知道：这是什么、干什么用、有哪些功能、能解决什么实际问题。卖点要落到「解决问题」上，不是空形容词。功能、材质、结构、使用方式——垫图和已核实事实撑得住的必须体现；撑不住的继续空着，不准编。

## 产出顺序

1. **按图位拷贝垫图（强制）**

   `S3_视觉板块/amazon-listing-image-designer/产品垫图/主副图/IMG01_….jpg` … `IMG07_….jpg`  
   A+ 进 `产品垫图/高级A+/` 或 `产品垫图/标准A+/A01_….jpg`。  
   文件名必须和图位一致。出图文档每一节写同一文件名。机器清单只留 `asset_manifest.yaml`，不要再另写一份给人翻的垫图 MD。
2. **给人看的主副图只出一份 MD**  
   `08_主副图出图文档.md`：卖点/能写不能写、上传清单、每一张的买家问题、垫图文件名、尺寸、英文 Prompt、图上文案、埋词。

3. **GPT 网页端投喂包（第 4 步写完 Prompt 必须立刻打包，禁止只丢散落文件）**

   产出两个**扁平**文件夹，提示词和垫图在同一层，用户全选即可投喂：  
   `S3_视觉板块/GPT网页端投喂_主副图/`  
   `S3_视觉板块/GPT网页端投喂_A+/`  
   每个文件夹里只有：出图文档 MD + 已编号垫图 + `00_把本文件夹全部上传.md`。

4. **用户去网页端出图，再回填。**  
   Prompt 就绪 ≠ 已出图。用户把下载的压缩包或图片原样放进对应回填文件夹（不用改名、不用解压），说「主副图回填好了 / A+ 回填好了」。  
   助手只从回填文件夹取图：压缩包解压到同夹 `_解压/`，按 IMG01–07 / 模块名对上号；原图路径写 `source_return_path`（指向回填夹），按亚马逊规格导出到 `visuals/listing/`、`aplus_visuals/` 写 `output_path`，再分别登记 `listing_media_manifest`、`aplus_media_manifest`。不要把下载的图放进投喂夹。  
   悬浮窗第 4/5/7 步有「上传包 / 回填」文件夹入口，点一下直接打开。

## 最终要达到的交互（GPT 网页端投喂）

S3 不是在会话里一张一张生图。S3 只准备好**两套投喂包**，你拖进 ChatGPT Images 2.5 网页端一次出齐。

| 你要出什么 | 一次投进去的东西 |
|---|---|
| 主副图整套 | `GPT网页端投喂_主副图/` 里的出图文档 + 已编号垫图 |
| 高级/普通 A+ 整套 | `GPT网页端投喂_A+/` 里的出图文档 + 已编号垫图 |

编号规则必须能互相指回去：

- 垫图文件名：`IMG01_...jpg` … `IMG07_...jpg`，A+ 用 `A01_...` … `A05_...`。
- 出图文档每一节写死：`垫图 asset_id` + 文件名 +「上传清单第几张」。
- Prompt 里写 `Use uploaded reference IMG03` 这种编号，不准只写「用那张侧面图」。

网页端操作就三步：

1. 同一会话先上传该包里全部垫图（按文档里的上传清单顺序）。
2. 把出图文档整份贴进去（或先贴套图总指令，再贴全文）。模型按编号对照垫图，一次出完整主副图（或完整 A+）。
3. 某张不满意，用网页端**局部改图**改那一张，不要新开对话重出整套；改的时候产品样子仍锁对应编号垫图。

## 套图必须讲清的买家问题

每张图只主答一个问题，整套合起来要覆盖：

| 买家在问 | 通常落在 |
|---|---|
| 这是什么东西？ | 主图 |
| 出门/车上怎么用？解决什么麻烦？ | 场景图、多场景 |
| 有哪些功能、怎么用？ | 功能图、A+ |
| 材质/结构摸起来什么样？ | 信息/细节图、A+（仅垫图可见或事实已核） |
| 和将就着用的旧办法差在哪？ | 对比图（只对比本品已核实能力，不点名竞品品牌） |
| 买回去是什么生活感？ | 情感图 |

写 `visual_suite.yaml` 时，每一格必须有「买家问题 + 解决的痛点 + 可上图证据 + 垫图文件 + 后台 SEO 词」。没有证据的格标 `blocked`，把位置让给能讲清的功能或场景。

## 挑垫图逻辑（先分类，再占位，禁止只挑白底好看图）

先把 S1 媒体**全部看完**，按用途分类，再分配到 IMG01–IMG07 / A+ 模块。禁止只挑 3–4 张白底主体图反复复用。

| 垫图类型 | 必须占用的图位 | 跳过条件 |
|---|---|---|
| 本品白底完整外观（与所选颜色一致） | 主图 IMG01 | 水印/拼图/非本品颜色 |
| 网窗/可见宠物 | 副图或 A+ 一组 | 无网窗结构 |
| 提手/肩带携带 | 副图或 A+ 一组 | 无此结构 |
| 顶开/侧开/内部 | 副图或 A+ 一组 | 无开口图 |
| **尺寸图 / 适宠示意图** | 主副图或 A+ **必须占一格** | 目录里没有尺寸图才可空 |
| **行李箱套杆 / 拉杆固定** | 主副图或 A+ **必须占一格** | 目录里没有套杆图才可空 |
| 车载固定/后座 | 产品定位含车载时必须占一格 | 无车载图则用主体垫图生成车载场景，产品锁主体垫图 |
| 工厂文字页、店铺推荐别人家的货、未选颜色 | 不进垫图包 | 一律跳过 |

颜色锁死已选变体。蓝/粉/绿等未选色只可当「还有其他颜色」的内部参考，不准当本品真值。

生活场景可以换，但**卖点图位不能让给空生活方式**。有尺寸图却不出尺寸、有套杆图却不出套杆，算挑垫图失败。

## 后台图片关键词（给 Amazon 上传框，不进画面）

出图文档每一张必须另写 `后台图片关键词`。这栏**不是**给 ChatGPT 画进图里的，是卖家在 Amazon 后台上传主图/副图/A+ Desktop/A+ Mobile 时填的检索词。

规则：

1. 只从本 run 的 `keyword_package.yaml` / 关键词库报告里选，不准现编高流量无关词。
2. 每张 5–10 个英文短语；至少 2 个反映**本图画面**（网窗、套杆、尺寸、车载等）。
3. Desktop 与 Mobile 可共享核心词，但至少 2 个短语要反映该端构图差异。
4. 黑名单照旧：airline approved、Best Seller、竞品品牌、未核实承重/防水。
5. Prompt 正文里写清：`Do not render these keywords as text on the image.`

## 亚马逊图片硬约束（2026，沿用现有尺寸）

尺寸沿用本 Skill 已写死的规格，不另改：

| 图位 | 生成/交付尺寸 | 硬条件 |
|---|---|---|
| 主图 IMG01 | **1600×1600**（最长边 ≥1000 才能放大；推荐 ≥1600） | 纯白 RGB 255,255,255；产品占比 ≥85%；必须是本品真品样子（锁垫图）；无文字、Logo、水印、边框、道具、徽章、价格 |
| 副图 IMG02–IMG07 | **1600×2000** | 可场景、可含字；图+文一次生成；文件 JPEG/PNG、sRGB、单张 <10MB |
| 高级 A+ 每组 Desktop | **1464×600** | 5 组模块，每组必须另出 Mobile，合计 10 张 |
| 高级 A+ 每组 Mobile | **600×450** | **独立构图**，禁止把 Desktop 裁切/压缩当手机版 |
| 普通 A+ | **970 宽**（970×600 / 970×300 等按模块） | 无 Premium 资质才走；不要混用 1464 规格 |

全套还禁止：Best Seller / #1、折扣价格、退款保证、竞品品牌名、未核实认证（航空、承重、防水等）。主图尤其不能插画化、不能改产品外形。

## 一次性含字 + 关键词埋入

- **图和文案必须一次生成。** 副图 / A+ 的标题、短句直接画进图里。禁止先出无字底图再另走叠字渲染器当默认路径。主图例外：白底、无字。
- 字体、颜色、大小写全套共用 `visual_style_tokens.yaml`，写进总指令，避免七张七副面孔。
- 关键词要**合理埋入**能读懂的那一句，每张附图 1–3 个，不准堆词、不准把黑名单词（航空、承重、Best Seller 等）写上去。
- 画面要好看：场景融进真品，字少、能扫读，不像参数海报。

## ChatGPT 网页端（测试口径）

- 主副图一套投喂，A+ 一套投喂；两套可以同一会话连续做。
- 先出整套，再用局部改图返修。
- 主图：白底真品、无字。
- 附图 / A+：使用场景融合进真品，图上文案只写已核实卖点和自然关键词。
- **张数写死**：主副图必须 7 张（1+6），少一张就不算完成；提示词开头写 HARD COUNT，末尾必须有 IMG01–IMG07 核对表，并写明 “Do not stop at 6. If the gallery shows only 6, generate IMG07 now.” 高级 A+ 必须 10 张（5 组 × Desktop 1464×600 + Mobile 600×450），禁止裁切电脑图当手机图。网页端常在 5/6 张停住，所以 A+ 提示词必须写成 **两批发**：先 5 张 Desktop，同一会话立刻再出 5 张独立构图的 Mobile；写明 “Do not stop at 5. Do not stop at 6.”
