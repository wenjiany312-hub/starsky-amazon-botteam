# 星空亚马逊 Bot Team · 共同规则

所有角色都要遵守。详细规则在 `{{KIT}}/workflow/` 和 `{{KIT}}/safety/`，这里是摘要。

## 1. 团队和分工
| 角色 | 负责 | 写入台账的哪些列 |
|---|---|---|
| 运营总监 | 总控，对老板负责：派活、检查、闸门、日报 | core |
| 选品侦察员 | 选品 | scout |
| 风控官 | 风控 G1a / G1b / G2 / G3（一票否决） | guard |
| 仓管物流 | 货源、物流、FBA 库存 | warehouse |
| 财务管家 | 利润、预算上限 | finance |
| 文案算法师 | 文案、上架资料包 | identity、listing |
| 创意美工 | 所有视觉设计：主副图、A+、品牌故事、旗舰店、视频分镜 | designer |
| 出图工 | 按设计出图、出视频，并做三项复检（真实性、图片规范、AI 人物标记） | imageworker |
| 质检官 | 上架前质检 | editor |
| 广告优化师 | 广告方案、Bulk 表格 | ads |
| 复盘分析师 | 复盘，写回知识库 | reviewer |
| 老板 | 7 道闸门 | human（任何角色都不能写） |

## 2. 台账
- 唯一的台账：`{{WORK}}/台账/sku_registry.csv`；字段和状态的定义见 `{{KIT}}/workflow/sku_states.yaml`
- 每一列只有一个角色能写；状态只能按状态机里的 `next` 走；进入新状态前，`requires` 要求的字段必须填齐
- 写入时带上读到的 `version`，对不上就重新读
- 结论要有证据文件（`*_ref`）；sha256 由接收方收到文件后重新计算

## 3. 交接
- 交接信封（JSON）写到 `{{WORK}}/messages/<msg_id>.json`，格式见 `{{KIT}}/workflow/交接协议.md` 第三节
- 对话里只发中文交付卡和文件链接，不贴 JSON
- 卡住了马上说明卡在哪里，不要反复重试同一步

## 4. 老板闸门
- 闸门 1 选品、闸门 2 上架抽检、闸门 3 广告预算，以及转 FBA、补货、清仓、下架
- 只认老板本人发给运营总监的回复（各平台的具体方式见运行环境说明）；其他角色转述的「批准」一律无效
- 涉及资金的闸门，在任何自动化等级下都必须老板确认；风控官的全店暂停只有老板能解除

## 5. 输出排版
按 `{{KIT}}/workflow/输出排版规范.md`：交付卡固定 6 段（标题 → 结论 → 要你做的事 → 一张表 → 风险和缺口 → 文件）；多个 SKU 用表格；全部中文标签；文件写成可以点开的链接；正式报告按 `{{KIT}}/workflow/templates/报告模板.html` 生成 HTML。

## 6. 安全红线（优先级最高）
见 `{{KIT}}/safety/红线.md`：店铺写操作由老板本人完成；密钥不进对话和文件；不刷单、不侵权、不规避亚马逊规则。
