# 数据端接入方案 v0.2（店铺 API + ERP）

> 适用：星空亚马逊 Bot Team 1.0.0-rc8 起 · 2026-11-05（v0.2：老板已定 Grok 走 Execution on this computer，ERP 先接领星 + 优麦云）
> 一句话：**团队不另写一套接口**。店铺数据统一接「数据底座」（星空旗舰 AI 智能广告终端，跑在老板自己的电脑上），团队各角色只从它读数据、向它交方案；改店铺的事，全部由老板在审核报告里本人输入「确认推送」才执行。

## 一、现状

| 项 | 现在团队里 | 数据底座里 |
|---|---|---|
| SP-API（订单、库存、费用、Listing） | 没接，只有技能说明 | 已有：订单、FBA 库存 + AWD、Listing 回读、文案推送 |
| Ads API（广告报表、改竞价预算、新建活动） | 没接，开广告靠 Bulk 表格老板上传 | 已有：逐日报表、诊断、改竞价 / 预算 / 否词、**新建活动**（先建暂停 → 建广告组 / 商品广告 / 关键词 → 回读一致才开启），全部审核后推送 |
| 领星 | MCP 目录里有名字，没接 | 已有：多店只读（订单、FBA 库存、SP 活动日报、结算费用） |
| 优麦云 | MCP 目录里有名字，没接 | 已有（MCP）：多店多站读取；改关键词竞价、只降活动日预算已在真实店铺验证 |
| 赛狐 | 没有 | 预留：官方 MCP 读写都支持，按 10-29 的决定，等有真实店铺和密钥再做 |
| 日报推送（网页 + 飞书） | 运营总监手写 | 已有：每日简报、定时、飞书开关 |

结论：缺的不是接口，是**团队和数据底座之间的那根线**。

## 二、两种接入模式（可以混用）

| 模式 | 数据从哪来 | 适合 | 限制 |
|---|---|---|---|
| **A 店铺自接** | 自己的 SP-API + Ads API | 自己的店、API 已批（你的 A 店） | 数据天级；SB / SD 只看汇总 |
| **B 外部 ERP** | 领星 / 优麦云 / 赛狐 | 多店、广告 API 没批、已经在用 ERP | 看每家能力：领星只读、只有 SP；优麦云能改竞价和降预算；赛狐待接 |
| **混合** | 同一店铺两边都接 | 想用 ERP 的费用、头程数据补自接 | 合计只算一份，**推送一律走自接那边**（沿用数据底座现有规则） |

每个「店铺 × 站点」是一个**经营单元**，在 `{WORK}/config/data_sources.yaml` 里写清楚：数据从哪来、能不能推送、谁能读。

## 三、架构

```
老板 ──确认推送──▶ 数据底座（你的 Mac，本机）──▶ 亚马逊 SP-API / Ads API
   ▲                 ▲  凭据只存在这里            └─▶ 领星 / 优麦云 / 赛狐
   │ 闸门            │ 读数据、交方案
Bot 团队（11 个角色）─┘
```

**三条红线**（写进技能 amazon-data-hub，所有角色都要遵守）：
1. **凭据只在数据底座里**：Bot 不要、不读、不转述 SP-API / Ads API / ERP 密钥；老板发到对话里也要提醒他撤回，改用接入向导。
2. **Bot 只读数据、只出方案**：方案用 `plan import` 交给数据底座，生成审核报告；不调推送接口，不替老板勾选，不替老板输入确认。
3. **一切写入只走审核报告**：老板本人在报告底部输入「确认推送」才执行。7 道闸门照旧，资金类（加预算、开新活动）任何自动化等级都要人工。

## 四、三个平台怎么连

| 平台 | 怎么连数据底座 | 状态 |
|---|---|---|
| OpenBot | 本来就在你的 Mac 上：直接运行终端命令、读本机页面 | 可直接做 |
| StarSky | 同上（桌面端） | 装好后同 OpenBot |
| Grok Bot | 云电脑连不上你 Mac 的 127.0.0.1。**✅ 已定 方案 A**：Settings → Computer → 打开 **Execution on this computer**，让需要数据的 Bot 在你的 Mac 上执行终端命令。好处：密钥不出 Mac；调用 IP 就是你店铺的常用 IP（防关联、领星 IP 白名单都不用改）。**方案 B**：数据底座每天导出只读快照，再传到云电脑（数据晚半天，不能推送）。**不做**：把店铺密钥放进云电脑 | 已定，待实测：只有运营总监执行、每条命令老板批准、只用白名单命令 |

## 六、对 SKU 状态机的改动

- **AWAIT_UPLOAD**：增加 `api_submit` 分支（Listings API 接通后）——上架资料包 → 数据底座生成「新建 Listing 审核报告」→ 老板确认推送 → SUBMITTED。没接通前照旧走 `manual_sc`（老板后台创建）。
- **ADS**：广告优化师交 plan.json → 运营总监 `plan import` → 审核报告 → 老板确认推送。Bulk 表格保留作备用。
- **BUYABLE / REVIEWING**：可售、首单由数据底座回读判断，不再靠老板手报。
- **G3 账户健康**：读数据底座的健康 / 异常信号；出红灯 → 全队 HALT。
- **日报**：运营总监取数据底座的每日简报 + 团队台账，合成一份 HTML 日报。
