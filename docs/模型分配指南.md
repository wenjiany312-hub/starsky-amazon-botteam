# 模型分配指南（MagPie）

> 适用：**OpenBot**、**StarSky（DSH）**。Grok Bot 不适用（见第四节）。
> MagPie 是一个装在你电脑上的本地模型网关：把你已经买的 AI 套餐（ChatGPT、Claude 等）、各家 API Key、本地模型统一接进来，所有 Bot 平台都指向这一个地址，再给每个角色选不同的模型。

## 一、为什么要按角色分配模型
11 个角色干的活差别很大：运营总监和风控官要判断准，选品和仓管要大量调用工具，文案要英文好，美工和质检要能看图，出图工要能出图。全队用同一个模型，要么贵，要么有的岗位能力不够。

## 二、能力档（`config/team_settings.yaml` 里的 profile）

| 能力档 | 要什么能力 | 哪些角色 | 选模型时看什么 |
|---|---|---|---|
| 强推理 | 多步判断、长上下文、不乱下结论 | 运营总监、风控官、复盘分析师 | 选你手上推理最强的模型，推理档位开到中或高 |
| 工具主力 | 工具调用稳、速度快、单价低 | 选品侦察员、仓管物流、财务管家、广告优化师 | 性价比模型；数据调用多，单价影响大 |
| 英文写作 | 英文地道、守字数和格式 | 文案算法师 | 英文写作好的模型 |
| 多模态创意 | 能读图，会写出图 Prompt | 创意美工 | 支持图片输入 |
| 多模态严谨 | 能读图，检查细致 | 质检官 | 支持图片输入 |
| 出图 | 生成图片 | 出图工 | MagPie 里类型是「图片」的模型；另配一个能读图的模型做复检 |

**原则**
1. 先保证运营总监和风控官的模型够强，其他岗位可以从便宜的开始
2. 没有出图模型就不要硬配：把 `visual.image_mode` 改成 `outsource`，出图走投喂包
3. 换模型后先跑一轮试跑，用同一批品对比结果再定

## 三、怎么配
1. 安装 MagPie，在 **Providers → Add provider** 里加上你的套餐或 Key（登录 ChatGPT / Claude 的订阅也可以直接当作一个来源）
2. 在 MagPie 里看你有哪些模型（模型 ID 写法是 `provider/model`）；出图模型在图片类型里
3. 把每个角色要用的模型 ID 填进 `config/team_settings.yaml` 的 `models.roles`
4. 在平台里给每个角色选上对应的模型：
   - **OpenBot**：每个助手对话顶部的模型选择器（你现在看到的 `magpie/DeepSeek V4.1 F…` 就是通过 MagPie 接入的）
   - **StarSky（DSH）**：MagPie 支持 DeepSeek Harness；每个成员能不能单独选模型，以 StarSky 设置里显示的为准（待实测）
5. 安装时，搭团队的 Bot 会读这份设置，告诉你每个角色该选哪个模型；平台不允许 Bot 自己改模型的，由你手动选

## 四、Grok Bot 不适用
- Grok Bot 由平台自己管模型，**没有模型选择器**
- Grok Bot 跑在云电脑上，连不到你电脑上的 MagPie（它只在本机 127.0.0.1 上）
- 所以 Grok 版不按角色分配模型；出图默认走外包投喂包，Grok 自带的出图能力能不能用，待实测

## 五、出图和视频
- **出图**：MagPie 支持图片模型（走 `/v1/images/generations` 接口）。出图工能不能在平台里直接调用，取决于平台有没有出图工具，或者出图工能不能执行一段调用脚本——**OpenBot 上待实测**。实测通过之前，建议先用 `outsource`
- **视频**：MagPie 也有视频接口（`/v1/videos`，文档里点名支持火山方舟）。如果以后你有能用的视频模型 Key，可以试着接进来，再把 `video_mode` 改成 `in_team`。实测通过之前，视频一律走投喂包 + 即梦生成

## 六、费用
MagPie 本身免费。费用来自你接入的套餐或 Key：订阅有用量上限，API 按调用计费。MagPie 里能看每个角色（每个 Bot）用了多少，建议第一周每天看一次。
