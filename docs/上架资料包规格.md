# 上架资料包规格（团队 → 数据底座，R12）

> 团队出包、数据底座校验和生成审核报告、老板本人「确认推送」后才提交。字段以数据底座 `references/listing_pack.md` 为准，这里是团队怎么分工把它填齐。
> 一个 SKU 一个文件夹，**四个子包分开**（新建 Listing 包里出现 A+ / 变体字段会被直接拒绝）。

```
<SKU 短号>/
├── listing/        listing.json（+ images/ 只留档）       → listing create
├── aplus/          aplus.json + images/                 → listing aplus      （要先有 ASIN）
├── brand_story/    brand_story.json + images/           → listing brandstory （要先有 ASIN）
└── update/         listing.json（亮点、长描述、搜索词、材质…）→ listing update   （建好之后补属性）
```

## 一、listing/listing.json（新建 Listing）

| 字段 | 谁填 | 说明 |
|---|---|---|
| `region` `sku` | 运营总监 | `us`；Seller SKU 必须是店里**还没有**的（已有 SKU 会被拒绝，避免整条覆盖） |
| `product_type` | 文案算法师 | 亚马逊产品类型，如 `PLANTER`；`--check` 会按官方 schema 校验 |
| `brand` `title` `bullets`（1–5）`description` `search_terms` | 文案算法师 | 文案；搜索词按字节限制 |
| `gtin` | 运营总监（问老板） | UPC/EAN；**不填 = 按品牌 GTIN 豁免提交**（品牌已授权才行） |
| `price` `currency` | 财务管家 | 售价；老板闸门 2 认可的价格 |
| `fulfillment` `quantity` `merchant_shipping_group` | 仓管物流 | `FBM`（要 quantity）或 `FBA`（只建 Listing，不建货件） |
| `images.main` `images.others[]` | 出图工 | **公开 https 地址**（主图 1 + 副图 ≤8），不收 http / 内网 / 带账号密码的地址；见第五节 |
| `attributes` | 文案算法师 | 其余必填属性（`manufacturer`、`country_of_origin`、尺寸、颜色…）；缺哪些看 `--check` 的报错补 |
| `restrictions_asin` | 选品侦察员 | 可选：同类目的一个参照 ASIN，用来做限制检查（不填就以亚马逊预校验为准） |
| `g2_verdict` `qa_verdict` | 风控官 / 质检官 | 原样显示在审核报告里 |

**不能出现**：`variations`、`parent_sku`、`parentage_level`、`variation_theme`、`child_parent_sku_relationship`、`aplus`、`fba_inbound`。变体本期不支持。

## 二、aplus/aplus.json（高级 A+）
- 要有 `asin`（新建成功、回读到 ASIN 之后才能做）；该 ASIN **已有 A+ 会被拒绝**
- 只开放两种模块，一份最多 7 个、不能混标准模块：

| 模块 | 图片 | 要求 |
|---|---|---|
| `PREMIUM_FULL_BACKGROUND_IMAGE` 高级完整图片 | 电脑端 + 手机端各一张 | 电脑端 ≥1464×600，手机端 ≥600×450；jpg / png，≤5MB；alt 文本 ≤100 字符 |
| `PREMIUM_FAQ` 高级问答 | 无 | 2–5 组问答 |

- 图片是本地文件，放 `aplus/images/`，数据底座自己传到亚马逊，不用图床

## 三、brand_story/brand_story.json（品牌故事）
| 模块 | 图片位和最小尺寸 |
|---|---|
| `BRAND_STORY_IMAGE_WITH_LOGO` 品牌轮播背景 | 电脑端 ≥1464×625，手机端 ≥463×625 |
| `BRAND_STORY_ABOUT` Logo 与品牌介绍 | Logo ≥362×453（后台网页的 315×145 接口不收） |
| `BRAND_STORY_MEDIA_ASSET` 品牌焦点图 | ≥362×453 |
| `BRAND_STORY_FOUR_ASIN` 四宫格商品 | 4 格，每格 ≥166×182，带对应 ASIN |
| `BRAND_STORY_QUESTIONS` 品牌问答 | 正好 3 组，每条答案 ≤200 字符 |

该 ASIN 已有品牌故事会被拒绝（已有高级 A+ 不影响）。

## 四、update/listing.json（建好后补属性）
只开放：亮点 `highlight`、长描述 `description`、ST 搜索词 `search_terms`、`material`、`planter_form` 等少数字段；每个字段整条替换，写前会复读线上值，变了就不写。

## 五、图片地址（新建 Listing 的主副图）
- 亚马逊只收它能公开访问的 https 地址，提交时由亚马逊自己去下载
- 第一次实测用的是免费图床。**正式长期用建议换成老板自己的 S3 / CloudFront**：免费图床可能删图、限流，而且新品上架前图片对外公开有被抄的风险
- 图片地址由出图工在出图清单里写好，文件名用 `<SKU>_<图位>_<版本>.jpg`

## 六、包怎么到老板电脑上（Mac / Windows）
1. 运营总监在云电脑上把 `<SKU 短号>/` 打成 `<SKU 短号>_上架资料包.zip`，**作为附件发给老板**
2. 老板点开附件存到电脑的「下载」文件夹
3. 运营总监在老板电脑上（Execution on this computer，老板逐条批准）解压到固定位置：
   - Mac：`unzip -o ~/Downloads/<SKU 短号>_上架资料包.zip -d ~/星空上架资料包/`
   - Windows（PowerShell）：`Expand-Archive -Force -LiteralPath "$env:USERPROFILE\Downloads\<SKU 短号>_上架资料包.zip" -DestinationPath "$env:USERPROFILE\星空上架资料包"`
4. 跑 `listing create --pack <资料包目录>/<SKU 短号>/listing --check`（Windows 路径写法见技能 amazon-data-hub），0 错误后再生成审核报告

## 七、顺序
`listing create --check`（补到 0 错误）→ `listing create`（审核报告）→ 老板确认推送 → `listing status` 回读到 ASIN → 把 ASIN 填进 aplus / brand_story → `listing aplus`、`listing brandstory`（各自一份审核报告）→ 需要时 `listing update` 补属性。
