# 输出排版规范 v1.0（所有角色通用）

> 角色交出来的东西，老板看不懂、看不完，就等于没交。**排版和内容一样，都是交付质量的一部分。**
> 适用于：角色交给运营总监的结果、运营总监发给老板的所有消息（任务单、审批卡、批次报告、日报、上报）。

---

## 一、两层输出：给人看的放对话，给系统的放文件

| 给谁 | 放哪里 | 内容 |
|---|---|---|
| **人**（老板，以及运营总监读摘要） | 对话 | 中文交付卡（第二节） |
| **系统**（台账、下游角色） | 文件 | JSON 信封、完整字段、长清单、原始数据、供应商问题清单 |

- **对话里不贴 JSON**，也不贴"JSON 摘要"。只放一个能点开的文件链接（第八节）
- 超过 10 条的清单（比如 55 个供应商问题）一律放文件，对话里只说"共 55 条，见 `xxx.md`"

## 二、交付卡：固定 6 段，按顺序写

```
### {图标} {角色} · {做了什么} · 批次 {批次号}
**结论**：一句话。做了多少、通过多少、淘汰多少、卡在哪。

**要你做的事**（没有就写「无」）
1. 具体动作 + 放到哪里 / 回复什么

**{关键表格标题}**
| ... 一行一个 SKU ... |

**风险和缺口**
- ⚠️ / ⏳ 每条一行，写清楚影响谁

**文件**
- [字段明细](绝对路径/xxx.json)
- [详细报告](绝对路径/xxx.md)
```

- 第一行标题让人一眼看出：**谁、干了什么、哪个批次**
- **「要你做的事」放在第二段**，老板不用翻到底才知道要干什么
- 没有内容的段落直接删掉，不写"无风险"这种空话（「要你做的事」除外）

## 三、表格规则

1. **多个 SKU 一定用表格**，一行一个 SKU。**不要用「｜」把十几个字段拼成一长行**
2. 表格**最多 8 列**。放不下的字段（HTS 编码、offer ID、供应商名）放文件
3. SKU 列只写**短号**（001、002），完整编号放文件；产品名不超过 8 个字
4. **单位写在表头里**，单元格只写数字：`采购价(¥)` `重量(kg)` `交期(天)`
5. 同一列的数字**位数一致**：金额两位小数，百分比一位小数
6. 有风险的行在最后一列用图标标出来，并写 2–6 个字说明原因

## 四、语言和格式

| 项 | 规定 | ✅ 正确 | ❌ 错误 |
|---|---|---|---|
| 标签 | 一律中文 | 结论 / 要你做的事 / 证据 | Status / Result / Evidence / Unblock |
| 内部代码 | 首次出现时配中文 | IP-DES（外观专利） | 只写 IP-DES |
| 金额 | 币种符号 + 两位小数 | ¥19.80、$24.99 | 19.8、¥19.80@≥1 |
| 百分比 | 一位小数 | 35.6% | 0.356、35.62% |
| 尺寸 | 长×宽×高 + 单位 | 25.5×13.5×10.5 cm | [25.5,13.5,10.5] |
| 重量 | 两位小数 + kg | 0.36 kg | 0.36kg、360g |
| 时间 | 天 / 小时 | 交期 7 天 | 交期7、7d |
| 状态 | 用状态机里的中文名 | 待老板选品确认 | AWAIT_GATE1 |
| 角色 | 用角色名 | 风控官、财务管家 | 风控 agent |

## 五、状态图标（只用这 5 个）

| 图标 | 含义 |
|---|---|
| ✅ | 通过 / 完成 |
| ⚠️ | 要注意，但不挡流程 |
| ❌ | 淘汰 / 失败 |
| ⏳ | 等待中 / 缺数据 |
| 🔒 | 要老板决定 |

不要用其他 emoji，也不要一行用好几个。

## 六、长度

- 一条消息**不超过一屏（约 25 行）**，表格行数不算在内
- 一条消息只讲**一件事**（一个批次的一个环节）
- 过程描述（"我先调用了……再检索了……"）不写进交付卡，需要时放文件

## 七、运营总监的额外规则

1. **运营总监是唯一面向老板的出口**。其他角色的原始输出不能原样转给老板，必须按本规范重排
2. 同一批次多个角色的结果，到闸门时**合并成一张批次卡**，不要一个角色一条消息刷屏
3. 审批卡的最后一行必须是**回复示例**，老板照着回就行

---

## 八、文件一定要能点开

对话里提到的每个文件，都写成**可以点击的链接**：

| ✅ 正确 | ❌ 错误 |
|---|---|
| `[闸门1审批卡](/Users/james/OpenBot/Shared/amazon-ai-ops-team-kit/试跑/B-2026-1102-T1_闸门1审批卡.html)` | `` `B-2026-1102-T1_闸门1审批卡.md` ``（反引号包起来，变成代码，点不了） |
| 链接文字写中文说明，路径写**绝对路径** | 只写文件名，或者另起一行写「文件实体在：……」 |

- **文件名和路径都不要用反引号包起来**，反引号会让它变成代码，不能点击
- 路径里有空格时，用尖括号包住：`[名称](</Volumes/Tool Disk/…/xxx.md>)`
- 以选品侦察员第一次交付时的写法为准：对话里显示成带 MD / TXT 图标的蓝色文件名，点了就能打开
- 「文件」一段里，每个文件一行，一行一个链接

## 九、正式报告出 HTML

下面这几类**正式报告**，除了对话里的交付卡，还要生成一份 **HTML 文件**，并在交付卡第一行放上它的链接：

| 报告 | 谁出 | 文件名 |
|---|---|---|
| 闸门审批卡（闸门 1/2/3、转 FBA、补货、清仓、下架） | 运营总监 | `{批次号}_闸门N审批卡.html` |
| 批次报告 | 运营总监 | `{批次号}_批次报告.html` |
| 台账日报 | 运营总监 | `{日期}_台账日报.html` |
| 复盘周报 | 复盘分析师 → 运营总监 | `{周次}_复盘周报.html` |

规则：
1. 用模板 `workflow/templates/报告模板.html`，替换里面的 `{{…}}` 占位符，保留它的样式
2. **单个文件**，不引用任何外部 CSS、JS、字体、图片 URL，双击就能在浏览器打开
3. HTML 里的链接用**相对路径**（相对这个 HTML 所在的文件夹），点表格里的「报告」就能打开那个 SKU 的详细文件
4. 结构和交付卡一致：标题 → 结论 → 数字卡片 → **要你做的事**（含回复示例）→ 关键表格 → 风险和缺口 → 文件
5. 对话里的交付卡照样要发（老板在手机上看对话，在电脑上看 HTML），两边的数字必须一致
6. 普通的角色交付（比如仓管物流交给运营总监的结果）不用出 HTML，交付卡 + 文件就够
